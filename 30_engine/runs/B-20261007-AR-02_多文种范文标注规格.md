# B-20261007-AR-02 · 多文种范文标注规格（汇报材料／实施方案／发展规划／调研报告）

- 目的：把范文库从讲话稿一个文种扩到 11 章 M4 的常用文种。P4 第 5—7 轮 F1 的漏检都是“稿子相对同类成品缺了什么、多了什么”，范文对照（gw-draft W2-0、gw-review pass3）是现有唯一能查这一层的手段，其他文种目前没有。
- 范围：`30_engine/batches/B-20261004-deid-个人历史交付物-r10/`（已脱敏、硬泄露 0）。每个文种由一个标注者负责，文件分配见派工单。
- 落点：标注者写 `30_engine/batches/B-20261007-AR-02/<文种>.jsonl`，不直接写 `20_knowledge/articles/articles.jsonl`；合并由统一一步完成。
- 字段与校验：沿用 `B-20261004-AR-01_讲话范文标注规格.md` 全部字段与纪律，差异只有下表。校验 `python3 -c "import sys;sys.path.insert(0,'30_engine/tools');import json,kb_validate;[print(i,e) for i,l in enumerate(open(F,encoding='utf-8'),1) for e in [kb_validate.validate_article(json.loads(l))] if e]"`（F 为批次文件），每条 0 错误才交。

## 与讲话类规格的差异

| 字段 | 写法 |
|---|---|
| id | 临时号段：汇报材料 AR-0101 起、实施方案 AR-0201 起、发展规划 AR-0301 起、调研报告 AR-0401 起；合并时不重编 |
| doc_type | `汇报材料`／`方案`／`规划`／`调研报告`（诊断报告、对标分析报告、结题报告归调研报告） |
| subtype | 推荐值，取主要功能：汇报材料＝工作汇报／专题汇报／经验交流／上报汇报；方案＝实施方案／工作方案／项目方案／技术方案；规划＝五年规划／专项规划／中长期规划；调研报告＝诊断报告／对标分析报告／调研报告／课题结题报告 |
| org_level | 发文或成稿主体层级；咨询方代拟的，按委托方层级 |
| summary | 80—150 字：谁、向谁、为什么写、主线是什么 |
| skeleton | 一级标题原文照录 |
| why_good | 3—6 条“做法——为什么好（位置）”，可迁移、不写空话 |
| must_haves | 4—10 条“同类文种起草时必须对照的要件——本文怎么做（位置）”。对照 `.claude/skills/gw-draft/references/wenzhong/` 对应文种指南的要件与体例，指南没写而范文普遍有的，单独在回报里列出（这是指南的缺口） |
| batch_id | `B-20261007-AR-02` |

## 选篇

- 同一文件多个版本（如“管理诊断报告 0712／0714／讨论后”）只取最终版或最完整的一版，其余在回报里写“同源未收”。
- 行业文件（国家局实施意见、政策措施）属上级文件，不是本库要学的“我方成稿”，不收；规划类的国家局“十四五”规划可作 B 级参照。
- 每个文种目标 4—8 条，宁缺毋滥；C 级不输出，只在回报里列。

## 纪律

- 只读分配的文件、文种指南和 QA 库；不读 `50_tasks/`、`~/wb`。
- 不还原脱敏占位，不写真实单位名、人名；读原文时发现脱敏漏网（真名、真单位、真品牌），记入回报“漏网”清单（文件、行号、原文片段改写成描述），不要在记录里复述。
