# 汇报骨架与提纲库

> 配合 `../SKILL.md` 模块2 使用。本库给两套骨架的逐段细则、开场模板、字数预算、以及从行业提纲样本提炼的搭法要点。
> 已脱敏：单位名以「某省/某市烟草、某中烟」代，数据以「X%／X 项／X 天」代。

---

## 一、工作汇报 vs 专题汇报骨架对照

| 维度 | 工作汇报 | 专题汇报 |
|---|---|---|
| 用途 | 综合通报一段时期工作进展、完成情况、下步安排 | 就一件专项任务/重要问题作针对性汇报，要领导决策 |
| 主题 | 多板块并列、综合 | 全篇聚焦**一个**主题 |
| 字数 | 1000-3000 字 | 1500-4000 字 |
| 问题段 | 直接列举，**不展开原因** | 列问题 + **必须有原因分析** |
| 末段 | 下步计划（对内自己干） | 下步建议 / **请示事项**（可向上请决策） |
| 分析深度 | 通报为主 | 分析更深、方案更具体 |

**选型一句话**：综合通报选工作汇报；只讲一件事、要领导拍板选专题汇报。

## 二、工作汇报骨架（逐段细则）

```
【一、背景与目的】（≤100 字）
  - 落实什么部署 / 针对什么任务（1 句）
  - 汇报目的（1 句）
  - 铁律：直接切入，不铺垫废话，不讲「为什么要做」

【二、工作开展情况】（主体，2-4 板块，每板块 200-500 字）
  - 每板块小标题领起（结论句：做法+成效）
  - 每板块内部：做了什么 → 怎么做的 → 达到什么效果
  - 每条须有数据支撑，数据带对比基准
  - 板块间按「重要性」排序，核心成效先说
  - 约束：不堆已完成清单，要有「做了什么→为什么这样做→效果」脉络

【三、存在的问题和不足】（2-4 条，简洁）
  - 具体到事项，不写「整体推进顺利」
  - 列举式，不展开原因分析

【四、下一步工作计划】（2-4 条）
  - 针对问题提举措，与问题对应
  - 时间节点到月份，责任主体明确
  - 不写「继续努力」「加快推进」
```
**红线**：不夹带请示/资金申请（请示单独行文）；时间不用「近期/尽快/适时」；成效不用「大幅/显著」无数字词。

## 三、专题汇报骨架（逐段细则）

```
【一、专题背景与汇报目的】（100-200 字）
  - 缘由：上级要求 / 工作需要 / 重要节点
  - 明确核心问题：交代清楚「为什么做这个专题汇报」

【二、基本情况（现状描述）】（200-400 字）
  - 客观现状 + 关键数据
  - 区分：已完成 / 进行中 / 未启动
  - 铁律：用事实说话，不加自我肯定评价（做法段后面专讲）

【三、主要做法与进展（核心段落）】（2-4 条，每条 200-400 字）
  - 每条：具体措施 + 阶段成效
  - 体现工作的逻辑性、系统性

【四、存在的主要问题及原因分析】（200-400 字）
  - 列问题 + 析原因（专题汇报必有原因分析）
  - 原因须实质：制度 / 资源 / 能力 / 客观条件四类
  - 问题按轻重缓急排序

【五、下步工作建议（或请示事项）】（200-400 字）
  - 与问题一一对应
  - 需上级支持的，明确写「请求上级……」+理由
  - 时间节点到月份
```
**红线**：不写成综合工作汇报（聚焦一个主题）；原因不写「重视不够/落实不到位」空话；请示不藏在建议里让领导猜；数据有统计口径说明。

## 四、框架方法版（与骨架互补的另一种切法）

来自框架方法资料，更适合「现场会交流/专题深度汇报」长稿：

```
【背景与定位】（300-500 字）：政策背景 + 问题背景（现有做法局限）+ 建设定位（解决什么问题）
【核心内容】（1500-3000 字，2-4 部分）：各部分独立标题，内部「一是/二是/三是」，每条有数据或举措
【推进情况与成果】（800-1500 字）：推进机制（怎么组织）+ 阶段成果（做了多少）+ 数据完整带对比
【存在问题】（300-500 字）：直接列举，不过度析原因
【下步工作】（500-800 字）：时间节点 + 量化目标 + 标志性成果
```
> 与「五段式」是同一逻辑的不同颗粒度：长稿/现场会用本版，常规向上汇报用五段式。

## 五、开场模板库（≤200 字）

**陈述式（默认）**
```
[称谓]：
按照[上级/公司]关于[工作]的部署，现将[单位][时段]推进[工作]的情况汇报如下。[如需：汇报分 X 个部分。]
```

**SCQA 升级式（重要节点/攻坚情境）**
```
[称谓]：
[S 稳定情境：单位已连续 X 年/从 X 年起坚持……]。[C 冲突：然而今年是收官年/面临……关键一跃……]。[Q 隐含疑问：不显式写，让领导心里产生「那怎么办」]。[A 直接给结论 + 核心数据：这一年，我们用……给出了答案]。下面作汇报。
```

**现场会交流式（接待/经验交流）**
```
近年来，[某单位]在[上级]领导下，紧紧围绕[现场会主题/行业部署]，[一句总体做法定性]。现将我们的主要做法和体会作交流汇报。
```

**开场三禁（反向自检）**：① 不讲「为什么要做这件事」；② 不用「坐标系/历史里程碑」比喻；③ 不超 200 字。

## 六、各板块字数预算速查

| 段落 | 工作汇报 | 专题汇报 | 现场会长稿 |
|---|---|---|---|
| 开场/背景 | ≤100 字 | 100-200 字 | 300-500 字 |
| 主体（做法/成果） | 每板块 200-500 字 | 每条 200-400 字 | 1500-3000 字（核心）+ 800-1500（成果） |
| 问题段 | 2-4 条简列 | 200-400 字含原因 | 300-500 字 |
| 下步/请示 | 2-4 条 | 200-400 字 | 500-800 字 |
| 全文 | 1000-3000 字 | 1500-4000 字 | 视场合，常 3000-5000 字 |

## 七、行业汇报提纲样本要点（从真实提纲提炼）

汇报提纲在「板块怎么并列、按什么排序」上有稳定套路，提炼如下（来源：行业汇报提纲样本，已抽象）：

**套路1：动词领起 + 业务并列（最常见）**
> 一级标题统一用「动词+领域+成效」，下设按业务条线并列的二级。
> 抽象样式：「发力 A，提升 X」「发力 B，提升 Y」「发力 C，提升 Z」——七个业务板块用同一句式套裁（创新/原料/制造/营销/物流/基础管理/人才）。
> 要点：同层句式三同对齐（炼标题交 `../../专项_02_标题炼制`），按重要性排序。

**套路2：思路—实践—成效（三段递进）**
> 一、推动 X 的**思路**；二、推动 X 的**实践**（下设若干「以 A 撬动 B 升级」）；三、推动 X 的**成效与下步打算**。
> 要点：思路在前定调，实践是主体，成效压轴；适合专题/经验交流。

**套路3：数字模型贯穿（记忆点强）**
> 用一个「X+Y+Z」数字模型统领全篇（如「四个引领、三个环节、五个协同」），各板块对应模型一个要素展开。
> 要点：数字须真有对应内容；模型词进标题、进帽段，强化领导记忆。

**套路4：现状—做法—成效—体会（经验交流标配）**
> 一、背景和思考；二、主要做法（占全文 60%）；三、几点成效；四、几点体会。
> 要点：做法是重心，成效带对比基准，体会升华为规律性判断。

**通用排序规律**（来自框架方法资料）：
- 工作进展/历史回顾 → **时间顺序**（过去→现在→未来）
- 成效汇报/板块并列 → **重要性顺序**（最重要先说）
- 问题/原因/下步 → **意义顺序**（问题→措施）
- 同一层级不混用两种排序

## 八、提纲自检清单

- [ ] 板块之间 MECE（不重叠不遗漏）——交 `../../专项_01_篇章结构` 判定
- [ ] 每条板块标题是结论句、同层对仗——交 `../../专项_02_标题炼制`
- [ ] 板块排序与内容性质匹配（成效按重要性、进展按时间）
- [ ] 做法板块占比够（经验交流类不少于 60%）
- [ ] 成果板块每条数据带对比基准
- [ ] 问题段位置正确、写法符合文种（工作汇报不析原因）
- [ ] 下步每条对应一个问题、含时间节点+量化目标
