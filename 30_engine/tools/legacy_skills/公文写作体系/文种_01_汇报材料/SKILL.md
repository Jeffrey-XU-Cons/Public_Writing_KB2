# 汇报材料——把工作讲给领导，让领导掌握情况并认可判断

> 本 skill 只管「汇报这个文种怎么搭怎么写」：文种定位、五段骨架、开场、成果段、问题段、领导意图落地。
> 结构是否 MECE、标题是否结论句、段落意群、字句锤炼等通用技法，分别指向 `../专项_01_篇章结构`、`../专项_02_标题炼制`、`../专项_03_段落意群`、`../专项_05_炼句金句`，本 skill 不重复。

## 使用场景

当用户需要：
- 把一堆工作素材搭成一份汇报（工作汇报 or 专题汇报），定骨架、写开场、铺各板块
- 区分「工作汇报」与「专题汇报」，选对骨架（综合通报 vs 单一主题深挖）
- 诊断一份已有汇报稿：开场是否得体、成果有没有对比基准、问题段是否克制、有没有体现领导意图

不要用于：
- 写工作总结（用 `../文种_02_工作总结/SKILL.md`；二者区别详见文末「汇报 vs 总结」）
- 写讲话稿（讲话给人听、靠耳朵接收，用 `../文种_06_现场会讲话/SKILL.md`）、写实施方案、写规划
- 设计 MECE 骨架本身、炼标题、锤句子（指向对应专项 skill）

## 输入要求

需要用户提供（缺则最多追问 3 条）：
1. 「这是工作汇报还是专题汇报？」——综合通报一段时期工作选工作汇报；只讲一件专项任务、要领导决策选专题汇报
2. 「向谁汇报、什么场合？」——上级主管部门／现场会交流／调研接待，决定语体与详略
3. 「核心判断一句话是什么？」——你最想让领导记住、认可的那一句（没有就先退回 `../专项_01_篇章结构` 定主旨）

## 工作流

### 流程A：起草新汇报
**输入**：工作素材 + 文种（工作/专题汇报）+ 汇报对象 + 核心判断
**步骤**：
1. **定文种、调骨架**：工作汇报用「背景与目的→工作开展情况→存在问题→下步计划」；专题汇报用「专题背景→基本情况→主要做法与进展→问题及原因分析→下步建议」。骨架细则见 `references/汇报骨架与提纲库.md`。
2. **列板块、做 MECE**：把素材归入 2-4 个并列板块，板块之间不重叠不遗漏——**MECE 判定交给 `../专项_01_篇章结构`**，本步只确认「按重要性排序」（核心成效先说）。
3. **拟板块标题**：每条板块标题须是结论句、同层对仗——**炼标题交给 `../专项_02_标题炼制`**，本 skill 只要求标题落点是「做法+成效」。
4. **写开场**：陈述式（默认）或 SCQA 升级式（有重要节点/攻坚背景时），≤200 字，见模块3。
5. **铺成果段**：每板块「总—分」结构，先一句板块判断，再分条铺事实，**每条数据必带对比基准**，见模块4。
6. **写问题段**：直接列举 2-4 条，工作汇报不展开原因，专题汇报才补原因分析，见模块5。
7. **写下步**：每条对应一个已列问题，含时间节点（到月份）+量化目标，不写「继续努力」。
8. 用本文 Rubric 自检，未过回到对应步骤。
**输出**：一份结构完整、开场得体、成果有基准、问题克制、体现领导意图的汇报稿
**失败处理**：
- 若核心判断写不出来 → 退回 `../专项_01_篇章结构` 重定主旨，汇报没有靶心就是流水账
- 若某条数据没有对比基准 → 标「[待补：需同比/历史最好/目标值]」，不得用「大幅提升」占位

### 流程B：诊断改写已有汇报稿
**输入**：现有汇报全文 + 用户指出的问题（或全面体检）
**步骤**：
1. **体检开场**：是否在讲「为什么要做这件事」、有没有「坐标系/里程碑」式比喻、有没有超 200 字——命中即标红（模块3 反向用）。
2. **体检成果段**：逐条数据问「有没有对比基准？」——只有绝对值无基准的标红；查同一数据是否多处重复出现。
3. **体检问题段**：工作汇报里问题段是否大段分析原因（应克制）、是否用「总体良好」回避真问题——命中标红。
4. **体检领导意图**：领导/上级反复强调的词句，有没有进到标题、帽段、导语——没有则提示补入（模块6）。
5. **体检文种纯度**：专题汇报有没有写成综合工作汇报（跑题）；工作汇报有没有夹带请示事项（汇报只通报，请示单独行文）。
6. 输出「问题清单 + 改写对照」，只改点名处，其余只提示（遵循修改模式）。
**输出**：汇报诊断表（位置｜问题类型｜改写建议）
**失败处理**：连续 3 处改写仍不达标 → 可能是素材本身缺数据/缺判断，提示补素材而非硬改

## 方法论模块

### 模块1：文种定位——汇报是写给领导看的（地基）
- **核心命题**：汇报的读者是领导，目的是**让领导掌握情况 + 认可你的判断**。一切写法服务于这两点。
- **三个推论**：
  1. **结论先行**：领导时间有限，开篇就给定性与核心数据，不让领导读到末尾才知道结论。
  2. **替领导省力**：成果用「总—分」，先给判断再给支撑；数据带基准，领导一眼看出好坏，不必自己换算。
  3. **想领导所想**：领导关心的（上级部署是否落地、风险是否可控、下一步靠不靠谱），就是重点板块；与领导无关的工作细节大幅压缩。
- **常见错误**：把汇报写成「我做了 ABCDE」的工作流水账（自我视角），而非「这件事进展如何、判断是什么、请领导放心/拍板」（领导视角）。

### 模块2：标准骨架（五段式，含字数区间）
> 两套骨架，按文种选。详细对照与提纲样本见 `references/汇报骨架与提纲库.md`。

**工作汇报骨架**（全文 1000-3000 字）：
1. **背景与目的**（≤100 字）：落实什么部署/针对什么任务 + 汇报目的，直接切入
2. **工作开展情况**（主体，每板块 200-500 字，2-4 板块）：做了什么→怎么做→什么效果，有数据
3. **存在问题**（2-4 条，简洁）：具体到事项，不展开原因
4. **下步计划**（2-4 条）：对应问题，含时间节点+量化目标

**专题汇报骨架**（全文 1500-4000 字）：
1. **专题背景与汇报目的**（100-200 字）：为什么做这个专题汇报
2. **基本情况**（200-400 字）：客观现状+关键数据，区分已完成/进行中/未启动，不加评价
3. **主要做法与进展**（核心，每条 200-400 字，2-4 条）：措施+阶段成效，体现系统性
4. **问题及原因分析**（200-400 字）：列问题+析原因（专题汇报必须有原因分析），按轻重排序
5. **下步建议/请示事项**（200-400 字）：与问题一一对应；需上级支持的写明请求

- **常见错误**：专题汇报写成综合工作汇报（什么都讲、不聚焦一个主题）；工作汇报在问题段大谈原因（越位到专题汇报的写法）。

### 模块3：开场写法（≤200 字）
- **陈述式（默认）**：`[称谓]：[1-2 句汇报背景]，[我代表 XXX 就 XX 工作作汇报]。[如需，列出几个部分]。`
  - 例：「各位领导：按照公司关于管理提升工作的部署，现将某市烟草今年以来推进管理体系建设的情况汇报如下。」
- **SCQA 升级式（有重要节点/攻坚情境时用）**：稳定情境 S→冲突挑战 C→隐含疑问 Q→直接给结论 A，100-150 字。
  - 例：「各位领导：从三年前启动体系建设到今天，某市烟草走过了探索历程。今年是收官之年，面临从试点走向全面推广的关键一跃——年初我们曾担心，标准建好了能不能真正走进基层日常？这一年用 X 个能力域的全面评价给出了答案。下面作汇报。」
- **铁律**：C 必须是真实冲突（不能用「面临新形势新任务」等套话冒充）。
- **常见错误（开场三禁）**：① 开场解释「为什么要做这件事」（这是正文内容）；② 用「坐标系」「历史里程碑」等比喻铺垫；③ 超 200 字。

### 模块4：成果段写法（总分 + 数据必有基准）
- **结构**：`板块判断句（总）→ 一是…二是…三是…（分，每条带数据+基准）`
- **数据三种基准**（必选其一，缺则不合格）：
  1. **同比**：「同比增长 X%／同比下降 X 个百分点」
  2. **历史最好/对比过去**：「为历史最好水平」「较三年前减少 X 天」
  3. **超目标/对标位次**：「超额完成目标 X%」「X 项指标优于行业平均水平」
- **重点板块可升级为「分析级」**：数据后补一句揭示机制的规律性判断（「这说明，只有……才能……」），但全文只 2-3 处，避免通篇说教。
- **常见错误**：① 只有绝对值无基准（「完成 X 条条款」——好不好不知道）；② 用「大幅提升/显著改善」等无数字模糊词；③ 同一数据全文多处重复。

### 模块5：问题段写法（直接列举，不展开原因）
- **工作汇报**：`在肯定成绩的同时，我们也清醒看到不足。一是[问题名]，[一句话表现]。二是……三是……`——只列问题与表现，**不分析原因**。
- **专题汇报**：在列问题基础上**补一层原因分析**（制度/资源/能力/客观条件四类实质原因，不写「重视不够」「落实不到位」空话），并按轻重缓急排序。
- **铁律**：不得用「总体良好」「无重大问题」回避；问题必须具体到事项，且在下步有对应措施。
- **常见错误**：工作汇报里问题段大段铺陈原因（越位）；用「这些问题既是……也是……」反复铺垫的咨询式表述。

### 模块6：让领导满意——把领导的话提炼进骨架
- **底层逻辑**：领导反复强调的词句，就是他的判断框架。把它提炼进**小标题/帽段/导语**，领导读到会感到「被听懂、被采纳」，认同度大幅提升。
- **三个落点**：
  1. **标题**：把领导的关键提法做成板块标题主题词（领导常说「刀刃向内」→板块标题「坚持刀刃向内，推进管理转型」）
  2. **帽段**：开篇定性句复现领导的定调话语（领导定调「高质量发展」→帽段「将工作摆进高质量发展大背景谋篇布局」）
  3. **导语**：每板块首句锚定领导关注点（领导关心落地→板块首句先讲「真正走进基层」）
- **常见错误**：通篇用自己的话语体系，领导找不到自己反复强调的提法，会觉得「没领会意图」。

## 质量 Rubric

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 文种规范 | 工作/专题汇报混淆、跑题 | 文种基本对但有越位写法 | 文种特征清晰 | 严格符合该文种定位与禁忌 |
| 骨架完整 | 缺主体或缺问题/下步段 | 五段有缺、字数失衡 | 五段齐、比例大体合理 | 五段齐全、字数落在区间内 |
| 开场得体 | 讲为什么/有比喻铺垫/超字 | 偏长或略铺垫 | 基本切入主题 | 陈述或 SCQA 得体、≤200 字、直切 |
| 数据有基准 | 多处只有绝对值/模糊词 | 半数数据缺基准 | 多数有基准 | 每条关键数据均带同比/历史/目标基准 |
| 问题克制 | 回避问题或大段析原因(工作汇报) | 部分越位或偏空 | 基本克制具体 | 列举具体、克制得当、与下步对应 |
| 领导意图 | 全篇无领导提法 | 个别处体现 | 标题或帽段体现 | 标题+帽段+导语三处落地领导关注点 |

**质量等级判定**（满分 18）：
- PASS（≥14）：可直接提交
- WARN（11-13）：可提交但建议小修
- MAJOR（7-10）：必须修订后提交
- REWRITE（<7）：建议重做

## 输出格式

起草新汇报，先给骨架确认：
```markdown
# 汇报骨架：[主题]
- 文种：工作汇报/专题汇报 ｜ 对象：__ ｜ 预计字数：__
- 核心判断（一句话）：__
- 开场方式：陈述式/SCQA ｜ 开场草稿（≤200字）：__
一、[板块标题（结论句）]（核心：__）
  数据清单：[指标]→[数值]→[对比基准]
二、……
存在问题：一、__ 二、__（工作汇报不展开原因/专题汇报附原因）
下步：每条对应一个问题，含时间节点+量化目标
```

诊断改写：
```markdown
# 汇报诊断表
| # | 位置 | 问题类型 | 改写建议 |
|---|---|---|---|
| 1 | 开场 | 解释了为什么要做 | 删原因铺垫，改为「按照…部署，现将…情况汇报如下」 |
总评：X/18（等级）。优先改：第__处。
```

## 反模式

1. **开场讲「为什么要做」**
   - 识别：开场在论证这项工作的意义、必要性、背景渊源
   - 改：删掉，「为什么」放正文背景段；开场只交代「按照什么部署，汇报什么」
2. **问题段大段分析原因（工作汇报）**
   - 识别：工作汇报的问题段后面跟着「究其原因，一方面……另一方面……」
   - 改：工作汇报只列问题+表现；要分析原因，说明这应该是专题汇报
3. **咨询式坐标系表述**
   - 识别：「在 XX 的坐标系中」「站在历史里程碑上」「六大核心业务的分类逻辑」等咨询/学术腔
   - 改：换成行业惯用的朴实判断句（「管理体系建设取得重要突破」）
4. **数据无对比基准**
   - 识别：「完成 X 条」「建成 X 个」「投入 X 万」——只有绝对值，领导无法判断好坏
   - 改：补同比/历史最好/目标完成度三种基准之一
5. **汇报写成总结**
   - 识别：通篇回顾「我们做了哪些工作」，没有向上的请示落点、没有让领导拍板的判断
   - 改：加结论先行的定性、加领导关注点呼应、加明确的下步（专题汇报加请示事项）

## 汇报 vs 总结（文种辨析）

- **汇报**：向上通报，让领导掌握情况并据此拍板；常带请示落点（专题汇报尤甚）；结论先行，全篇服务于「让领导省力、认可你的判断」。
- **总结**：对内回顾沉淀，面向自身（本部门/本单位）；按全年或阶段盘点工作；标准结构是「成绩—问题—打算」三块，重在提炼经验、固化做法。
- **一句话区分**：汇报是「讲给领导听、请领导拍板」，总结是「写给自己看、给自己复盘」；同一批素材，向上报送走汇报，年终归档走总结，不可一稿两用。
- 写总结请转 `../文种_02_工作总结/SKILL.md`。

## 来源与边界

蒸馏自（均已脱敏，不含客户单位名/具体经营数据/姓名）：
- 文体骨架库：工作汇报、专题汇报两套 structure_skeleton 与 constraints（字数区间、五段顺序、禁忌）
- 框架方法资料：工作报告框架、专题汇报框架（背景与定位→核心内容→推进情况与成果→问题→下步）
- 语言风格资料：工作报告/专题汇报陈述式开场与 SCQA 升级开场、成果段总分写法、问题段克制写法、汇报 vs 讲话语体差异
- 行业汇报提纲样本：工作汇报与现场会交流汇报的多份提纲（板块并列、按重要性排序、做法占比）
- 行业真实交流材料：现场会企业管理交流稿的骨架与开场（脱敏为「某省/某中烟/X%」）

边界：
- 只管「汇报文种怎么搭怎么写」。MECE 判定、标题炼制、段落意群、字句锤炼分别交给对应专项 skill
- 工作汇报与专题汇报骨架不同、问题段写法不同，不可混用；汇报不等于总结，不可一稿两用
- 行业惯用格式（四种一级标题、对比基准口径）源自烟草系统文稿，跨行业套用须重校
