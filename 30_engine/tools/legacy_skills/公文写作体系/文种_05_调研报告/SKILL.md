# 调研报告——用事实说话，把「问题—原因—对策」打成一条链

> 本 skill 只解决「调研报告」这一文种的特有难题：让问题站得住（基于调研事实而非主观臆断）、原因挖得透（由表及里到根因）、对策落得地（可操作且逐条对应原因）。
> 通用技法（标题、段落、篇章结构、炼句）指向各专项 skill，本文件不重复。

## 使用场景

当用户需要：
- 起草一份新的调研报告（已有座谈/问卷/数据/实地等调研素材，要组织成稿）
- 诊断改写已有调研报告初稿（问题泛、原因浅、对策空、对策与原因两张皮）
- 把零散调研素材组织成「问题—原因—对策」一条链

不要用于：
- 设计整篇骨架、判断板块是否 MECE（用 `../专项_01_篇章结构/SKILL.md`）
- 段落论证与数据组织（用 `../专项_03_段落意群/SKILL.md`）
- 对策要展开到任务分解、时间节点、责任矩阵（用 `../文种_03_实施方案/SKILL.md`）
- 单纯找一句金句、排比句素材（用 `../专项_05_炼句金句/SKILL.md`）

## 输入要求

需要用户提供：
- 调研主题（这份调研报告要诊断什么）
- 已有素材类型（座谈记录／问卷结果／数据／实地见闻，分别有哪些）
- 字数要求
- 受众（向谁报、谁来看）

如果输入不足，最多追问 3 个关键问题：
1. 「用了哪几种调研方式、各覆盖多少？」（座谈几场、问卷多少份、看了哪些数据——决定可信度地基）
2. 「最想解决的核心问题是哪几条？」（聚焦真卡点，避免问题泛泛罗列）
3. 「对策只要方向+举措，还是要展开到任务分解？」（要展开到任务分解则应转 `../文种_03_实施方案/SKILL.md`）

## 一、文种定位

调研报告 = 「用事实和数据说话，发现真问题、挖深层原因、提可行对策」的分析性公文。

它区别于其他文种的三条硬特征：
- **不是工作总结**：总结报成绩（成绩/问题/打算），调研报告的落点是「问题—原因—对策」，成效只是铺垫。
- **不是工作汇报**：汇报通报进展，调研报告必须有「调研方法交代」——座谈了谁、发了多少问卷、看了哪些数据，可信度建立在调研过程之上。
- **不是方案**：方案是「怎么干」的施工图，调研报告是「为什么这样干」的诊断书，对策建议只到「方向+举措」层，不展开到任务分解。

一句话判据：**如果一份稿子的问题不是调研得来的、原因停在「重视不够」、对策只是「加强领导」，它就不是合格的调研报告，只是套了壳的工作汇报。**

## 二、标准骨架

调研报告的五段式骨架（核心是中间三块的「问题—原因—对策」层进）：

| 段 | 板块 | 核心任务 | 通用技法去哪 |
|---|---|---|---|
| 1 | 调研背景与方法 | 为什么调研 + 怎么调研的（座谈/问卷/数据/实地）| SCQA 入口见 `专项_01` |
| 2 | 现状与成效 | 客观摆事实、亮数据，不加主观评价 | 数据组织见 `专项_03` |
| 3 | 存在问题（分类） | 基于调研事实，分类列举真问题 | —— 本 skill 模块2 |
| 4 | 原因剖析（深层） | 由表及里挖到根因，逐条对应问题 | —— 本 skill 模块3 |
| 5 | 对策建议（可操作）| 逐条对应原因，方向+举措落地 | —— 本 skill 模块4 |

> 板块标题炼制（结论句、对仗、做亮）统一交给 `专项_02_标题炼制`；本 skill 只管「每块装什么、三块怎么咬合」。
> 详细骨架变体（学习借鉴式、专题诊断式、综合调研式）见 `references/调研报告骨架库.md`。

## 三、方法论模块

### 模块1：「问题—原因—对策」层进逻辑（地基，必过）
- **触发条件**：任何调研报告，起草或诊断都先过这一关
- **核心法则**：三块是一条「现象→原因→解决方案」的演绎链，不是三个并列罗列的筐。
  - 问题层 = 现象（调研中观察到的「是什么不对」）
  - 原因层 = 病理（「为什么会这样」，往深里挖）
  - 对策层 = 处方（「怎么治」，针对病理下药）
- **操作步骤**：
  1. 先把问题逐条编号（问题1、问题2……）
  2. 每条问题往下追问「为什么」，挖出对应原因（原因1对应问题1）
  3. 每条原因往下追问「怎么解」，给出对应对策（对策1对应原因1）
  4. 三列对齐成表，**任何一行缺项都不合格**（有问题无原因、有原因无对策、对策对不上原因，都要回炉）
- **输出要求**：问题、原因、对策三者编号可一一映射
- **常见错误**：问题归类一套逻辑、对策另起一套逻辑，读者无法把对策接回问题（即「两张皮」）

### 模块2：问题要真，且分类呈现
- **触发条件**：写「存在问题」板块
- **「问题真」三条标尺**：
  1. **基于调研事实**：每条问题背后能指出「这是座谈中谁反映的/问卷里多少比例反映的/哪个数据暴露的」，而非起草人拍脑袋的主观臆断
  2. **具体可指**：问题写到具体事项、具体环节，不写「管理水平有待提高」这类放之四海皆准的废话
  3. **不回避**：真卡点照写，不用「总体良好、个别不足」打太极
- **分类操作**：把零散问题按维度归堆（如：认识层/机制层/能力层/数据层；或按业务条线分），同层 MECE，不重叠不遗漏。维度选取见 `references/调研报告骨架库.md` 的问题分类框架。
- **常见错误**：问题泛泛而谈、主观臆断（「思想不够重视」却拿不出调研依据）；问题与原因混写在一段（把「为什么」塞进「是什么」里，后面原因板块就空了）

### 模块3：原因有深度（由表及里）
- **触发条件**：写「原因剖析」板块
- **「由表及里」三层下挖**（每条问题至少挖到第2层）：
  1. **表层**：直接现象层的原因（如「数据不准」→「填报口径不统一」）
  2. **中层**：机制/制度层的原因（→「没有统一的数据治理规范」）
  3. **根层**：能力/认识/资源层的根因（→「缺乏数据分析人才与工具支撑」）
- **有效原因 vs 无效原因**：
  - 无效（禁用）：「重视不够」「落实不到位」「执行力不强」——这是结论不是原因
  - 有效：制度原因 / 机制原因 / 资源原因 / 能力原因 / 客观条件原因（五类至少归到一类）
- **自检问**：对每条原因再问一次「那又是为什么」，问到再问下去就触及体制/资源约束、答案对实际工作无指导意义时，即到根因，停。
- **常见错误**：原因停在表面（只到表层就收笔）；把问题换个说法当原因（「问题是数据不准，原因是数据质量不高」——同义反复）

### 模块4：对策可操作，且与原因一一对应
- **触发条件**：写「对策建议」板块
- **「对策实」三条**：
  1. **对应原因**：每条对策开头能接回「针对……（某条原因）」，对策编号与原因编号对齐
  2. **可操作**：含明确的责任主体/动作/抓手，能让人知道「谁去做、做什么、靠什么做成」，不写「加强领导」「高度重视」这类空口号
  3. **方向到举措**：调研报告的对策落到「方向+具体举措」即可（如需精确到时间节点/任务分解，那是方案文种的活，交 `../文种_03_实施方案/SKILL.md`）
- **对应自检**：做一张「原因—对策对应表」，逐行核对——有原因无对策（漏治）、有对策无原因（无的放矢）都要补/删。
- **常见错误**：对策空喊口号（「切实提高认识」）；对策与原因不对应（原因讲数据问题，对策却讲队伍建设）；把所有对策堆成一段，无法逐条对回原因

### 模块5：调研方法交代（可信度地基）
- **触发条件**：写「调研背景与方法」板块；以及全篇任何一处下结论时
- **要交代清楚**：调研主体（谁带队/哪个部门牵头）、调研对象（哪些单位/多少人）、调研方式（座谈交流/书面问卷/数据分析/实地走访/内部研讨，至少 2 种）、调研时段。
- **为什么重要**：调研报告的全部说服力建立在「这些问题和数据是真调研来的」之上。没有方法交代，读者无从判断问题真假，整份报告降格为主观议论。
- **贯穿要求**：正文摆数据、列问题时，关键处要能回指调研来源（如「7 家单位座谈中均反映」「问卷显示 X% 受访者认为」），数据须有统计口径与对比基准。
- **常见错误**：开篇只写「根据工作安排开展调研」却不说怎么调研的；问题和数据凭空出现，无调研出处

## 四、工作流

### 流程A：起草新调研报告
**输入**：调研主题 + 已有调研素材（座谈记录/问卷结果/数据/实地见闻）+ 字数要求
**步骤**：
1. 先填 `templates/调研报告任务单.md`：把调研方法、现状数据、问题清单、原因、对策逐栏填入——**此单不填满不动笔**。
2. 用模块1 搭「问题—原因—对策」三列对应表，确认每行三项齐全、编号可映射。
3. 按五段骨架（模块2/3/4）展开：问题分类→原因由表及里→对策接回原因。
4. 板块标题交 `专项_02_标题炼制` 炼成结论句并对仗；段落论证交 `专项_03`。
5. 用质量 Rubric 自评，<16 分回炉。
**输出**：一份问题真、原因透、对策实、三块咬合的调研报告
**失败处理**：
- 若某条问题挖不出原因 → 问题本身可能是臆断的，退回核对调研事实
- 若某条原因写不出可操作对策 → 原因可能没挖到可干预的层面，继续下挖或并条

### 流程B：诊断改写调研报告初稿
**输入**：现有调研报告全文
**步骤**：
1. 抽出全文的「问题—原因—对策」三块，列成对应表（缺哪块标红）。
2. 逐条体检：问题是否基于事实（标「臆断/有据」）、原因是否到第2层（标「表层/有深度」）、对策是否可操作且对应（标「空喊/对应✓」）。
3. 查调研方法交代是否齐全（主体/对象/方式/时段）。
4. 输出「问题清单 + 改写对照表」，只改被点名处，遵循修改模式不重写全文。
**输出**：诊断表（板块｜问题类型｜改写建议｜改后等级）
**失败处理**：
- 若对策与原因全篇两张皮 → 不逐句缝补，建议按模块1 重搭三列对应表再落笔

## 五、质量 Rubric

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 文种规范 | 写成了工作汇报/总结 | 文种特征模糊 | 基本是调研报告样式 | 五段骨架完整、落点在问题—原因—对策 |
| 问题基于事实 | 全凭主观臆断 | 半数问题无调研依据 | 多数有据 | 每条问题可回指调研来源，具体不回避 |
| 原因有深度 | 全是「重视不够」式空话 | 多数停在表层 | 多数到机制层 | 逐条由表及里到根因，归得到五类之一 |
| 对策可操作 | 全是空口号 | 多数无抓手 | 多数有动作/主体 | 每条含主体+动作+抓手，能落地 |
| 对策对应原因 | 完全两张皮 | 部分对得上 | 多数对应 | 对策与原因编号逐行映射，无漏无空 |
| 数据支撑 | 无数据或无来源 | 数据少/缺口径 | 多数有数据 | 关键判断均有数据，含口径与对比基准 |
| 调研方法交代 | 完全没交代 | 只提「开展调研」 | 交代了部分 | 主体/对象/方式(≥2种)/时段齐全 |

**质量等级判定**（满分 21）：
- PASS（≥16）：可直接交付
- WARN（13-15）：可交付但建议小修
- MAJOR（9-12）：必须修订后交付
- REWRITE（<9）：建议重做

## 六、输出格式

起草「问题—原因—对策」对应表时：
```markdown
# 问题—原因—对策对应表
| # | 问题（基于何事实）| 原因（挖到第几层）| 对策（主体+动作+抓手）|
|---|---|---|---|
| 1 | 数据应用浅（7家座谈均反映）| 缺数据治理规范+缺分析人才（根层）| 企管部牵头制定数据治理标准，引入分析工具 |
```

诊断改写时：
```markdown
# 调研报告诊断表
| # | 板块 | 问题类型 | 改写建议 | 改后等级 |
|---|---|---|---|---|
| 1 | 原因剖析 | 停在表层「重视不够」| 下挖到机制层：考核未将该项纳入指标 | PASS |
总评：X/21（等级）。优先改：第__条。
```

## 七、反模式

1. **问题泛泛、主观臆断**
   - 怎么识别：问题写「思想认识不到位」却拿不出任何座谈/问卷/数据依据
   - 怎么改：每条问题后补「调研出处」，写不出出处的问题删掉或下沉为推测
2. **原因停在表面**
   - 怎么识别：原因清一色「重视不够」「落实不到位」「执行力不强」
   - 怎么改：套模块3 三层下挖，问到机制/能力/资源层，归到五类原因之一
3. **对策空喊口号**
   - 怎么识别：对策是「加强领导」「高度重视」「切实抓好」这类无主体无动作的话
   - 怎么改：补「谁来做+做什么+靠什么抓手」，例：「企管部牵头，制定统一数据治理规范」
4. **对策与原因两张皮**
   - 怎么识别：原因讲A，对策讲B，读者无法把对策接回任一条原因
   - 怎么改：建模块1 对应表，逐行核对；对不上的对策删除或补上对应原因
5. **无调研方法交代**
   - 怎么识别：开篇只「根据安排开展调研」，全篇问题数据凭空出现
   - 怎么改：补齐调研主体/对象/方式(≥2种)/时段；关键判断处回指调研来源

## 九、来源与边界

蒸馏自：
- 写作体系金字塔核心框架：「问题/原因/对策」三块式（调研报告专属框架）、演绎/归纳纵向逻辑、论据三元素（事实+理论+概括叙述）、so what / why so 上下追问
- 文体骨架库「专题汇报」骨架：现状→做法→问题及原因分析→建议五段式、「原因分析须有实质内容、不得只写重视不够」、「下步建议与问题一一对应防两张皮」
- 行业实际调研报告提炼：座谈/问卷/数据/研讨多法并用、问题分类呈现、问题—改进建议对应表式（已脱敏，不含客户名/具体数据/姓名）

边界：
- 只管「调研报告」文种的特有逻辑（问题真/原因透/对策实/三块咬合）。
- 标题炼制 → `专项_02_标题炼制`；段落与数据组织 → `专项_03_段落意群`；篇章 MECE 与 SCQA 入口 → `专项_01_篇章结构`；金句素材 → `专项_05_炼句金句` 与 `03_dictionary`。
- 对策只到「方向+举措」；若需展开到任务分解、时间节点、责任矩阵，那是方案文种，转 `../文种_03_实施方案/SKILL.md`。
