# 调研报告骨架库

> 配合 `../SKILL.md` 使用。本文件收录调研报告的骨架变体、问题分类框架、原因「由表及里」层次、对策—原因对应表式、调研方法清单。
> 通用技法（标题、段落、SCQA）不在此重复，指向对应专项 skill。

---

## 一、调研报告标准骨架（五段式）

```
一、调研背景与方法
    —— 为什么调研（上级要求/工作需要/重要节点）
    —— 怎么调研的（主体+对象+方式+时段），交代清楚增强可信度
二、现状与成效
    —— 客观摆事实、亮数据，不加主观评价
    —— 区分「已完成/进行中/未启动」三类情况
三、存在问题（分类呈现）
    —— 基于调研事实，按维度归堆，同层 MECE
四、原因剖析（由表及里）
    —— 逐条对应问题，挖到机制/能力/资源根层
五、对策建议（可操作）
    —— 逐条对应原因，方向+举措落地
```

中间三块「问题—原因—对策」是一条演绎链，骨架质量取决于三块能否编号映射、行行咬合。

---

## 二、三种常见骨架变体

不同调研场景，骨架略有侧重，但「问题—原因—对策」内核不变。

### 变体A：专题诊断式（最常用）
适用：就某一专项工作（如管理效能、消耗管控）开展专题调研。
```
一、××工作总体推进情况（现状+成效，含核心数据）
二、专题调研发现的主要问题（分类，4 条左右）
三、问题成因分析（逐条对应，由表及里）
四、下阶段对策建议（逐条对应原因）
（附：问题—改进建议明细表，列「问题描述｜改进建议｜责任部门｜时限」）
```
特点：常带一张明细对应表把问题与建议钉死，是「对策对应原因」的强落地形式。

### 变体B：学习借鉴式
适用：到兄弟单位/先进单位学习后回看本单位。
```
一、调研背景与方法（学习了哪些单位、围绕哪几方面）
二、兄弟单位的特点与亮点（外情，客观描述其做法）
三、反观本单位存在的问题（对照外情找差距，分类）
四、对本单位的改革建议（逐条对应问题/差距）
```
特点：用「外情」（同类单位做法）作镜子照出问题，建议天然对应差距。

### 变体C：综合调研式
适用：覆盖面广、问题维度多的全局性调研。
```
一、调研基本情况（方法+范围+样本量）
二、现状综述（分条线/分维度摆事实）
三、问题与原因（每个维度下「问题+原因」配对呈现）
四、对策建议（分维度给方向+举措）
五、结语（总体判断+推进要求）
```
特点：问题与原因可在同一维度下「配对」写，避免问题、原因隔得太远读者接不上。

## 三、问题分类框架（让问题 MECE 不重叠）

零散问题要归堆成「同层不重叠、合起不遗漏」的几类。常用四套分维度，按调研主题选一套：

| 分类法 | 维度 | 适用场景 |
|---|---|---|
| 层级法 | 认识层 / 机制层 / 能力层 / 数据(基础)层 | 管理类、综合类调研 |
| 业务条线法 | 按生产/营销/物流/专卖/财务等条线分 | 跨条线的全局调研 |
| 要素法 | 制度 / 流程 / 标准 / 队伍 / 工具 | 管理体系、流程类调研 |
| 阶段法 | 事前预防 / 事中控制 / 事后改进 | 风险、质量、消耗管控类调研 |

归类自检：
- 两两比对有无重叠（同一问题被塞进两类）→ 合并
- 对照调研发现有无遗漏（某类真问题无处安放）→ 补位
- 一组问题只用一套分类法，不混用（不能一条按条线、一条按层级）

## 四、原因「由表及里」三层下挖

每条问题的原因至少挖到第 2 层；触及根层最佳。

```
问题（现象）
  ↓ 问：为什么会这样？
表层原因 —— 直接现象层（口径不统一、记录靠手工、设备老化……）
  ↓ 再问：为什么会这样？
中层原因 —— 机制/制度层（缺规范、缺标准、考核未纳入、协同机制不畅……）
  ↓ 再问：为什么会这样？
根层原因 —— 能力/认识/资源层（缺人才、缺工具、缺投入、思路滞后……）
  ↓ 再问下去若只剩体制/资源大约束、对实际工作无指导意义 → 到根因，停
```

**五类有效原因**（每条原因须归得到其中一类，否则是无效原因）：
1. 制度原因——缺制度、制度冲突、制度有断点
2. 机制原因——流程不畅、协同不够、考核激励缺位
3. 资源原因——人/财/物/工具投入不足
4. 能力原因——专业能力、分析能力、管理颗粒度不够
5. 客观条件原因——外部环境、政策变化、阶段性约束

**无效原因黑名单**（出现即回炉）：重视不够 / 落实不到位 / 执行力不强 / 主观能动性不足 / 思想认识有差距——这些是结论或态度评价，不是可干预的原因。

同义反复陷阱：「问题是数据不准，原因是数据质量不高」——把问题换个说法当原因，等于没分析。

## 五、对策—原因对应表式

调研报告对策的生死线是「逐条对应原因、可操作」。用下表把每条对策钉到原因上：

| # | 问题 | 原因（层级）| 对策（主体+动作+抓手）| 落点 |
|---|---|---|---|---|
| 1 | 数据应用浅，停在描述性统计 | 缺数据治理规范（机制）+ 缺分析人才工具（能力/资源，根层）| 企管部牵头制定统一数据治理标准；引入数据分析工具并培训骨干 | 方向+举措 |
| 2 | 标准制修订质量不高、频次过高 | 制修订前瞻性不够、基层沟通机制不畅（机制）| 健全基层标准制修订协调机制；强化集中审核负责制 | 方向+举措 |

对应自检三问：
1. 每条原因是否都有对策接住？（有原因无对策 = 漏治）
2. 每条对策是否都接得回某条原因？（有对策无原因 = 无的放矢）
3. 对策是否含「谁做+做什么+靠什么」？（缺则是空口号）

**对策深度边界**：调研报告对策落到「方向+具体举措」即可。若要展开到「任务分解—时间节点—责任矩阵—资源预算」，那是实施方案的职责，转 `../../文种_03_实施方案/SKILL.md`，不要在调研报告里写成施工图。

## 六、调研方法清单（交代越实，可信度越高）

「调研背景与方法」板块须从以下要素中交代清楚（方式至少 2 种）：

| 要素 | 写什么 | 范例措辞（脱敏）|
|---|---|---|
| 调研主体 | 谁牵头、谁带队 | 「由××部门牵头，组成调研小组」 |
| 调研对象 | 哪些单位、多少人/份 | 「对 X 家单位、X 个部门开展调研」 |
| 调研方式 | 座谈/问卷/数据/实地/研讨（≥2 种）| 「通过座谈交流、书面调研、数据分析、内部研讨等方式」 |
| 调研时段 | 什么时间开展 | 「××年×月至×月」 |
| 样本规模 | 座谈场次、问卷份数、走访点数 | 「先后开展 X 场、X 人次专题研讨」 |

**五种调研方式速记**：
- 座谈交流——面对面听一线声音，适合挖深层困难
- 书面调研/问卷——覆盖面广、可量化（「X% 受访者认为……」）
- 数据分析——用指标暴露问题，最具说服力
- 实地走访——眼见为实，适合现场类问题
- 内部研讨——多方碰撞，适合形成共识对策

**回指要求**：正文每下一个关键判断，尽量回指调研来源——「7 家单位座谈中均反映」「问卷显示 X% 受访者认为」「数据表明……同比……」。无出处的问题与数据，可信度归零。
