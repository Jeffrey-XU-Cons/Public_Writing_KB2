# 公文写作总纲——判文种、串五层、收全稿

> 本 skill 是公文写作的「导演」，不是「演员」。它只做三件事：①判断文种与工作模式；②按五层流程把任务派给对应的下属 skill；③在每层和收口处用统一标准验收。
> 具体技法（怎么搭骨架、怎么炼标题、怎么写段落）一律由下属 skill 承担，本体不复刻。

## 使用场景

当用户需要：
- 接到一个公文写作任务（汇报/总结/方案/规划/调研报告/讲话稿），从立意到成稿走完整流程
- 拿到一堆素材但还没想好怎么组织，需要从「定方向→搭框架→填内容→打磨→审查」被一步步带着走
- 已有初稿，需要按统一标准做全流程统稿验收，并定位该调哪个专项 skill 去修

不要用于：
- 只改一个标题、只对一组小标题做对仗（直接用 `../专项_02_标题炼制/SKILL.md`）
- 只设计骨架、只判断板块是否 MECE（直接用 `../专项_01_篇章结构/SKILL.md`）
- 只写/改一个段落、一句话、一个金句（用 `../专项_03_段落意群/`、`../专项_05_炼句金句/`）
- 纯查行业术语、政治表述顺序（查 `03_dictionary/`，无需走总纲）

> 一句话边界：**单点技法问题直接进对应专项 skill；只有「整篇从无到有」或「整篇统稿验收」才走总纲。**

## 输入要求

接到任务后，若素材里没写清楚，最多追问 3 个关键问题（其余靠读素材和范文自行判断）：

1. **文种**——汇报／工作总结／实施方案／发展规划／调研报告／现场会讲话？（决定走哪条文种路由、套哪本骨架、成效与措施比例）
2. **主题与受众**——核心要说的一个判断是什么？写给谁看／谁来讲？（决定 WA 目标和立意，无受众则无法定调）
3. **字数**——大致篇幅区间？（无特别说明按骨架默认范围，决定详略预算）

> 三问之外不再追问。文种＋主题＋受众这三项一旦明确，立意三字经、四情清单、骨架选择都可由总纲推进。

## 工作流

总纲的核心是「**全流程五层调度**」加「**文种路由**」。先判文种定骨架，再逐层往下走，每层指向对应下属 skill；本层不通过不进下一层。

### 第〇步：判文种 + 判模式（先于五层）

1. **判文种**——对照下表「文种路由」，确定文种，锁定骨架来源与下属文种 skill。
2. **判模式**（沿用项目既有约定，见 `CLAUDE.md`）：
   - 用户说「写／起草／新建／帮我写一份」→ **模式一：框架优先生成全文**，从第一层走到第五层
   - 用户说「改／修改／优化／统稿」→ **模式二：修改/统稿**，跳过一至三层的从零构建，直接进第五层质量审查定位问题，再回派对应专项 skill 定向修改
3. **建任务文件夹**——按 `CLAUDE.md` 规范在 `tasks/[日期]_[文种]_[主题]/` 下落盘。

### 文种路由（先判文种 → 指向文种 skill）

| 文种判定线索（素材里出现） | 文种 | 调用文种 skill | 骨架/比例要点 |
|---|---|---|---|
| 向上级报告进展、成效、数据 | 汇报材料 | `../文种_01_汇报材料/SKILL.md` | 「果」≥50%，成效40-55% |
| 回顾一个周期做了什么、有何体会 | 工作总结 | `../文种_02_工作总结/SKILL.md` | 五忌；须有规律性认识 |
| 部署一项工作怎么落地、谁来做、何时完成 | 实施方案 | `../文种_03_实施方案/SKILL.md` | 「法」≥60%，措施三要素齐全 |
| 谋划未来三/五年目标与路径 | 发展规划 | `../文种_04_发展规划/SKILL.md` | 目标分层（类）+路径（法） |
| 摆问题、析原因、提对策 | 调研报告 | `../文种_05_调研报告/SKILL.md` | 「因」析到第二层根因 |
| 在会上讲、要鼓动部署、口语化 | 现场会讲话 | `../文种_06_现场会讲话/SKILL.md` | 听得懂；谐音类技法禁用 |

> 文种不清时回到「输入要求」第 1 问。文种 skill 提供该文种专属骨架与禁忌；专项 skill 提供跨文种通用技法。两者配合用。

### 五层调度（模式一逐层走，每层有调用、有产出、有过关闸）

```
第一层 思维准备 ──→ 本体方法论（立意三字经/WA/四情四要素/详略）
        ↓ 过关闸：WA 与主旨句写得出来吗？写不出 → 退回研素材，不进结构层
第二层 结构设计 ──→ 调 ../专项_01_篇章结构/  （结论先行·SCQA·MECE·三种排序）
        ↓ 过关闸：一级标题 MECE 吗？so what / why so 两遍走得通吗？
第三层 内容填充 ──→ 调 ../专项_03_段落意群/  （意群·三元公式·四情归堆·详略）
        ↓ 过关闸：每个意群有观点+概括+事实三件吗？详略与重要性成正比吗？
第四层 语言打磨 ──→ 调 ../专项_02_标题炼制/（标题做亮）
                    调 ../专项_04_遣词用字/（准确·简洁·禁用词）
                    调 ../专项_05_炼句金句/（炼句·排比·金句素材）
        ↓ 过关闸：标题是结论句吗？每段删 20% 信息不减吗？
第五层 质量审查 ──→ 本体方法论 + skill_quality.md（统稿八看·意思流窜·数据规范）
        ↓ 过关闸：统稿八看逐项过；Rubric ≥ 20/24 才交付
```

**调度纪律**：
- 一层不过关，不进下一层（结构没搭好不许填内容，内容没填实不许打磨语言）。
- 模式二（修改/统稿）反向走：先用第五层定位问题落在哪一层，再只回派该层对应的专项 skill 做定向修改，不重写无关部分。
- 同一问题在某层连续 3 次过不了关闸 → 触发熔断（见末尾），回项目架构师请示，不硬撑。

> 各层「核心动作 + 产出物 + 调谁」的完整速查表，以及「文种判定决策表」「两种构建方向」，见 `references/全流程调度图.md`。本体只记上面这条主线。

## 方法论模块（总纲本体只管「思维准备层」与「调度判断」，每模块给触发条件·步骤·常见错误）

### 模块1：立意三字经——时·事·势（思维准备层，定调用）
- **触发条件**：第一次接题、还没动笔时；或写出框架后做立意自检。
- **操作步骤**：
  1. **时**——这篇文写在什么时代背景／政策窗口下（如「十五五」开局、行业某专项部署年）。
  2. **事**——具体写的是哪项工作（不要泛化成「管理工作」，要落到「某专项评价」「某条线建设」）。
  3. **势**——这项工作的发展趋势／要往哪走（从定性到定量、从试点到推广）。
  4. **取三字交集**：时×事×势同时成立的那个判断，就是立意区间。把它写成一句「主旨句」。
- **常见错误**：只写「事」（就事论事，无高度），缺「时」「势」（看不出为什么现在写、要往哪去）；主旨句写成话题（「关于管理体系建设的汇报」）而非判断。

### 模块2：WA 目标法（思维准备层，定方向用）
- **触发条件**：凡受委托起草讲话/汇报/方案，动笔前必做。
- **操作步骤**：
  1. **W（说服对象）**——写给谁看／谁来讲。一句话写死。
  2. **A（希望对方采取的行动）**——读完/听完，希望对方批准什么、认同什么、部署什么。
  3. 把 W+A 写在启动单最上方，全文每个板块都回头问「这一段是否服务于 A」。
- **常见错误**：把 W 写成「领导」笼统带过（不同层级领导关切不同）；A 含糊（「让领导了解情况」不是行动，「批准方案进入实施」才是）。

### 模块3：四情·四要素（思维准备层，研素材用）
- **触发条件**：定盘子后、搭框架前的素材调度阶段。
- **操作步骤**：
  1. **四情**逐项调度：上情（上级政策原文逐字理解）／内情（本单位工作实际，先建文件夹再读）／下情（基层执行，座谈调研）／外情（同类单位经验，横向搜索）。
  2. **四要素**逐项核查：事（历史/现状/问题/趋势）／人（领导意图/受众关切）／体（文种体例，对应文种 skill）／景（宏观背景/会议场景）。
  3. 每项填进启动单的清单，缺项标「[待补充：需XX]」，不用模糊话占位。
- **常见错误**：四情只研内情（自说自话，无上情对标、无外情参照）；四要素漏「人」（不研领导意图，写出来不是领导想讲的）。

### 模块4：详略五规律（思维准备层兼内容层，分配篇幅用）
- **触发条件**：填充内容前定篇幅预算时；或统稿发现比例失衡时。
- **操作步骤**：
  1. 按「重要详／新颖详／具体详／近期详／有特点详」给各板块分配字数预算。
  2. 反向：次要略／已知略／抽象略／旧事略／普遍略。
  3. 草稿完成后数各部分字数，看是否与重要性成正比。
- **常见错误**：**详略倒置**——背景写三段、重点措施一句话；成效占全文 80%，问题一句带过。

### 模块5：五种创新路径（思维准备层兼结构层，破套路用）
- **触发条件**：框架完成后自问「这框架是否和上次写的一样」，是则选一路创新。
- **操作步骤**（不破坏 MECE 前提下选一）：
  1. 框架结构创新——两段/三段/纵横交叉替代单一并列。
  2. 阐述角度创新——换视角切入（问题视角→机遇视角）。
  3. 文字表达创新——避免千篇一律的标题词（交给专项_02）。
  4. **观点论断创新**（最重要）——提出对工作的新判断，而非复述上级文件原话。
- **常见错误**：为创新而创新破坏了 MECE；只在文字上翻花样（最表层），不在观点上出新判断（最有价值的一层没动）。

## 质量 Rubric（用「统稿八看」八维度，每维 0-3 分，满分 24）

> 这是总纲的**总验收**标尺，覆盖全篇而非单层。各专项 skill 各有自己的细粒度 Rubric；总纲只看八个整体维度是否达标。

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 主题 | 全文无核心结论或中途跑偏 | 有主旨但部分板块偏离 | 主旨基本一以贯之 | 主旨句贯穿首尾，每板块均服务于 A |
| 结构 | 一级标题不 MECE，层级混乱 | 个别板块交叉或遗漏 | 大体 MECE，层级清楚 | 同层 MECE，纵向以上统下两遍走通 |
| 内容 | 论点空洞无论据 | 部分论点缺概括或事实 | 多数意群三元齐全 | 每意群观点+概括+典型事实俱全 |
| 逻辑 | 横向排序混用、因果断裂 | 个别跳跃 | 排序统一、因果基本完整 | 同层同序，因果链有中间传导步骤 |
| 语言 | 套话堆砌、禁用词、零信息句多 | 局部冗余/不规范 | 基本简洁规范 | 删 20% 信息不减，无禁用词与套话 |
| 数据 | 数字无基准、前后矛盾 | 个别缺基准 | 多数有对比基准 | 同一数据仅一次、均带基准、口径一致 |
| 格式 | 序号跳级、文种格式错 | 个别不规范 | 基本符合文种格式 | 序号体系一致、文种格式完全规范 |
| 整体 | 文气断裂、详略倒置 | 局部卡顿 | 节奏基本顺畅 | 文气一气呵成，详略与重要性成正比 |

**质量等级判定**（满分 24）：
- PASS（≥20）：可直接交付
- WARN（16-19）：可交付但建议小修，标出失分维度回派对应 skill
- MAJOR（11-15）：必须修订后交付，按维度逐项回派专项 skill
- REWRITE（<11）：结构层就没过关，退回第二层重搭

## 反模式

1. **无框架先写正文**
   - 怎么识别：素材一到手就开始码段落，没有一句话主旨、没有一级标题骨架。
   - 怎么改：强制走第一、二层——先写主旨句和粗纲，过 MECE 关闸再动笔。结构没确认前不展开全文（沿用项目模式一 Step 4 不可跳过）。
2. **意思流窜**
   - 怎么识别：同一论点/数据在开篇、正文、结尾出现多次（「各保留一点」）。
   - 怎么改：第五层建「论点地图」，每个论点/数据只许在一处出现，其余删除（不是各删一半）。
3. **详略倒置**
   - 怎么识别：背景三段、措施一句；成效占 80%，问题一句带过。
   - 怎么改：用模块4详略五规律重排预算，数字数对照重要性，回派对应文种 skill 调比例。
4. **套话堆砌**
   - 怎么识别：段落做「可移植性测试」——把单位名/数字换掉后换给别家还能用。
   - 怎么改：每段至少嵌一个不可替换信息（具体数字/专属事件/具体部门+行为），回派 专项_04。
5. **一稿两用**
   - 怎么识别：不研 WA 与四要素，把上次的稿子换个标题就交；领导意图、受众关切完全没体现。
   - 怎么改：重做模块1/2/3，用模块5观点论断创新出一个本次专属的新判断。
