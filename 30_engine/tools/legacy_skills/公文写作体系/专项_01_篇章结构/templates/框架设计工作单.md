# 框架设计工作单（逐项填空）

> 用法：搭新框架时从上往下填「拟制区」；诊断旧框架时填「诊断区」。
> 填完对照 `../SKILL.md` 完成前检查清单与 `../../../skill_framework.md` 自查清单各过一遍。

## 一、基本信息
- 文种：______（汇报/总结/方案/规划/调研报告/讲话稿）
- 受众与目的（WA：说服谁W + 要其做什么A）：______
- 字数预算：______（核心内容须占 ≥60%）

## 二、主旨句（先做，过三检验）
- 主旨句（[时段]+[主体]+在[领域]+[判断]+[数据/事实锚]）：______
- [ ] 可证伪性：换个单位/时段就不成立？（成立才算专属判断）
- [ ] 统率性：下面每个板块都能回答「我为主旨句哪一面服务」？
- [ ] 数据锚：含至少一个具体数据或事实锚点？

## 三、开篇与骨架选型
- SCQA 变体：标准 / 开门见山 / 突出忧虑 / 突出信心（选一，见 `../references/结构方法库.md` 一）
- 三块式：为什么是什么怎么办 / 问题原因对策 / 成绩问题打算（选一，见 同文件 三）
- 搭框方向：自上而下 / 自下而上（见 同文件 五）

同层一致性复核：
- [ ] MECE 无重叠：任意两块不说同一件事换角度
- [ ] MECE 无遗漏：对照 `structure_checklists.yaml` 本文种 required_sections，必备项都有枝
- [ ] 同层同序：全层只用一种排序——选定：时间 / 结构 / 重要 / 意义
- [ ] 层级归属：每个二级都完全归属其一级范畴（不属则重新归属）

## 五、纵向检验
- [ ] so what（自底向上）：遮住每个一级，其下二级能自然概括出该一级
- [ ] why so（自顶向下）：每个一级结论追问「凭什么」，二级答得上
- 主骨架结构：演绎 / 归纳 / 混合（核心演绎+各层归纳）
