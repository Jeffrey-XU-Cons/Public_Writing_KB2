# 示例：框架搭建与 MECE 诊断

> 素材取自 `00_raw_materials/汇报材料` 一篇「对标管理改进项目专项汇报」的真实一级/二级标题骨架（已脱敏为「某省烟草」，隐去单位、姓名、具体数据）。
> 演示流程B（诊断旧框架）：用论点树检验法找出一个有重叠+遗漏的框架，修成 MECE，前后对比。

## 一、原框架骨架（脱敏）

```
（标题）优化对标管理，提升核心竞争力
（开篇）对标是企业管理转型升级的重要工具……现将项目开展情况汇报如下。

一、前期工作情况
   （一）前期调研情况
   （三）项目组织            ← 缺（二），编号本身就漏项

二、总体工作思路
   （一）总体思路
   （二）主要目标
   （三）推进路径

三、主要变化和需要关注的问题   ← 一块装了两件事
   （一）充实指标体系
   （二）实施科学分组
   （三）细化评价方法
   （四）健全运行机制

四、存在问题及下一步建议
   （一）存在问题
   （二）下阶段工作重点
```

## 二、论点树检验（四道检验逐一过）

**主旨句（先补出来）**：某省烟草通过对标管理改进，把分散照搬的旧体系升级为「以提升核心竞争力为中心」的新体系，在指标、分组、评价、运行四方面实现突破。

**检验3 · MECE（同层横扫）——查出两处硬伤：**

| 病灶 | 类型 | 说明 |
|---|---|---|
| 三「主要变化和需要关注的问题」一块装「变化（成效）」+「问题」两类内容 | 重叠×层级混 | 一个一级标题塞两个判断，违反结论先行「一块一判断」 |
| 「问题」同时出现在 三（每个子项下挂『需要关注的问题』）和 四（一）「存在问题」 | 意思流窜 | 同一类内容在两个板块各出现一次，读者两头看到问题 |
| 一、缺（二），只有（一）（三） | 遗漏 | 编号跳号暴露归堆时漏了一项（项目背景/依据） |

**检验4 · 层级归属验证——查出一处错挂：**
- 三的四个子项（充实指标体系/实施科学分组/细化评价方法/健全运行机制）本身归属清晰、互不重叠 → **这部分做对了，保留**。
- 但它们被挂在「主要变化和需要关注的问题」之下，而它们讲的全是「变化（成效）」，与标题里的「问题」无关 → 标题与下挂内容不归属。

**检验1 · so what（自底向上）——三的四个子项概括出的是「四方面成效」，不是「成效+问题」**，进一步坐实三的标题名不副实。

## 三、修框（前后对比）

核心动作：**把「变化」与「问题」拆开，让「问题」全文只在一处出现**；给一补回漏项。

### 改前 → 改后

```
改前：                              改后：
一、前期工作情况                     一、前期工作情况
   （一）前期调研                       （一）前期调研
   （三）项目组织  ← 跳号                （二）需求分析  ← 补回漏项
                                        （三）项目组织
二、总体工作思路                     二、总体工作思路（不动，本就 MECE）
   （一）总体思路                       （一）总体思路
   （二）主要目标                       （二）主要目标
   （三）推进路径                       （三）推进路径
三、主要变化和需要关注的问题  ← 混装   三、对标体系的四项主要变化  ← 只装成效
   （一）充实指标体系                   （一）充实指标体系
   （二）实施科学分组                   （二）实施科学分组
   （三）细化评价方法                   （三）细化评价方法
   （四）健全运行机制                   （四）健全运行机制
四、存在问题及下一步建议  ← 问题重复   四、存在问题与下步重点  ← 问题唯一归此
   （一）存在问题                       （一）当前存在的主要问题
   （二）下步工作重点                   （二）下阶段工作重点
```

### 修框三步说明
1. **拆重叠**：三的标题从「主要变化和需要关注的问题」收窄为「四项主要变化」，只承载成效；三各子项下原挂的「需要关注的问题」全部上提，并入四（一）。
2. **去流窜**：全文「问题」此后只在四（一）出现一次——意思分布表里「问题」一行只对应一个位置。
3. **补遗漏**：一补回（二）需求分析，编号连续，前期工作三步（调研→需求→组织）按时间顺序成立。

## 四、修框前后 Rubric 对比

| 维度 | 改前 | 改后 |
|---|---|---|
| 结论先行 | 1（三是话题+混装） | 3 |
| MECE | 0（既重叠又遗漏） | 3 |
| 纵向严谨 | 1（三 so what 名不副实） | 3 |
| 排序统一 | 2（基本按推进逻辑） | 3 |
| 层级递进 | 1（三标题不归属下挂内容） | 3 |
| 提纲落地 | 2 | 3 |
| **合计** | **7/18（MAJOR）** | **18/18（PASS）** |

## 五、对照正例（同层对齐的好骨架）

取 `00_raw_materials/现场会讲话` 一篇企业管理会讲话第三部分（脱敏）作为「本就 MECE」的正面参照：

```
三、必须抓实抓细本年度企业管理工作
   （一）着力推进精益烟叶生产
   （二）着力推进精益卷烟营销
   （三）着力推进精益物流配送
   （四）着力推进精益专卖内管
   （五）着力推进精益科技创新
   （六）着力推进精益财务管理
```

**为什么是教科书级 MECE**：六条「着力推进精益__」句式全同、按业务板块（结构顺序）划分、六大业务互不重叠又覆盖全面、同层同序。
**注**：此处只评「结构是否 MECE」；这六条标题的对仗/做亮属 `专项_02_标题炼制` 职责，本 skill 不越界。

## 六、交接

修好的骨架（含意思分布表「问题→仅四（一）」）交：
- `专项_02_标题炼制`：把三「四项主要变化」等板块名炼成结论句、做同层对仗
- `专项_03_段落意群`：四（一）问题段、四（二）下步重点段填充论据与数据
