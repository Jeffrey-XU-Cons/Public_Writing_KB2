# 篇章结构——用金字塔搭骨架，先立住再展开

> 本 skill 只解决「谋篇布局」一层：让一篇公文的骨架结论先行、纵向走得通、横向不重叠不遗漏、排序统一。
> 上游是立意（先有一句话主旨判断），下游是标题（`专项_02_标题炼制` 把板块炼成结论句）和段落（`专项_03_段落意群` 填充论据）。
> 本 skill 大量复用既有 `../../skill_framework.md`（v1.6，烟草适配的框架设计法），此处做方法论沉淀，操作细则与自查清单以 `skill_framework.md` 为准，避免重复。

## 使用场景

当用户需要：
- 接到任务、素材在手，要先搭一级/二级骨架再动笔（提纲阶段）
- 一堆零散素材不知怎么组织，要归堆向上概括出结构
- 成稿/旧框架体检：板块是不是 MECE、纵向支不支撑、排序乱没乱、层级清不清

不要用于：
- 把板块的「内容方向」炼成正式标题、做对仗（用 `专项_02_标题炼制`）
- 段落内部的观点+论据+数据组织（用 `专项_03_段落意群`）
- 立意定位、主旨高度本身的确认（属总纲层，见 `../../skill_framework.md` 第零节立意三题）

## 输入要求

需要用户提供：
- 文种（汇报／总结／方案／规划／调研报告／讲话稿）——决定用哪套三块式骨架
- 一句话主旨判断，或要表达的核心结论（无主旨无法做纵向检验）
- 已有的素材清单或旧框架标题（用于归堆与 MECE 诊断）

如输入不足，最多追问 3 个关键问题：
1. 「这篇你想让读者记住的一个核心判断是什么？」（无判断无法结论先行）
2. 「这是向上汇报、对下部署，还是分析问题？」（决定三块式选型与排序逻辑）
3. 「现有哪些板块/素材？」（不给清单无法做 MECE 与归堆）

## 工作流

### 流程A：搭新框架（提纲阶段）
**输入**：主旨判断 + 文种 + 素材清单
**步骤**：
1. **写主旨句**——一句话写出全文靶心判断（含主体+做法+成效），过「可证伪/统率性/数据锚」三检验（见 `../../skill_framework.md` 原则五）。
2. **选开篇与骨架**——按文种选 SCQA 变体（模块2）+ 三块式框架（模块5）。
3. **画论点树**——自上而下或自下而上（模块6）拉出一级板块；每个一级下挂 2-4 个二级支撑。
4. **横向 MECE 检查**——同层两两比对，重叠则合并，遗漏则补位（模块4）。
5. **定排序**——给同层选一种排序（时间/结构/重要），全层统一（模块4）。
6. **纵向双向检验**——自底向上 so what、自顶向下 why so 各走一遍（模块3）。
7. 落成提纲三级（模块7）+ 意思分布表，交 `专项_02` 炼标题、`专项_03` 填正文。
**输出**：一棵 MECE、纵向走得通、排序统一的论点树 + 意思分布表
**失败处理**：
- 主旨句写不出 → 立意未定，退回总纲层（`skill_framework.md` 立意三题）补素材
- 某板块挂不进任何一级 → 板块与主旨脱节，删除或重组，不强行塞

### 流程B：诊断旧框架（成稿阶段）
**输入**：现有全文的一级/二级标题清单
**步骤**：
1. 把所有标题抄成一棵树，逐个一级问「这是不是一个判断」「下挂的二级是否都归它管」（层级归属验证）。
2. 同层横扫 MECE：找重叠（两条说同一件事）、找遗漏（任务清单里有、框架里没有）。
3. 查排序：同层是否混用了时间/重要/结构（模块4）。
4. 查纵向：遮住每个一级标题，看其下二级能否自然概括出这个一级（so what）。
5. 查意思流窜：同一论点/同一组数据是否在两个板块各出现一次。
6. 输出「结构诊断表 + 修框建议」，只动结构，不改标题措辞（措辞交 `专项_02`）。
**输出**：结构诊断表（板块｜问题类型｜修框建议）
**失败处理**：
- 重叠的两块谁去谁留拿不准 → 看哪块离主旨更近，留近的，另一块降级或并入
- 拆完仍不 MECE → 说明分类标准本身有问题，回模块4 换一种排序/划分依据

## 方法论模块

### 模块1：结论先行（地基，必过）
- **触发条件**：每个板块、每一段开头
- **操作**：一次表达只支持一个核心结论，结论放最前；先想清说什么，再想拿什么撑。
- **判定**：把全文开头 3 句单抄，读者仍不知你要说什么 → 结论没先行，重写。
- **常见错误**：用背景铺垫开头（「自XX专项行动启动以来，公司上下认真贯彻……」）——把判断埋在第三段。
- **交叉**：板块标题的结论化由 `专项_02_标题炼制` 模块1 接手。

### 模块2：SCQA 开篇四变体
- **触发条件**：写导语/序言/开头
- **四要素**：S 情境（已知背景）→ C 冲突（发生了什么变化/问题）→ Q 疑问（由此要回答什么）→ A 答案（我们的主张/对策）
- **四变体选型**：

| 变体 | 句序 | 适用文种/场景 |
|---|---|---|
| 标准式 | S→C→Q→A | 一般汇报、工作报告 |
| 开门见山式 | A→Q→S→C | 领导很忙、结论优先 |
| 突出忧虑式 | C→S→Q→A | 问题类、整改类文稿 |
| 突出信心式 | Q→S→C→A | 鼓动型讲话稿 |

- **写完查开头四戒**：背景过多／套话虚话／引据过多／叙述过细。
- **常见错误**：把 S 写成三段背景，A（主张）拖到最后才出现——退化成流水账。

### 模块3：纵向以上统下（so what / why so）
- **触发条件**：框架成形后做纵向检验
- **两个方向**：
  - **so what（向上）**：把底层信息往上概括，问「这说明了什么」，逼出上层结论。
  - **why so（向下）**：从上层结论往下追问「为什么/凭什么」，检验论据是否够。
- **两种纵向结构**：
  - **演绎**（三段论）：大前提→小前提→结论（或 现象→原因→对策）。适合论证/分析类。
  - **归纳**：多个并列论据→共同结论。适合罗列/汇报类。
  - 实战常用混合：核心骨架演绎，骨架之下各层归纳。
- **判定**：自底向上、自顶向下两遍都走得通，纵向才合格。
- **常见错误**：一级标题是「加强组织领导」，下挂的二级却是「完善资金保障机制」——下层不归上层管（层级归属验证不过）。

### 模块4：横向 MECE 与三种排序
- **触发条件**：列完一级标题、或诊断同层板块
- **MECE**：同层相互独立（不重叠）、完全穷尽（不遗漏）。
  - 重叠：两条说的是同一件事，只换了角度 → 合并
  - 遗漏：某类重要情况没有位置 → 补位
- **三种排序（同层只能用一种，不可混）**：

| 内容性质 | 排序逻辑 | 错误用法 |
|---|---|---|
| 工作进展/历史回顾/阶段推进 | 时间（过去→现在→未来） | 先说明年计划再说去年启动 |
| 成效汇报/工作板块并列 | 重要（最重要的先说） | 边缘工作放第一、核心成效压最后 |
| 问题分析/原因阐述/部署 | 意义（原因→结果、问题→对策、主→次） | 先讲措施后讲问题，读者不知为何这样做 |

- **同层同序**：前三条按重要性排、第四条突然按时间排 → 不行。
- **常见错误**：把「成效显著」和「指标完成符合预期」并列——两条重叠。

### 模块5：三块式框架（快速成型）
- **触发条件**：选定文种后定整体骨架
- **三套对照**：

| 三块式 | 适用文种 | 三块内涵 |
|---|---|---|
| 为什么/是什么/怎么办 | 动员类讲话、综合类汇报 | 重要性铺垫 / 工作内容罗列 / 部署措施 |
| 问题/原因/对策 | 调研报告、分析类文稿 | 摆现象 / 挖根因 / 给建议 |
| 成绩/问题/打算 | 工作总结、工作报告 | 回顾成效 / 直面短板 / 下步安排 |

- **操作**：先用三块切大盘，每块内部再用归纳法挂并列条目（一是/二是/三是）。
- **常见错误**：用「成绩/问题/打算」却把「问题」拆到两处（成绩段藏一个、专设问题段又一个）——意思流窜。

### 模块6：自上而下与自下而上
- **触发条件**：决定从哪头搭框架
- **自上而下**（思路成熟时）：写主旨结论→设想读者疑问→逐一回答→每个回答又成子结论，递归往下。
- **自下而上**（素材多、结论未明时）：把素材摞齐→按「为什么/是什么/怎么办」归堆→用信息摘要法（提炼共同本质）或逻辑推论法（推出共同结论）向上概括出结构。
- **判定**：两法可交替；归堆后必做一次模块4 的 MECE 复核。
- **常见错误**：素材一堆就硬套自上而下，凭空造板块导致「有框无肉」；或自下而上堆完不向上概括，停在罗列。

### 模块7：提纲三级落地
- **触发条件**：框架确认后物化为提纲
- **三级**：粗纲（一级标题）→ 细纲（到每段段旨句）→ 腹稿（心中有序可直接下笔）。细纲约等于文稿雏形。
- **提纲质量三检**：①标题与主题严格对应不偏题 ②一级标题 MECE ③每个小标题下有明确内容方向、不留空。
- **一稿过诀窍**：把领导反复说的词句提炼进小标题/帽段/导语，认可度大幅提升。
- **常见错误**：跳过细纲直接写正文，写到一半发现板块不成立返工——提纲不可跳过，再急也先列粗纲定方向。

## 质量 Rubric

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 结论先行 | 通篇背景开路，无判断 | 部分板块仍背景铺垫 | 多数板块结论先行 | 每块首句即结论，开头 3 句见主张 |
| MECE | 同层既重叠又遗漏 | 有一处重叠或遗漏 | 基本独立穷尽 | 同层两两无交叉、对清单无遗漏 |
| 纵向严谨 | 上下层不归属、走不通 | 单向走得通 | so what/why so 基本成立 | 双向均走通，混合结构清晰 |
| 排序统一 | 同层多种排序混用 | 个别条目错位 | 大体统一 | 全层同一排序、与内容性质匹配 |
| 层级递进 | 层级颠倒/并驾齐驱 | 个别层级模糊 | 层级基本清晰 | 上含下、同层并列，归属验证全过 |
| 提纲落地 | 只有空标题、无内容方向 | 部分小标题空挂 | 多数有段旨 | 细纲到段旨、含意思分布表可直接展开 |

**质量等级判定**（满分 18）：
- PASS（≥14）：骨架可交付，可进入 `专项_02` 炼标题、`专项_03` 填正文
- WARN（11-13）：可用但建议小修（多为排序或个别遗漏）
- MAJOR（7-10）：必须修框后再展开
- REWRITE（<7）：分类标准有问题，回模块4/6 重搭

## 输出格式

搭新框架时：
```markdown
# 框架方案：[文种]·[主题]
- 主旨句：[一句话判断]（可证伪✓ 统率✓ 数据锚✓）
- 开篇变体：[标准/开门见山/突出忧虑/突出信心]
- 三块式：[为什么是什么怎么办 / 问题原因对策 / 成绩问题打算]

论点树：
一、[一级板块]（核心论点：XXX）
   （一）[二级]  （二）[二级]
二、[一级板块]（核心论点：XXX）
   ...
- 同层排序：[时间/结构/重要]（全层统一）
- 纵向检验：so what✓ | why so✓
- 意思分布表：[论点A]→仅一(一)；[论点B]→仅二(二)
```

诊断旧框架时：
```markdown
# 结构诊断表
| # | 板块 | 问题类型 | 修框建议 | 改后 |
|---|---|---|---|---|
| 1 | 三「主要变化和问题」 | 重叠（变化+问题混装） | 拆成「主要变化」与「问题」两块 | PASS |
总评：X/18（等级）。优先修：第__块。
```

## 反模式

1. **话题罗列无结论**
   - 怎么识别：一级板块是「整体情况」「相关工作」「下步打算」一串话题词，读者读完不知主张
   - 怎么改：每块先补一句判断（结论先行），话题词降为板块归类名
2. **同层重叠或遗漏**
   - 怎么识别：两块说同一件事换角度；或任务清单里的事在框架里找不到位置
   - 怎么改：重叠合并到离主旨近的一处，遗漏补位——对照模块4
3. **排序混用**
   - 怎么识别：同层前三条按重要性、第四条按时间，读者感到「为什么这样排」
   - 怎么改：按内容性质选定一种排序，全层套裁（模块4 三表）
4. **详略由着性子**
   - 怎么识别：背景写三段、核心措施只一句；字数与重要性不成正比
   - 怎么改：搭框架时就给每块分配「篇幅预算」，核心内容占比 ≥60%（详见 `../../skill_framework.md` 自查清单）
5. **层级颠倒**
   - 怎么识别：二级标题的内容其实比一级还大，或下层不归上层管
   - 怎么改：做层级归属验证，重新归属或调整一级表述（`skill_framework.md` 层级归属验证）
