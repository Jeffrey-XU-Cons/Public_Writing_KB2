# 六大类判定规则与边界案例表（唯一裁决源）

> 争议只准查表；查不到就按最接近项归类并把案例**追加到本表**（一次裁决永久生效）。
> 禁止因分类争议停工空转；任何情况禁止全库重打标（设计第八章死因 D4）。

## 快速判定（先问这两个问题）

1. **这条知识在讲「规定」还是「方法」？** 规定（怎样才合规）→ ①骨或②形；方法（怎样写得好）→ ③架④肉⑤用⑥魂
2. **它绑定具体文种吗？** 绑定（只对请示/纪要等成立）→ 优先①骨；不绑定（所有公文通用）→ 按内容归③④⑤⑥

## 六大类一句话边界

| 类 | 管什么 | 不管什么 |
|---|---|---|
| ①骨 文种规范 | 某文种该怎么写（要件、适用情形、该文种的结构惯例） | 通用结构技巧（归③） |
| ②形 格式规范 | 版式、行文规则、标题格式、落款、印章等「硬规矩」 | 标题怎么起得好（归③或④） |
| ③架 结构与逻辑 | 开头/主体/结尾/过渡/篇幅/**模块写法**——通用的骨架搭法 | 具体措辞（归④） |
| ④肉 语言与措辞 | 惯用语、分寸词、称谓、禁忌、数字时间写法 | 段落安排（归③） |
| ⑤用 场景实战 | 带场景的打法：向上汇报、代笔讲话稿、改他人稿等 | 抽象原则（归⑥） |
| ⑥魂 思维与原则 | 站位、政治性、短实新——为什么这么写的底层逻辑 | 可操作步骤（归⑤或③） |

## 模块写法 vs 其他类的三条裁决线（v1.1 新增小类，最易争议）

- **模块写法 vs 主体展开**：讲某个命名模块（指导思想/工作目标/保障措施…）的写法 → 模块写法；讲主体部分泛化的分条列项/层次安排 → 主体展开
- **模块写法 vs 场景实战**：讲模块本身怎么写 → 模块写法；讲什么场景该不该设这个模块、领导怎么看这个模块 → ⑤用
- **模块写法 vs 文种规范**：模块写法只收跨文种通用的模块知识；「实施方案必须含保障措施章节」这种文种要件 → ①骨·总结计划方案
