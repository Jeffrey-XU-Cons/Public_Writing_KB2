## 输入

- 主题：例如“战略对标实施方法”“精益管理推进路径”“流程责任人机制”
- 可选：字数、是否放行行业内部 / 客户实践素材（见 Step 3）、是否出 docx

## 工作模式判断（先做这一步）

| 模式 | 触发 | 检索问题数 | 输出结构 | 字数 |
|---|---|---|---|---|
| **段落模式** | “写一段”“整合一段”“来一段” | 8–12 | 五段式（思路/方法/机制/融合/案例） | 1,500-2,000 |
| **完整方案模式** | “方案”“实施方案”“建设方案”“咨询方案” | **12–20** | **八段式**（背景/目标/选型/模型/路径/组织/机制/考核） | **3,500-5,000** |

不明确时**默认完整方案模式**。

## 工作流（按顺序执行，不可跳步）

### Step 1：环境检查

```powershell
$py = "D:/ai-runtime/venv-cuda/Scripts/python.exe"
$kb = "D:/projects/Kb-RAG"
```

`$py` 不存在或不在 ThinkBook 上 → 告诉 Jeffrey 检索环境未就绪，停止。**不要退回 tobacco_kb**。

检索的判断规则（问题加工、选库、分级、迁移翻译、判空）以 Kb-RAG 仓库里的 kb-search skill 为准（Kb-RAG 下 .claude/skills/kb-search/SKILL.md），动手前读它；本 skill 只管“拿证据写成品”。

### Step 2：问题加工与选库（按 kb-search §二、§三）

1. 抠意图，把主题拆成**口语问句**（不是关键词堆砌），覆盖真正不同的侧面
2. 按 kb-search §3.1 路由表定层：写材料、汇报一般 **L5 → L6 → L3**；战略规划 **L3 → L5 → L6**；投标方案 **L4 → L6 → L5**；先跑 `& $py $kb/tools/kb_registry.py layers` 看现有类别与库
3. 侧面参考：

| 维度 | 何时用 | 问法示例 |
|---|---|---|
| 总体框架 | 必跑 | “<主题>整体思路怎么定” |
| 推进路径 | 完整方案必跑 | “<主题>分几个阶段推进，每阶段干什么” |
| 制度机制 | 完整方案必跑 | “<主题>要配哪些制度和考核机制” |
| 组织保障 | 写方案 | “<主题>由谁牵头、各部门怎么分工” |
| 行业做法 | 涉及烟草行业 | “烟草企业一般怎么做<主题>”（L5，敏感，见 Step 3） |
| 客户先例 | 主题含“参照某客户” | “<客户>的<子主题>是怎么做的”（L6，敏感，见 Step 3） |
| 底层原理 | 需要讲“为什么” | 退阶后的 B 类问法（kb-search §三·五），用该库自己的语汇 |
| 考核指标 | 写完整方案 | “<主题>的成效用什么指标衡量” |

4. **回显**：“你要写 X，我拆成 N 个问题、分 M 批检索”，列出每批问题和范围
5. 问题总数 >12 或跨 3 层以上，先 `--dry-run` 报范围（kb-search §四 成本闸门）

### Step 3：检索（每批同一侧面 3–5 问，多侧面分批）

```powershell
& $py $kb/tools/search.py --cat 4.1 --q "问题1" --q "问题2" --q "问题3" --top 8 -p deep --json
& $py $kb/tools/search.py --layer L3 --q "..." --top 8 -p deep --json
```

- 写材料用 `-p deep`；**不用 `--all`**
- 要做引用尾注，**不用 `--answers-only`**——完整 JSON 才有 `source`（源文件）、`question`、`strong_count`
- 正式成稿时加 `--trace draft_<主题>` 留痕（落 Kb-RAG 的 runs/）
- 某批分数普遍低于 0.1：先按 kb-search“换词重试”换成该库自己的语汇再试 1 次，再判空
- **敏感素材（L5 行业内部、L6 客户实践）默认不放行**。只有 Jeffrey 明确说要用行业/客户素材时才加 `--include-sensitive`，并且：
  - 成稿顶部标注“内部草稿：含行业内部 / 客户项目记录，不可外传”
  - 引用表里逐条标出哪些来自敏感库
  - 提醒 Jeffrey：对外交付前要脱敏或替换这些段落（Kb-RAG 红线三）

### Step 4：分析召回质量（按 kb-search §五）

- 先按 `strong_count` 降序看，再看分数；精排分 <0.01 基本是噪声
- **A/B/C 三级**：A 直接回应 → 深度整合；B 补充延伸 → 适度引用；C 词面沾边 → 丢弃
- **B 类（`class: "B"`）必须迁移翻译**：“这条讲的是 X 领域的 Y，套到本主题意味着 Z”，不翻译不许用
- 去重：同一 `source` 多条取最有价值的；正文几乎相同的两条（模板生成的重复）只留 1 条
- 缺口补检索最多 1 轮（kb-search §三·六），仍空就在成稿里标“库中无对应积累，以下为通用判断”

### Step 5：按模式选骨架

**段落模式（五段式）：**

```
一、指导思想     — 总体思路 + 金句口诀
二、方法论框架   — 结构化步骤 / 流程
三、机制保障     — 组织、考核、报送、协作
四、体系融合     — 与绩效/精益/财务/数字化的协同
五、典型实践案例 — 两类分开写：① 标杆做法参照（L3/L4 书籍库里的公开企业案例，可直接引用）；② 客户先例（仅 L6、须放行敏感库，标明客户、不可外传）。两类都没有就删本段，不编
```

**完整方案模式（八段式）：**

```
一、背景与战略意义   — 政策导向 + 问题导向 + 方法论价值
二、目标 / 选型对比   — 量化目标 + 参照对比表（如有参照案例必含）
三、核心模型         — 五级 / 六维 / 三层等结构化框架
四、能力体系 / 维度细化  — 各子域具体内容
五、阶段推进路径     — 三阶段 / 四阶段，每段明确任务+输出+时间
六、组织保障         — 领导机构、工作机构、专家支持、培训赋能
七、机制保障         — 制度、资源、信息化、结果运用
八、预期成果与考核指标 — 量化目标表 + 定性成果 + 评价机制
```

按召回素材的实际密度调整段数，不是每段都要有。

### Step 6：输出格式（咨询公文风格）

- **中文标点**：中文全角引号“”‘’，严禁英文直引号和「」『』
- **金句加粗**：“四对照”“七步闭环”等关键词用 `**...**`
- **段落标号**：“一、二、三、”或“（一）（二）”
- **语法**：公文风格，主谓宾完整，避免“的”字叠用，避免翻译腔
- **引用尾注**：每段末尾标 ¹²³，文末附引用表：`QA 编号 | 库 | 源文件 | 层 | 是否敏感`

### Step 7：附评估表 + 登记缺原文

1. **证据覆盖**：每段用了哪些 QA，哪些段落是通用判断（库里没有）
2. **层分布**：A 类 / B 类各几条，B 类是否都做了迁移翻译
3. **缺口与建议**：哪些侧面库里没有积累（这是建库订单，交给 kb-rag），给出补检索命令
4. **缺原文登记（必做）**：凡是因为“需要原文条款、具体数字、文号、客户原话”而写不下去或只能写通用判断的，**在 Kb-RAG 仓库 STATUS.md 的“缺原文登记”表追加一行**（日期、任务、缺什么原文、当时怎么处理、可能出处）。这张表攒到 3–5 条真实需求，才启动原文证据层建设
5. **临时查原文**（仅内部稿）：tobacco_kb 迁入的原文切块在 `20_knowledge/corpus/tobacco_kb/语料/chunks_full.jsonl`，可 grep 关键词找原话；未脱敏，引用即视同敏感素材，按 Step 3 的敏感规则标注

### Step 8（可选）：一键 .docx

Jeffrey 要“出 docx”/“Word 成品”/“直接交付”时：

1. 把成稿 Write 成 markdown：Jeffrey 指定位置优先；未指定写到 `50_tasks/YYYY-MM-DD_主题/draft_HHMMSS.md`（任务目录约定同 gongwen）
2. 转 docx（pandoc 优先，没有则回退 python-docx）：
   ```powershell
   & $py .claude/skills/draft/scripts/md_to_docx.py <md 路径>
   ```
   脚本即本 skill 自带的 `scripts/md_to_docx.py`
3. 调 word-beautify skill 套 NRCC 品牌排版
4. 含敏感素材的稿件不出对外 docx，除非 Jeffrey 确认已脱敏
