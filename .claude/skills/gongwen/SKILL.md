# gongwen · 公文写作总控

依据：`90_design/公文链路设计/` 05 章（主干与三确认点）、09 章（八类场景）、10 章（节点与闸）、11 章（P3 范围）。
本 skill 是**薄调度层**：不写正文、不改句子，只做路由、任务单、确认点和终验把关。

## 当前能力边界（P3 MVP，如实告知用户，不假装）

| 场景 | 状态 |
|---|---|
| F1 有素材写 | 完整链路：gw-draft（W1–W3）→ gw-review（W4–W5） |
| F2 无素材写 / F3 只搭结构 | 可走，未单独测试 |
| F4 定点修改 / F5 整稿改造 | 走 gw-review 的定点操作 / 诊断模式，未单独测试 |
| F6 单点问答 | 经 Kb-RAG 检索（`public_writing_qa` 库，命令见 gw-draft「检索」节，仅 ThinkBook 可跑）；7050 上退回本地直查并说明"本地库直查、覆盖有限"；术语查 `20_knowledge/terms/terms.jsonl` |
| F7 素材加工 | 只做 W3-3 归堆（先摞→再归→再改），不写正文 |
| F8 知识入库 | **不进写作链路**；建库类 skill 未建，按 11 章 P5 与 04 章 §4.4 手工走 |

## 第 1 步 · 判场景（决定走哪条路）

| 用户说法特征 | 场景 | 派给 |
|---|---|---|
| 给了素材（往年稿/数据/台账/批示）+ 要写一篇 | F1 | gw-draft（**自下而上**：先归堆素材，再立意） |
| 只有一句话需求，没素材 | F2 | gw-draft（**自上而下**；内情/下情拿不到必须明说，不许用通用表述糊过去） |
| "先出个大纲/框架" | F3 | gw-draft 大纲模式，**止于确认点 2** |
| "标题再想几个""这段重排""这句拗口""这段太虚" | F4 | gw-review 定点操作（附前后对照） |
| "结构不对""大纲重新搭" | F4→退 W2 | gw-draft 大纲模式（**不是**在句子层修补） |
| 他人来稿/旧稿"整体改一改" | F5 | gw-review 诊断模式：先定位失分层，再回派，不重写无关板块 |
| "XX怎么写""能不能用XX""为什么要结论先行" | F6 | 直接查库回答，不走流程 |

拿不准就问，**最多 3 问，做成选择题**（点头不必过脑，做选择必须过脑）。

## 第 2 步 · 判文种

读 `references/wenzhong-router.md`（六文种判定线索 + 三组易混辨析）。判定**必须给依据一句话**，如"要钱要政策 → 请示不是报告"。

## 第 3 步 · 建任务目录与任务单

```
50_tasks/YYYY-MM-DD_文种_主题/
    素材/            用户给的原始材料
    task.md          任务单（下）
    outline.md       gw-draft W2 产物
    v1_初稿.md       gw-draft W3 产物
    review_report.md gw-review W5 产物，不生成不得呈报终稿
    终稿.md
```

`task.md` 至少写：场景 F?｜文种（依据）｜受众 W｜期望行动 A｜字数区间｜确认点状态（1/2/3 各自 待确认/已确认+日期）。

## 第 4 步 · 派工与三个确认点

1. **确认点 1（意图卡）**：gw-draft 产出 ≤12 行意图卡后，由你呈报，**做成选择题**（如两版主旨方向二选一）。短文种（请示类）可与确认点 2 合并。呈报前自查两项，任一不过不放行：
   - **汇报立场**已写明（送审/报成果 vs 报问题/求决策），主旨备选都与立场一致。选择题里推荐项的理由必须从立场出发，不能只凭“省读者时间”这类通用理由。
   - **素材时点**已核查：核心数据若落在时点缺口里（素材截止后、使用前还有评审/修订/发布），先向用户要最新数据，不许以删节或 `[待补]` 代替。
2. **确认点 2（大纲）**：gw-draft 产出 `outline.md` 且机检 0 block 后呈报，**连同弃用清单一起呈报**（丢了哪些内容块、为什么丢），整份弃用素材不放行。**确认即冻结**，后续偏离须在 outline 里书面记录。改大纲成本是改终稿的 1/10（A6）——这是全流程性价比最高的一次确认，不许跳过。
3. **确认点 3（终稿）**：gw-review 产出 `review_report.md` 后呈报：终稿 + 20 条硬门禁逐条 ✅/❌ + 与大纲偏差说明 + 待人工裁决项。

## 第 5 步 · 终验（呈报前最后一道）

```
python3 30_engine/tools/draft_lint.py 50_tasks/…/终稿.md --outline 50_tasks/…/outline.md --report 50_tasks/…/review_report.md --final
```
（Windows 上用 `python`；纯标准库，无需装依赖）

- 输出有任何 `[block]` → **不呈报**，退回 gw-review。
- 红线 5 条任一 ❌、待人工裁决项仍为"待裁决"、某 pass 已 3 轮未过 → 不呈报，按报告提示处理。
- 0 block 才进入确认点 3。

## 硬规则（任何场景都适用）

- **不编造**：原材料中没有的数字、比例、金额、单位、人物、案例一律不写；缺处写 `[待补:XX]`，`[待补]` 不得进终稿。
- **跨客户素材只取方法与结构，不取数据与名称**：库里的范文、段落、示例来自不同客户（references 里标了 `[客户:XX]`），不得把他方的单位名、数字、项目名带进本稿。
- **中文引号** “” ‘’，严禁英文直引号和「」『』。
- **退回规则**：失分能靠改句子解决 → W4 就地改；不能（站位、论点流窜、结构比例）→ 退 W2 重排，顺次再走 W3/W4。
- 同一问题连续 3 次过不了闸 → 停下，向用户报告卡在哪一层，不硬撑。
