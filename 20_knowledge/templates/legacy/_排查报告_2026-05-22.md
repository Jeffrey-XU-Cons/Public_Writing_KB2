### 4.6 ⚠️ 隐性问题：43/45 模板的 prompt_template 含 PDF 转换垃圾

**最关键的内容质量发现：**

| 检查模式 | 命中数 |
|---------|-------|
| `prompt_template` 字段含「第X页,共Y页」 | **43/45** |
| `prompt_template` 字段含「## 第 X 页」 | **43/45** |
| `prompt_system` 字段含 PDF 页码碎片 | **5/45**（plan-implementation-16, plan-planning-17/18/22/26）|

**典型污染样本（plan-implementation-12.json）：**
```
"...针对每个问题提出 2-3 条具体措施）
第3页,共26页

## 第 4 页

四、责..."
```

**根因：** 这批模板是从 `00_raw_materials/AI写材料提示词模板库/` 下的 PDF 教材转 markdown 后再切分为 JSON 的，转换过程没有清洗页码标记和"## 第 X 页"分隔符，整段直接打包进了 `prompt_template`。

**业务后果：** 如果 Claude Code 直接把 `prompt_template` 作为提示词给 LLM，LLM 会看到`"第 3 页,共 26 页"`这种碎片，可能：
1. 在输出中混入页码"第 X 页"
2. 把"## 第 X 页"误解为 markdown 标题层级
3. 至少污染 prompt 上下文，降低生成质量

`structure_skeleton` / `constraints` / `quality_checklist` 三个字段 100% 达标，且抽查内容质量较好。这些是 2026-03-18「A3 批量写入」操作产出的，字段值来自 A2 骨架 YAML 的 7+2=9 种文体定义，**与 PDF 提取无关，质量可靠**。

**支撑数字：**

- **可救部分**：3 个骨架字段（structure_skeleton/constraints/quality_checklist）= **100% × 45 个 × 3 字段 = 135 项实质内容**，质量良好，可直接用于 CLAUDE.md 的「框架优先生成全文」工作流。这些不是空壳，是真实可用的写作骨架。

- **需重写部分**：`prompt_system` 字段 = **78% 是废话或短文风**。但因为骨架字段已经承载了主要的"写作约束"信息（structure_skeleton 含章节、constraints 含禁止项、quality_checklist 含检查清单），`prompt_system` 实际上是冗余字段，可以批量重写为统一的简短指令或干脆删除。
