## 4.1 QA 单元 schema

**存储（单层 JSONL 真源 + 网页编辑，ADR-015）**：
- **唯一存储层**：`knowledge\qa\c{n}_*.jsonl`，每大类一个文件，每行一条 QA（扁平 JSON 对象）；真源与检索加载的是同一份文件，没有转换环节、没有同步问题
- **人工编辑入口**：`tools\kb_editor.py` 本地网页编辑页——按需启动（`python tools\kb_editor.py` → 浏览器 `http://127.0.0.1:8765`），功能：大类切换 / 关键词与批次过滤 / 行级编辑表单（category_l2、doc_types、status 等受控字段用下拉，选项来自 vocab.py）/ 新增（自动分配下一 id）/ 废弃（置 status=deprecated，不物理删）
- **三道防线**：①保存前强制单条校验（kb_validate 同一套函数，不过不落盘、错误内联显示）；②原子写（临时文件+替换，防半写）；③单实例锁（端口占用即拒绝二开）。Claude Code 直接编辑 JSONL 亦合法，但必须紧跟 `kb_validate`；除这两条路径外禁止手改

字段表（JSONL 顶层字段 = 编辑页表单字段，完全同名）：

| 字段 | 规则 |
|---|---|
| id | `QA-C{1-6}-{5位}`，全局唯一，删除不回收 |
| question | 3–6 个多角度问法，` / ` 分隔；方法型含 ≥1 反向问法 |
| answer | 条文型 4 段 ≥150 字（默认档）；方法/拆解型七层 ≥400 字 |
| answer_type | `条文型` / `方法型` / `拆解型`（校验按此分档） |
| tags | 5–12 个（大类 2-3 + 细分 3-9） |
| scenarios | 结构化四段【主要适用场景】【典型使用者】【触发时机】【注意】 |
| question_keywords | 5–10 个用户搜索词（含口语化与反向搜索词） |
| category_l1 / category_l2 | 1–6 / 受控词表（见 4.2），不过即拒收 |
| doc_types | 受控文种表（16 文种 + 通用） |
| source_path / source_anchor | 真实存在的文件路径（断链门禁 0）+ 章节锚点 |
| extract_method | `v7.1` / `v6.0` / `m3` / `人工` |
| quality_grade / quality_checked | A/B/C + 是否人工抽检过 |
| batch_id / status / created / updated / answer_hash | `B-YYYYMMDD-NN` / active·deprecated / 日期 / sha1 前 12 位（精确去重，入库脚本与编辑页保存时自动计算回填） |

非 QA 单元：范文（articles.jsonl：id/title/doc_type/org_level/industry/summary/why_good/linked_qa/source_path/grade）、段落（paragraphs.jsonl：id/text/func 受控/doc_type/score/source_ar）、模板（templates.jsonl 索引 + 原 JSON 文件）。QA 答案引用范文/段落一律写 `[引用:AR-0123]`——引用只认 id，id 由 audit 保证存在，物理杜绝断链。

## 4.2 受控词表（`tools/vocab.py`，v1.1）

- **C1 骨**：通知通报通告 / 请示报告 / 函批复 / 会议纪要 / 意见决定决议 / 讲话发言稿 / 总结计划方案 / 简报信息
- **C2 形**：版式格式 / 行文规则 / 标题规范 / 落款与成文日期 / 附件与印章
- **C3 架**：开头写法 / 主体展开 / 结尾写法 / 过渡衔接 / 篇幅控制 / **模块写法**（v1.1 新增，ADR-014：指导思想·指导思路 / 总体要求 / 工作思路 / 工作目标 / 思想认识 / 基本原则 / 主要任务 / 重点举措 / 保障措施 / 组织领导 / 实施步骤 等常用模块的写作方法）
- **C4 肉**：公文惯用语 / 措辞分寸 / 称谓规范 / 禁忌与常见错误 / 数字时间规范
- **C5 用**：向上汇报 / 布置工作 / 跨部门协调 / 应急敏感行文 / 领导讲话稿代笔 / 修改审核他人公文
- **C6 魂**：政治性与准确性 / 站位思维 / 简明性原则 / 公文与普通写作的区别
- **段落 func 词表**：开头 / 主体-成绩 / 主体-问题 / 主体-措施 / 过渡 / 结尾 / **模块-指导思想 / 模块-工作思路 / 模块-工作目标 / 模块-思想认识 / 模块-基本原则 / 模块-主要任务 / 模块-保障措施 / 模块-组织领导**（v1.1 新增前缀族，范文中的模块段落样本按此归档，供修改时定向调取）

## 4.4 萃取批次 SOP（十步闭环，单批 30–50 条，v1.2 按单层 JSONL 重排）

```
①登记(source\manifest.yaml + 建 batches\B-YYYYMMDD-NN\) 
→ ②预估报告(plan.md，宁低勿高)
→ ③萃取(gw-extract → raw_output.md 六列 MD 表——第一审阅面)
→ ④转换入库(脚本把 MD 表逐条转 JSON 追加进对应 c{n}.jsonl，自动补 id/answer_hash/batch_id 等字段)
→ ⑤校验(kb_validate 100% 通过，不过逐条打回③修)
→ ⑥去重(answer_hash 精确 + 向量>0.92 近重复按 v7.1 合并增强策略处置清零)
→ ⑦专家抽检与修正(在 kb_editor.py 网页端进行：按 batch_id 过滤出本批，随机 max(5条,10%)，
   合格率≥90% 否则整批打回③；修正直接在编辑页改（保存即校验）；
   **强制差评制：每次必须指出本批最差一条及其问题，不许交全优白卷**——防橡皮图章化)
→ ⑧审计(kb_audit --scope 本批)
→ ⑨建索引 + 冒烟(kb_ingest 内嵌 validate→audit→build，不过物理建不出；冒烟 10 条)
→ ⑩git commit(批次粒度：jsonl + batches\ 同 commit，支持整批回滚)
```

**首件铁律**：第一批只取 1 篇文章（约 5,000 字）走完十步全绿，实测产出即为一期条数预估的唯一校准基准；每开一个新子类，先萃 1 篇给 Jeffrey 抽读确认口径再批量。**十步走通之前禁止任何批量萃取。**

## 4.5 检索机制

```
gw-search(LLM): 需求→按 V5 诊断决定查哪些类/发几路查询（提示词承担，无 Python 诊断器，ADR-006）
    ↓ 调 tools\search.py --q "..." [--q ...] [--doc-type 请示] [--category c1,c3] [--l2 模块写法] [--kinds qa,para] [--top 12] --json
Python: LanceDB 原生混合检索(向量 + FTS/BM25 双路) → 原生 RRF 融合 → metadata 过滤(doc_type/category/l2/status=active)
    → bge-reranker 精排 → C级淘汰(阈值待实测定，见第九章 T-1) → 去重 → JSON 输出
    输出: results[{id,kind,score,question,answer,category_l1/l2,doc_types,source,hit_queries,retrieval{vector_rank,fts_rank,rrf_score,rerank}}]
         + stats{queries,candidates,after_filter,after_rerank,dropped_low_score,latency_ms,index_stale,mode,rerank_enabled}
gw-search(LLM): A/B 语义分级（V5 标准）→ 去重合并 → 价值排序 → 素材包（A 级 10–20 条深度引用）
```

`--l2` 为 v1.1 新增可选参数（ADR-014），典型用法：修改「指导思想」段时 `--category c3 --l2 模块写法 --kinds qa,para`，同时命中模块写法 QA 与 `模块-指导思想` 段落范例。

> **v1.5 变更（ADR-019）**：检索引擎由「ChromaDB + 自建 RRF」改为 **LanceDB 原生混合检索**。
> 链路总形态不变（双路召回 → RRF → 过滤 → 精排 → 淘汰 → JSON），变的是 BM25 与 RRF 由库原生提供、不再自建。
>
> ⚠️ **中文分词红线**：FTS 索引建表时必须显式配 **`base_tokenizer="icu"`**（2026-09-12 实测确定）。
> 多数 BM25 实现默认按空格切词，中文会被吞成单一 token 而**静默失效**——不报错、只是关键词那一路召回归零。
> 此项列为第九章 AT-3 专项验收。
>
> **完整功能需求、参数规格、验收标准见 [第九章 检索需求规格](09_检索需求规格.md)。**

索引陈旧处理：manifest 时间戳落后于 knowledge\ mtime → stats 标 `index_stale:true` + skill 提醒，**warning 不拒绝服务**（死因 D5 解药）。重建触发点 = 批次入库后（SOP 步⑨）；写作途中新增素材进暂存、隔日统一走 SOP。全量重建不做增量（数据量级下 <10 分钟，换索引永不漂移）。

## 4.6 质量门禁指标（kb_audit.py，改造自旧 audit_kb_sources.py 七维框架）

| 项 | 阈值 | 级别 |
|---|---|---|
| JSONL 逐行可解析 / 必填字段 / 受控词表 | 100% | error |
| ID 正则 + 全局唯一 / answer_hash 精确重复 | 0 违例 | error |
| source_path 与 `[引用:]` 断链 | **0** | error |
| 污染启发式（答案<50字/含"作为AI"等模式串/数字无来源） | >10% error，>5% warning | e/w |
| 索引-真源一致（LanceDB 条数 == active 条数，manifest 比对） | 一致 | error |
| 文档-实现一致（G 项，3 条可靠机判：声明脚本存在 / collection 名与 manifest 一致 / STATUS 宣称 QA 数 ±5%） | 通过 | error |
| 目录树漂移、禁用命名、skills 文本含 index/ 路径 | — | warning |
| 中文弯引号（答案禁英文直引号） | 0 | error |
| golden Top5 命中率 | ≥70%（一期唯一硬线） | 报告项 |

**强制节点**：①每批入库前（--scope 增量，秒级）②pre-commit hook 只跑 `kb_audit --fast`（<10 秒——**hook 慢就会被绕，绕一次门禁即死**）③每阶段末全量 + eval ④重建索引后 E 项+冒烟。error 零容忍；warning 进 STATUS 债务清单、下阶段 checkpoint 前清零。pytest 移出 hook（阶段末跑）。
