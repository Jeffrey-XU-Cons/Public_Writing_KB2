## 3.1 系统分层

```
L4 交付层    drafts\ 下的成稿（md；需要时 word-beautify 转仿宋 A4 docx）+ delivery_log.md 台账
     ▲ 成稿（gw-draft 产出、gw-review 四 pass 放行、20 条门禁呈报）
L3 智能体运行层（Claude Code）  CLAUDE.md + .claude\skills\{7个}
     萃取线: gw-extract → gw-ingest → gw-audit     写作线: gongwen → gw-search → gw-draft → gw-review
     ▲ 检索 JSON（search.py 契约）        │ Bash 调用 tools\*.py
L2 索引检索层（Python 确定性，永不调 LLM）
     kb_validate.py → kb_ingest.py（唯一入库入口：校验→建索引→审计，audit 不过 exit 1 物理拦截）
     search.py（LanceDB 原生混合检索：向量+FTS 双路 → RRF 融合 → bge-reranker 精排 → C级淘汰 → JSON，ADR-019）
     kb_editor.py（本地网页编辑页：127.0.0.1 按需启动，保存内嵌校验，ADR-015）
     kb_audit.py / kb_eval.py / draft_lint.py / doctor.py / common.py
     ▲ 只读（editor 是唯一合法写入口之一）
L1 知识资产层（进 git）
     knowledge\qa\c{n}_*.jsonl（QA 唯一真源=检索层同一份；人工修改走 kb_editor.py 网页端）
     其他: exemplars\ articles.jsonl paragraphs.jsonl patterns\ templates\ terms\ rules\
     index\（可丢弃派生物，不进 git）
```

垂直纪律：
- **L3 永远不直接摸 index\，只认 search.py 的 JSON**（kb_audit 扫描 skills 文本中出现 `index/` 路径即报警）
- **QA 数据修改纪律**（ADR-015）：JSONL 的人工修改只准走 kb_editor.py 网页端（保存即校验）；Claude Code 直接编辑必须紧跟 kb_validate；pre-commit fast audit 兜底一切路径

## 3.3 技术选型

| 项 | 选定 | 不选 X 的理由 |
|---|---|---|
| Embedding | bge-large-zh-v1.5（fp16 约 1.5GB 显存；CPU 回退一等公民） | bge-m3：能力浪费+作废已验证链路 |
| 重排 | bge-reranker-base（已缓存） | 不重排：问题变体多、粗排噪声大 |
| 向量库 | **LanceDB**（嵌入式，向量+FTS 同库；v1.5 改，ADR-019） | ChromaDB（v1.4 原选型）：无中文 BM25，混合检索需自建；FAISS 无 metadata 过滤；Qdrant/Milvus 要常驻服务或 Docker（Milvus Lite 且不支持 Windows） |
| 全文检索（BM25） | **LanceDB 原生 FTS**，建表时必须显式配 **`base_tokenizer="icu"`**（2026-09-12 实测：jieba 需预下载语言模型不开箱可用，zh 选项不存在，icu 实测有效） | rank_bm25 自建（v1.4 原选型）：需自行实现 RRF 融合；**LlamaIndex BM25Retriever：中文默认破损且不可修**（`token_pattern` 吞整句、`tokenizer` 参数已废弃）；ES：JVM 常驻，杀鸡用牛刀 |
| 融合排序 | **LanceDB 原生 RRF**（v1.5，ADR-019） | 自建 RRF（v1.4 原选型）：库已原生提供，自建属重复造轮 |
| QA 人工编辑面 | **kb_editor.py 本地网页编辑页**（Flask 单文件+内嵌单页 HTML 约 200 行；按需启动 127.0.0.1:8765，非常驻；保存内嵌 kb_validate 校验+原子写+单实例锁）（v1.2，ADR-015） | Excel 维护层：多一个存储格式+转换环节，且 Excel 另存有毁库风险（ADR-013 已废）；常驻编辑服务：违背按需原则 |
| 检索服务形态 | CLI 脚本每次调用（冷启动 5-8 秒，一篇公文检索 3-5 次总开销 <1 分钟）；支持一次传多 query | 常驻 FastAPI/MCP：nssm 托管+端口+崩溃恢复 = 旧项目式过重 |
| 依赖（6 项） | torch(按 tobacco_kb freeze 钉版) / sentence-transformers / **lancedb**（v1.5 替 chromadb+rank_bm25+jieba；FTS 用内置 icu 分词，无需外部分词库） / pyyaml / **flask**（v1.2，仅 kb_editor 使用） / **openpyxl**（v1.6，仅 kb_import 使用，ADR-020；不进检索链路） | pandas/openpyxl（随 Excel 层撤销）、pydantic（30 行纯函数够）、LangChain/LlamaIndex（黑盒调试地狱；且 LlamaIndex 中文 BM25 默认破损）；flask 不进检索链路 |

## 3.4 索引组织（3 个 collection，六大类只做 metadata 不做物理隔离）

- `kb_qa`：向量侧只嵌 `question + question_keywords + scenarios 前 50 字`（答案全文归 FTS/BM25 侧）；LanceDB 记录 `id={qa_id}#q{n}` 每问法变体一条，检索后按 id 回 JSONL 取全文
- `kb_para`：段落+句式，嵌正文（含 v1.1 新增的 `模块-*` 功能段落）
- 范文**一期不建向量 collection**：articles.jsonl 的 title/doc_type/industry 走 BM25；整篇参考由 skill 按 doc_type 过滤后直接 Read 原文。二期 M2 拆解积累 100+ 篇摘要后再建
- 不按六大类切 6 个库的理由：写一篇请示同时要命中①②③④，物理切库 = 6 次 ANN + 手工归一化，纯负债
