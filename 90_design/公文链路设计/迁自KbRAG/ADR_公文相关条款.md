## ADR-001 ~ 012（v1.0 定稿，2026-07-05）节选：公文相关条款

原表格 ADR-003（Embedding 模型选型）、ADR-005（检索工具命名与契约）、ADR-006（问题诊断双头）三条**留在 Kb-RAG**（两边共用/QA 库侧仍依赖），此处只摘公文专属的九条：

| ADR | 冲突点 | 裁决 | 关键理由 |
|---|---|---|---|
| 001 ⚠️曾被 013 部分取代，ADR-015 已恢复全部效力 | 知识真源格式：CSV vs 嵌套 JSONL | **扁平 JSONL 为唯一真源**（字段扁平无嵌套 meta、目录用 `knowledge\`、批次 Markdown 表为萃取产出的第一审阅面）；人工修改入口见 ADR-015 | 七层答案是多段 Markdown，行式 JSONL 对 git diff 与逐行校验最友好 |
| 002 | ID 格式（三版并存） | `QA-C{1-6}-{5位}`（如 `QA-C3-00042`）；范文 `AR-`、段落 `PG-`、模板 `TP-`、句式 `SP-`、术语 `TM-`；全局唯一、永不回收 | 最简单、正则可校验 |
| 004 | Skill 清单（6/7/8+ 三版） | **7 个封顶**：`gongwen` `gw-search` `gw-draft` `gw-review` `gw-extract` `gw-ingest` `gw-audit`；不设 pm-check / gw-plan / gw-polish / gw-intent | 收尾例程是必做动作不该靠触发；润色并入 gw-review 第四 pass |
| 007 | 范文迁移（复制 vs 引用） | **物理复制**进 `knowledge\exemplars\`（TA 265 件 + 行业 240 篇 + 个人交付物精选 30-50 份）；其余个人交付物留旧项目只读引用（作萃取素材）；断链阈值 **0** | 复制是一次性成本，跨仓库引用是永久风险 |
| 008 | 终稿验收（20 条硬门禁 vs 八看 24 分制） | **20 条硬门禁为唯一放行标准**；「统稿八看」降为呈报组织视图，废除打分制 | Rubric 打分对单人项目是伪精确 |
| 009 | 评测口径 | 一期 **30 条封顶**（每类 5 条，10→20→30），`eval\golden.yaml`；唯一硬线 **Top5 含 expected_id ≥70%**；回归用 before/after JSON diff 人工解读；稳定期扩 60 条、目标 ≥80% | 小样本多条并行硬线 = 假警报 = 门禁被禁用 |
| 010 | 坏资产处置 | 允许尝试修复，**0.5 天/项时间盒**，超时即弃、降级为素材重萃 | 修复烂资产是无底洞 |
| 011 | 交付归档与台账 | 归档 `drafts\YYYYMMDD_文种_主题\`；台账 `drafts\delivery_log.md` **进 git**；不设 deliver.py，归档由 Claude Code 执行 + word-beautify 转 docx | 台账是执行追踪证据必须进 git |
| 012 | 一期规模 | 一期 **500–700 条 QA、封顶 2,000**；单批 **30–50 条**；LLM 重萃取聚焦 c1骨/c3架/c4肉；c2 靠国标 M3、c5 靠范文库、c6 靠书籍规则 M3——六类第一天起都有内容但火力分级；排期按「会话数」；首件实测为唯一校准基准 | 1,900 条 = 150 万字级 LLM 产出，是「6 周拖 4 个月」的复刻配方 |

## ADR-015（v1.2 追加，2026-07-05，Jeffrey 裁定）

| ADR | 决议 | 内容 | 配套机制 |
|---|---|---|---|
| **015** ⚠️Excel 用途部分由 020 放宽 | **取消 Excel 维护层；JSONL 单层真源 + 本地网页编辑页**（取代 ADR-013 全部；恢复 ADR-001 的「扁平 JSONL 唯一真源」） | ① `knowledge\qa\c{n}_*.jsonl` 是 QA 数据的**唯一存储层**（真源=检索层同一份，不再有转换环节）；② 新增 **`tools\kb_editor.py`：本地网页编辑页**（Flask 单文件 + 内嵌单页 HTML，约 200 行）——JSONL 通过网页端读取、检索过滤、人工修改、新增、废弃；③ **按需启动非常驻**：`python tools\kb_editor.py` → 自动开浏览器 `http://127.0.0.1:8765` → 编辑完 Ctrl+C 关闭，不用 nssm、不开机自启、只绑 127.0.0.1；④ 编辑页功能封顶（宁少勿多）：大类切换 / 关键词与批次过滤 / 行级编辑表单（受控字段下拉，数据来自 vocab.py）/ 新增（自动分配下一 id）/ 废弃（置 status=deprecated，不物理删）——**不做**多用户、登录、统计图表、索引重建按钮 | ① **保存前强制校验**：编辑页保存动作内嵌调用 kb_validate 的单条校验函数，不过不落盘、错误内联显示——这是取消 Excel 后守住数据质量的**第一道闸**；② **原子写**：保存 = 内存改行 → 写临时文件 → 原子替换，防浏览器崩溃产生半写文件；③ **单实例**：启动时检测端口占用即拒绝二开，防并发写冲突；④ JSONL 人工修改**只准走编辑页**（或 Claude Code 改完即跑 kb_validate）；pre-commit fast audit 兜底一切修改路径；⑤ 依赖变化：撤 pandas/openpyxl，增 **flask**（仅编辑页使用，检索链路不引入）；⑥ **禁区清单修订**：「不建 Web UI」改为「不建**对外/常驻** Web 服务；本地按需启动的 kb_editor.py 是唯一例外」 ；**（020 注）** 本条反对的是「拿 Excel 当**维护层/编辑面**」（另存毁库风险）——该立意继续有效；ADR-020 放宽的只是允许 Excel 作为**上游一次性导入格式**（只读、不回写），公文六大类 JSONL 单层真源与 kb_editor 编辑面地位不变 |

## ADR-016 ~ 017（v1.3 追加，2026-07-06，Jeffrey 裁定；实施期决策）

| ADR | 决议 | 内容 | 配套机制 |
|---|---|---|---|
| **016** | **QA 按条自动路由到六大类**（细化 ADR-001「一条一主类」；使「整本书」可一批处理） | 背景：处理整本书（如李忠秋《结构化写作》31.7 万字，横跨 ③架/⑤用/⑥魂/④肉）时，「一批=一类」不成立。裁决：`category_l1` 从**批次头部**下放为 **raw_output.md 首列**（表由 9 列→**10 列**）；`kb_ingest.py` 按每条自己的 category_l1 **自动路由**到 `knowledge\qa\c{n}_*.jsonl`，一个批次可同时写入多个大类文件；id 按**各大类独立序列**分配 | ① 物理仍是单一检索库、六大类是 metadata 维度（架构不变，只是真源按大类分文件存）；② **一条一主类**不变——跨类知识靠 tags 与检索权重，不靠复制；③ 多文件写入采**全批原子 + 全体回滚**（任一大类文件写入后 audit 不过，所有本批触及的文件一起回滚）；④ 去重跨全部大类文件比对 answer_hash；⑤ 边界争议查 `category-map.md`，不停工空转，禁止全库重打标（死因 D4） |
| **017** | **答案字数 500–2000**（调整 ADR-012 分档下限、新增上限） | 方法型/拆解型答案下限 400→**500**、全类型上限 **2000**（超限 error，提示拆条或精简）；条文型下限保留 **150**（格式/条文类硬撑到 500 字即注水、伤检索——评审明确反模式，且会使已入库通知批次失效）。写死于 `tools\vocab.py` 的 ANSWER_MIN_CHARS / ANSWER_MAX_CHARS，kb_validate 双向校验 | 若后续要求条文型也 ≥500，改 vocab 一处即可；上限防七层答案膨胀成长文（长答案伤向量检索、抬高抽检成本） |
