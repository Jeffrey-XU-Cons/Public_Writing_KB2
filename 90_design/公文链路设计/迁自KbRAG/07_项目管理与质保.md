**反沼泽双规**（死因 D2）：一期 QA 封顶 2,000 写进 CLAUDE.md 禁区；Phase 4 末写作 skills 仍未动工→无条件冻结萃取带库进 Phase 5，缺口由写作实战反向定向补萃。

## 7.2 通用 DoD + Checkpoint（每阶段末，Claude Code 收尾会话执行）

DoD：验收表逐条实测 / audit 退出码 0 / eval 结果进 STATUS 仪表盘 / STATUS 更新 / git status 干净 / ARCHITECTURE 与改动一致。

Checkpoint 三选一：**继续**（100% 过）/ **调整**（≥70% 且缺口有因，最多补 3 天，仍不过降级止损；**禁止带病进入下一阶段**）/ **止损**（<70% 或二次调整不过：砍范围→换方案→冻结出 v0.x——过了门禁的半成品库就是可用资产，不存在全损）。

## 7.3 执行追踪（全部转嫁给 Claude Code，零意志力成本）

- **STATUS.md** 五段固定格式 ≤100 行：当前阶段/数字仪表盘(QA 数·audit·golden·台账行数)/本次会话做了什么/下一步≤3 条/决策日志追加式一行一条。CLAUDE.md 硬指令：**每次会话结束必更新 STATUS 并 commit**；hook 软校验（knowledge/tools 变更而 STATUS 24h 未动→醒目 warning 不拦截）
- **commit 纪律**：`类型(范围): 摘要`，类型限 kb/tool/skill/eval/doc/fix；每会话 ≥1 commit；批次独立 commit（jsonl+batches 同 commit，回滚粒度=批次）
- **停滞响应**：7 天无 commit→下次会话第一件事读 STATUS 恢复上下文+完成一个最小批次（15 分钟也算合法会话）；14 天→「缩圈」砍掉未开始阶段直接出 v0.x 打 tag。检测滞后于下次会话属已知局限，如需主动提醒可用 Claude Code schedule 每周检查 git log（可选项）
- **架构同步**：ARCHITECTURE.md 只写现状禁写愿景（愿景进 STATUS backlog）；结构变更同 commit 更新文档；audit G 项 3 条机检兜底

## 7.4 测试策略

- **Python 单测**：只测确定性纯函数——kb_validate 的 schema 判定、ID 生成与查重、去重合并逻辑、**kb_editor 的保存函数（合法记录落盘/非法记录拒绝/原子替换三用例，v1.2；不测 Flask 路由与页面）**。每个 tools\*.py ≥3 个 pytest 用例，全量 <30 秒，阶段末跑（不进 hook）。测试与脚本同 commit 是 CLAUDE.md 行为指令（不做 hook 拦截）
- **检索评测**：golden.yaml 一期 30 条（每类 5 条，10→20→30 随 Phase 增长），唯一硬线 Top5 ≥70%；回归用 before/after JSON diff 人工解读（复用旧 eval.py 机制）。**v1.5 起细化为 [第十章 检索测试方案](10_检索测试方案.md)**——L0-L6 六层 34 条用例 + 4 组对照实验；其中**三类静默故障（中文分词失效 / 废弃条目泄漏 / 阈值永不触发）列 S1 致命级，专项用例强制拦截**；Top5 ≥70% 仍为唯一效果硬线，延迟只记录不设线
- **写作 E2E**：8 文种各 1 份固定任务书存 eval\e2e\；双层判定 = draft_lint 全过 + Jeffrey 5 分制 ≥4；v1.0 后 skill 提示词大改至少回归 3 例
