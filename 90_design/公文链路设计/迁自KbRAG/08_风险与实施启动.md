## 8.1 风险与事前验尸哨兵

| 死因/风险 | 触发信号 | 预防/止损 |
|---|---|---|
| D1 规格分裂复发 | 任一字段名在 CLAUDE.md/tools/skills 三处 grep 不一致 | ADR 表为唯一命名源；发现即冻结萃取，**以已写代码为准回填文档**一次会话对齐 |
| D2 萃取沼泽（最可能死法） | 连续两周只有 kb 类 commit；条数被向上修正 | 每周实写 1 篇 + 封顶 2,000 + Phase 4 末强制转段 |
| D3 知识库被写作悄悄弃用（无声死亡） | 台账 A 级引用率 <50% 连续 3 篇；贡献分连续 ≤1 | 归因专场：检索没召回→调阈值/嵌入构造；库里没货→砍公共素材全力 M2 拆个人交付物；都不是→接受「条文类走 references 常驻」降级并记 ADR |
| D4 六类边界争议返工 | 抽检 category 异议率>20%；「同一知识两类各一条」反复出现 | category-map.md 边界案例表为唯一裁决源（首件批次预填 15-20 例，**含「模块写法 vs 主体展开」「模块写法 vs 场景实战」边界例**）；golden 主判定=命中 expected_id 而非大类；争议耗 >2 会话→category 降级为统计维度，**任何情况禁止全库重打标** |
| D5 门禁摩擦→绕行→静默失效 | git 出现 skip/no-verify 语义改动；同一 warning 连续两期未清 | 索引陈旧只 warning；hook 永远 <10 秒；发现绕行=一级事故：封死绕行路径**同 commit** 修掉逼人绕行的摩擦点 |
| D6 人工闸橡皮图章化 | 连续 5 批抽检 0 不合格（统计上可疑）；确认点秒回成常态 | 强制差评制；确认点选择题化；坐实后「降频提深」：每 3 批抽 1 批整批精读+随机回捞复检 |
| R2 CUDA 环境 | doctor GPU 项 1 个工作日不过 | CPU 回退一等公民（设计内建，非降级）；BM25-only 再兜底；环境死磕禁超 2 天 |
| R3 范围蔓延 | 想加 Web UI/新运行时/六类外知识 | CLAUDE.md 禁区清单：不建 Web 服务、不用 Dify、v1.0 前不扩文种；新想法只准进 backlog |
| **R6 编辑页数据事故**（v1.2 改写，ADR-015） | jsonl 出现解析失败行；同一文件 git diff 出现大面积无关变动（疑似半写/覆盖）；发现绕过编辑页的手改痕迹（commit 中 jsonl 变动无对应校验记录） | ① 保存前强制校验（kb_validate 同套函数），非法记录不落盘；② 原子写（临时文件+替换），浏览器崩溃/断电最多丢当前一条编辑；③ 单实例锁（端口占用拒绝二开），防并发写；④ 受控字段下拉不可自由填写；⑤ jsonl 进 git，批次粒度 commit 可整批回滚；⑥ pre-commit fast audit 兜底一切修改路径——绕过编辑页的手改在 commit 时被拦 |

## 8.2 实施启动指引

本方案定稿时**未做任何构建**：未建目录树、未写代码、未建 venv、未迁移旧资产、未创建 skills。

实施从 Phase 0 启动时的开工三件事（按序）：

1. 把[第二章](02_仲裁决议ADR.md) ADR-001~015 原样抄进 ARCHITECTURE.md 的 ADR 表（规格冻结，防死因 D1）
2. 按[第七章 7.1](07_项目管理与质保.md) 阶段表执行 Phase 0（门禁先于知识：doctor.py / kb_audit v0 / pre-commit hook 先行；kb_editor.py 编辑页在 Phase 1 随首件抽检交付）
3. Phase 1 首件铁律：1 篇素材走通十步 SOP 全绿之前，禁止任何批量萃取

落地验证已内建于各 Phase 的二元验收标准（doctor/audit 退出码、golden 命中率、E2E 双层判定），无需另行设计。
