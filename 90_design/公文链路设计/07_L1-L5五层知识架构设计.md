## 〇、设计要解决的三个问题

1. 41 条规则与五本书方法论的边界反复摇摆——因为一直按「主题」分层，主题天然重叠。
2. 生成的稿子行业味不足——术语库存在但只在校验末端起作用，没有进入生成过程。
3. 现有 `skills/公文写作体系` 已按篇/标题/段/词/句分了五个专项，但**没有对应的检索底座**。SKILL.md 里写的是方法，方法背后的例子、变体、反例无处可查。

三个问题同一个根因：**层的划分标准不统一**。本设计把唯一划分标准定为**可判定性**（能否由机器或有限规则判断对错），其余维度（粒度、动作、文种、场景）一律降级为标签。

## 一、分层：按可判定性，不按主题

| 层 | 名称 | 内容 | 载体 | 判据 | 进检索库 |
|---|---|---|---|---|---|
| **L0** | 公理 | 5-7 条跨文种底层判断（公文的本质、读者、效率约束） | **QA 检索库** | 不可判定但可陈述 | **是**（见 2.4） |
| **L1** | 规范 | 15 文种边界、GB/T 9704 版式、烟草行文层级、上下行语气 | 校验规则（code / agent_prompt） | 可判对错 | 否（进校验器） |
| **L2** | 骨架 | 各文种固定框架、层次序数、篇幅配比、板块必备项 | 结构化模板 | 可核对有无 | 否（进生成器） |
| **L3** | 技法 | 拟标题、谋篇、组段、炼句、改病句的可复用手法 | **QA 检索库** | 可举例示范 | **是** |
| **L4** | 素材 | 范文、段落、金句、术语、政策数据 | **QA 检索库**（带来源+时效） | 可直接取用 | **是** |
| **L5** | 心法 | 三重境界、二十年真经、写前判断、职业体悟 | SKILL 提示词 | 不可检索 | 否 |

**L1 与 L3 的切法**（41 条规则边界问题的解）：

```
「请示不得一文多事」             → 可判定   → L1
「请示的理由要写得让人无法拒绝」   → 不可判定 → L3
「向上行文不得使用下行文语气」     → 可判定   → L1（已在 rules_master FC-001）
「汇报的问题段要克制，点到为止」   → 不可判定 → L3
```

判定测试：**为该条目写一个自动检查函数，能否只靠字符串、结构或清单判出 true/false？** 能 → L1；需读懂语义并权衡 → L3。中间地带（`execution: agent_prompt`）归 L1 但标 `hard: soft`，由 LLM 判定器执行，不进检索。

**L3 与 L4 的切法**（检索被素材淹没的解）：

```
L3 回答「怎么写」——手法、步骤、判断标准、反例
L4 回答「写什么」——具体的字、句、段、篇、数据
```

检索时必须分标：问「开头怎么写」命中 L3，问「关于数字化转型的开头」命中 L4。混库的后果是 L4 体量（万级）压垮 L3（千级），语义检索永远返回素材。

**L5 不进库的理由**：碎片化后模型拿到的是「三重境界」四个字，组织逻辑全丢。这 105 篇由人读完写成 SKILL 正文，不切片。

## 二、L3 技法层的二级分类

### 2.1 主键是粒度，不是动作

L3 一级主键定为**写作对象的粒度**（篇→章→段→句→词），写作动作（立意→谋篇→拟题→组段→炼句→润色）降级为 `action` 标签。

L2 骨架层已承担流程职能，L3 再按动作切会与 L2 重叠，重新制造边界摇摆。粒度切分对检索友好（「标题怎么起」直接命中一个桶），且与已建成的 `skills/公文写作体系/专项_01~05` 一一对齐——不用重造分类，直接给现有 skill 配检索底座。

### 2.2 L3 六个桶

| 编号 | 桶名 | 粒度 | 管什么 | 对齐 skill | 典型 QA |
|---|---|---|---|---|---|
| **L3-A** | 立意定调 | 全篇 | 主旨句提炼、站位、WA 目标、四情四要素、为谁写 | 00_总纲 | 这篇汇报的主旨句怎么提 |
| **L3-B** | 谋篇结构 | 篇→章 | 结论先行、SCQA、MECE、并列/递进/总分、提纲三级、详略配比 | 专项_01 | 三个板块并列还是递进 |
| **L3-C** | 标题炼制 | 标题 | 大标题/小标题/层次标题、对仗、动宾结构、结论化、字数节奏 | 专项_02 | 话题句标题怎么改成结论句 |
| **L3-D** | 段落组织 | 段 | 意群、三元公式（观点+支撑+落点）、概括桥、过渡衔接、数据基准 | 专项_03 | 段落只有观点没有支撑怎么补 |
| **L3-E** | 语句锤炼 | 句 | 长短句、排比、句式变换、病句 23 种改法、口语转书面 | 专项_05 | 这句太平怎么提气 |
| **L3-F** | 遣词用字 | 词 | 分寸、称谓、程度副词、套话替换、禁忌、数字时间写法 | 专项_04 | 「高度重视」能不能用 |

跨桶的两类技法单列标签而非单列桶（避免七八个桶互相渗透）：

- `action: 修改`——改稿类技法（病句、删繁、统稿八看），分散在 B/D/E/F，用标签聚合
- `action: 诊断`——反模式识别（意思流窜、层次混乱、数据无基准），同上

### 2.3 桶内三级：原则 / 方法 / 技巧

同一桶内按**抽象度**分三级，字段 `depth`：

| depth | 定义 | 数量级 | 示例（L3-C 标题桶） | 可用性 |
|---|---|---|---|---|
| `principle` 原则 | 为什么这样做，可推出多个方法，跨文种成立 | 每桶 3-8 条 | 标题是结论不是话题——读者只看标题也要拿到判断 | 领会 |
| `method` 方法 | 可复述的步骤或框架，有明确适用条件 | 每桶 10-30 条 | 动宾结构提炼法：从段落抽核心动词+核心宾语，再加程度限定 | 可套用 |
| `technique` 技巧 | 单点招式，可直接照做 | 每桶 30-100 条 | 小标题控制在 9-13 字，三个小标题字数差不超过 2 | 可直用 |

**三级必须相互挂钩**：每条 `method` 必填 `derives_from`（指向本桶某条 principle），每条 `technique` 必填 `implements`（指向某条 method）。孤儿条目在质检时拦截——这是防止 L3 退化成一堆零散 tips 的唯一机械手段。

### 2.4 原则的位置：修正 v0 的设计错误

v0 把「底层逻辑」5-7 条塞进 L5 心法 SKILL 的开篇，这是错的。三个理由：

**一，违反本设计自己的划分标准。** 五层按可判定性分，L5 的定义是「不可检索」——因为心法是漫谈体，碎片化后丢失组织逻辑。但底层逻辑不是漫谈，它是**可陈述、可引用、可被 principle 指向的命题**（「公文是权力的书面运行」是一句完整判断，不是一篇体悟）。把它按载体形态（写在 SKILL 里）而不是按可判定性归层，标准就破了一次；标准破一次，边界问题就会从这个口子复发。

**二，它是 L3 挂钩链的根，不能悬在库外。** 设计强制 `technique → implements → method → derives_from → principle`。principle 再往上指向底层逻辑，但底层逻辑在 L5 SKILL 正文里，是一段自然语言，**没有 id 可指**。链条断在最上面一环，`principle` 层就变成了一批没有共同根的孤儿——正是三级挂钩要防的那个退化。

**三，检索时拿不到「为什么」。** agent 问「为什么汇报的问题段要克制」，答案在底层逻辑（公文是权力的书面运行，问题段过重等于替领导下判断）。这条在 L5 就检索不到，agent 只能拿到 L3 的操作层答案，解释不了取舍。

**修正：新增 L0 公理层，进检索库。**

| 层 | 名称 | 条数 | 判据 | 载体 | 进检索 |
|---|---|---|---|---|---|
| **L0** | **公理** | **5-7 条** | **不可判定但可陈述，跨全部文种与粒度** | **QA 检索库（与 L3 同 collection）** | **是** |
| L3 | 技法 | 千级 | 可举例示范 | QA 检索库 | 是 |
| L5 | 心法 | — | 不可陈述为命题，只能整篇领会 | SKILL 正文 | 否 |

L0 与 L5 的界线：**能不能压成一句可独立成立的判断句？** 能 → L0（「公文的读者只有一个，就是拍板的人」）；不能，必须读完整篇才有感觉 → L5（「叙事·辅政·鼎新的三重境界」）。

L0 条目结构：

```yaml
- id: L0-003
  layer: L0
  depth: axiom
  question: 为什么公文要结论先行？
  answer: |
    公文是权力的书面运行，读者是拍板的人，时间是最稀缺资源。
    结论先行不是行文技巧，是权力场景下的信息效率约束……
  governs: [L3-B, L3-C, L3-D]     # 管辖哪些桶
  derived_principles: [L3-B-P-001, L3-C-P-002]   # 反向索引，质检用
  tobacco_fit: 通用
```

对应改动：

- L3 的 `principle` 层字段 `derives_from` 由「选填」改为**必填，指向某条 L0**。至此挂钩链完整：`technique → method → principle → axiom`，全链在库内，全链可检索，孤儿在任一环都能被机械拦截。
- L5 只留真正不可命题化的部分（105 篇「其余」里的职业体悟、境界论）。预估 L0 抽走之后，L5 的体量会比 v0 估计小一半——这是好事，L5 越薄越可信。
- 检索侧：`pw_methods` collection 增加 `layer=L0` 的少量条目。因只有 5-7 条，不会稀释 L3 检索；且 agent 问「为什么」类问题时优先命中。

**L0 的抽取来源**：五本书的总论章 + 105 篇「其余」里可命题化的判断句。这是**唯一一处「其余」105 篇要被读进库的地方**——只抽命题，不抽漫谈。

## 三、QA 知识库条目 Schema

### 3.1 为什么用 QA 形态

L3/L4 都以**问答对**入库，不以原文段落入库：

- 检索侧：query 天然是问句，问-问匹配比问-答匹配语义距离短，召回质量高一截。
- 生成侧：answer 已是可直接粘进上下文的成品表述，不需要二次总结。
- 质检侧：一条 QA 能否写成「问题清晰 + 答案自足」，本身就是抽取质量的过滤器——讲评型文章里抽不出自足答案的点评，说明那是 L5 心法，不该进库。

与项目已有的 `book2qa`（5 列 CSV）形态一致，可复用其抽取流程，字段扩到下面这套。

### 3.2 L3 条目字段

```yaml
- id: L3-C-M-014                  # 层-桶-depth首字母-序号，全局唯一
  layer: L3
  bucket: L3-C
  depth: method                   # principle | method | technique
  question: 话题句标题怎么改成结论句？
  answer: |                       # 自足，不依赖上下文，200-600 字
    ...（手法描述 + 判断标准）
  worked_example:                 # 必填；technique 层必须给前后对比
    before: 关于加强卷烟物流管理的几点思考
    after: 卷烟物流三项指标全面达标的关键在于前置调度
  anti_example: |                 # 选填，反例 + 为什么错
    ...
  derives_from: [L3-C-P-002]      # method 必填
  implements: []                  # technique 必填
  # ── 标签维度（用于过滤，不参与主键） ──
  action: [拟题, 修改]             # 立意|谋篇|拟题|组段|炼句|润色|修改|诊断
  doc_type: [汇报, 讲话, 总结]      # 空 = 跨文种通用
  direction: 上行                  # 上行|下行|平行|通用
  org_level: [省级公司, 地市局]     # 烟草行文层级，空 = 通用
  occasion: [正式会议, 内部通报]
  usability: 可直用                # 可直用 | 可改写 | 仅供领会
  tobacco_fit: 需适配              # 通用 | 需适配 | 烟草专用（见第四节）
  # ── 溯源 ──
  source: {corpus: 技巧汇编, file: 汇编三, article: 标题制作的11种方法, locator: §3}
  confidence: 0.9                 # 跨源交叉验证得分，见 3.4
  cross_refs: [L1-FC-001, L2-汇报-骨架]
```

### 3.3 L4 条目字段

与 L3 同构，差异字段：

```yaml
  bucket: L4-范文 | L4-段落 | L4-金句 | L4-术语 | L4-数据
  content_scope: 段落             # 篇|章|段|句|词|数据点
  valid_until: "2030-12-31"       # 时效，政策数据必填
  policy_basis: 十五五规划纲要      # 政策类素材必填
  reusability: 可改写直用          # 沿用段落库 v2 已有口径
```

L4 的 `question` 写成**取用式问句**（「有没有讲数字化转型成效的段落」）而非方法式问句，这是 L3/L4 不互相污染的第二道保险（第一道是 `layer` 标量过滤）。

### 3.4 confidence：跨源交叉验证

四源（技巧汇编 / 书籍 / AI 手册 / 自有交付物）各有生态位，但**层内确实重复**（四本书都讲「标题要实」）。合并时不去重，而是合成一条并累加证据：

```
confidence = 0.5 + 0.1 × (独立来源数 − 1) + 0.2 × (有自有交付物佐证)
上限 1.0；单源孤证 = 0.5，四源共识 + 自有佐证 = 1.0
```

检索排序用 `score × (0.7 + 0.3 × confidence)`，让共识手法优先于孤证。冲突条目（两源给相反建议）不合并，两条都入库，各标 `conflict_with` 并在 answer 里写明适用边界——沿用 `rules_master` 已有的 `context_note` 做法。

## 四、烟草行业用词的注入机制（三处，不止校验端）

现状的毛病是术语库只在**末端校验**起作用：生成时模型按通用公文语感写，写完再挑错，代价高且改不干净。设计三处注入。

### 4.1 入口：每条 L3/L4 打 `tobacco_fit`

| 取值 | 含义 | 处理 |
|---|---|---|
| `通用` | 手法与行业无关（如「标题动宾结构」） | 直接用 |
| `需适配` | 手法通用但例子是党政口径（如「三个聚焦」排比） | answer 里必须**额外给一条烟草版改写** |
| `烟草专用` | 只在烟草语境成立（如「专卖专营体制下的行文避讳」） | 标 `org_level`，非烟草场景不召回 |

技巧汇编 305 篇全是党政通用口径，抽取时默认 `需适配`，意味着**抽取阶段就要产出烟草版 worked_example**，而不是留到生成时临时换词。这是本设计增量最大的一处工作量，也是「写出来的东西行业看得懂」的真正成本所在。

### 4.2 中段：术语强制进入生成上下文

生成任一段落前，按段落主题从 `03_dictionary/tobacco_terms/` 召回 3-8 条术语，以**候选词表**形式进 prompt（而非事后替换）。召回键用术语的 `domain` 字段（技术研发/原料保障/生产制造/市场营销/物流管理）+ `context` 字段做语义匹配。

术语条目本身以 L4-术语 形式入 QA 库，question 写成「XX 在烟草语境里怎么表述」，answer 直接给 `definition + example`。

### 4.3 出口：校验不变

L1 校验器继续跑 `official_terms_v2.yaml` 的禁用词（PW）、搭配（MM）、套话替换（CP），但此时只该剩零星漏网，而不是像现在这样承担全部行业化职责。

**可观测指标**：出口校验的术语命中率应随 4.1/4.2 落地而下降。若始终居高不下，说明 `需适配` 条目的烟草版改写没做到位，回头补 L3，而不是加严校验。

## 五、检索契约（与现有 rag/ 的关系）

现有 `rag/build_index.py` 已有 6 个 collection，`taxonomy.py` 已有六大类打标，`eval.py` 已有评测集。本设计不推翻，做映射与增补。

| 现有 collection | 归入 | 处理 |
|---|---|---|
| `pw_templates` | L2 骨架 | 退出检索主路径，改由生成器直读；保留索引供人查 |
| `pw_paragraphs` | L4-段落 | 加 `layer/usability/tobacco_fit` 字段重建 |
| `pw_golden` | L4-金句 | 同上 |
| `pw_patterns` | 拆分：标题结构 → **L3-C**，固定句式 → L4-金句 | **本次唯一需要拆库的地方** |
| `pw_terms` | L4-术语 | 加 `domain` 召回键 |
| `pw_articles` | 拆分：技巧型 → **L3 六桶**，范例型 → L4-范文，讲评型 → 段落级切分后进 L3 | 主要增量 |
| **新增 `pw_methods`** | **L3 全部** | 新建，六桶共用一个 collection，靠 `bucket` 标量过滤 |

`taxonomy.py` 的六大类保留为 `cat1/cat2` 辅助标签（BM25 侧有用），但**主过滤键改为 `layer` + `bucket`**。六大类与五层是两套正交口径，不要试图统一——六大类是主题，五层是可判定性。

检索调用约定：

```
问「怎么写」类  → collection=pw_methods, filter{bucket, depth?, doc_type?}
问「写什么」类  → collection=pw_{paragraphs|golden|terms|articles}, filter{layer=L4, ...}
agent 生成流程  → 先取 L2 骨架（直读）→ 按当前粒度取 L3（检索）→ 按当前主题取 L4（检索）
```

## 六、切分规则

| 源 | 篇数 | 切法 | 产出层 |
|---|---|---|---|
| 技巧汇编·技巧型 | 105 | 按标题直抽，一个小标题一条 QA | L3（六桶按标题关键词路由） |
| 技巧汇编·讲评型 | 106 | **段落级切分**——技巧藏在对具体句子的点评里，抽「点评 + 被评原句」成 QA，原句即 worked_example | L3（多为 C/D/E） |
| 技巧汇编·其余 | 105 | **只抽可命题化的判断句**，其余不切 | **L0** + L5（人读后写 SKILL） |
| 五本书 | 8 文件 | 总论章抽公理；其余按已有 `02_rules/_方法论提取/*章节地图.md` 抽 | **L0** + L3 principle + L1 |
| AI 写材料手册 | 12 章 | 只取「操作指南」部分，弃 AI 工具相关 | L3 method |
| 提示词模板库 | 6 章 | **不入库**——879 个【】占位符与其余三源零交集，是填槽模板 | skill 素材 |
| 六目录交付物 | 2,973 篇 | 见第八节：去重去空→评分→切段→脱敏→四闸 | L4 为主，不强抽 L3 |
| 自有交付物 | 82 篇 | 按 5 类切段，主要作 confidence 佐证与烟草版 worked_example 来源 | L4 + L3 佐证 |

## 七、构建顺序

```
⓪ L0 公理（5-7 条）
   从五本书总论章 + 105 篇「其余」抽可命题化的判断句。
   量极小但必须最先做——L3 的挂钩链以它为根，它不定，
   principle 层就没有共同根，抽出来要返工。
   半天到一天的工作量，不占工期。

① L1 + L2（规范与骨架）
   有唯一正确答案，可立即校验，见效最快。
   主要工作是把 rules_master 345 条按可判定性重过一遍：
   可判定的留 L1，不可判定的移出到 L3 待抽取池。
   预估 345 条里约 40% 会被移走。

② L3 骨干（六桶 × principle 层）
   先只抽 principle（每桶 3-8 条，全库 30-50 条），从五本书抽。
   每条必须挂到 ⓪ 的某条 L0 公理，孤儿拦截。
   这一步做完 L3 的挂钩骨架就立住了，后面 method/technique 有地方挂。

③ L3 主体（method + technique）
   105 篇技巧型 → 106 篇讲评型。
   每条必须挂上级，孤儿拦截。
   同步产出 tobacco_fit 标注与需适配条目的烟草版改写。

④ L4 素材
   量最大但最依赖前三层的标签体系，最后做。
   现有 pw_paragraphs/golden/terms 加字段重建即可，不重新抽。

⑤ L5 心法 SKILL
   人读 105 篇「其余」+ 书籍心法章，写成 SKILL 正文，不进库。
   可与 ①②③ 并行，不占检索链路工期。
```

① 和 ② 之间有硬闸：**L1 不瘦身完就不要开始抽 L3**，否则同一条知识在两层各存一份，边界问题原样复发。

## 八、全量语料入库（3,055 份 / 3,349 万字）

### 8.1 实测家底

对 `00_raw_materials` 六个交付物目录 + 个人历史交付物做全量扫描：

| 指标 | 实测值 |
|---|---|
| 文件总数 | 3,055（项目全域 .md 3,816，其余是已加工产物与文档） |
| 正文总字数 | 3,349 万字 |
| 有 to-md frontmatter | 97%（带 `source_path`／`modification_date`，可溯源） |
| 正文 < 200 字（空壳/残件） | 49 份（1.6%） |
| 乱码文件 | 0（转换质量干净） |
| 前 3000 字完全重复 | 62 份冗余（2.0%），唯一文档 2,993 |
| 正文长度 | 中位 5,320 字，P75 9,877，P95 35,803 |
| **含具体单位名** | **83%** |
| **含经营数据** | **63%** |

两个直接结论：

- **不是 6,000 个文件，是 3,055 份原始语料**，加工产物与文档凑到 3,816。规划工作量按 3,055 算。
- 语料**干净但高度涉密**。83% 带客户单位名、63% 带经营数据，这决定了全量入库的主要成本不是抽取，是脱敏。

### 8.2 全量入库不等于全量进 L3

3,349 万字里，**方法论知识的含量极低**。这些是成品交付物，不是教材——它们示范「写成什么样」，不解释「为什么这样写」。硬抽 L3 会得到大量「本方案分四个部分」这类无信息条目。

按层分流：

| 语料 | 份数 | 入哪层 | 处理方式 |
|---|---|---|---|
| 六目录交付物 | 2,973 | **L4 为主** | 切段入 L4-范文/L4-段落，**不强抽 L3** |
| 同上 | — | L3 佐证 | 仅作 `confidence` 加权与烟草版 worked_example 来源 |
| 个人历史交付物 | 82 | L4 + L3 佐证 | 同上，但可信度最高，优先做烟草版例子 |
| 空壳/残件 | 49 | 丢弃 | 正文 < 200 字 |
| 重复件 | 62 | 去重保一 | 前 3000 字 md5 相同 |

**L3 的知识来源仍然只有四处**：五本书、105 篇技巧型、106 篇讲评型、AI 手册操作指南部分。3,055 份交付物是 **L4 的料**，这一点不因为体量大而改变。体量大是 L4 的优势（覆盖全、行业真实），不是 L3 的来源。

### 8.3 L4 的切分与准入

3,349 万字直接切段会产出百万级 chunk，检索会被稀释到不可用。三道闸：

**闸一 · 文档级筛选**。按现有 `04_corpus/优质范文库(P3).yaml` 的评分机制扩展到全量，只有评分达标的进 L4-范文全文；未达标的仅进 L4-段落（抽其中可复用段）。预估进全文库 300-500 份，其余只贡献段落。

**闸二 · 段落级准入**。一个段落进 L4 必须满足：

```
有观点句（不是纯流水账）
且 有支撑（数据／事例／政策依据）
且 长度 120-600 字
且 不含未脱敏的单位名与经营数据
```

四条全过才入库。按段落库 v2 的实测经验，通过率约 5-8%，3,349 万字预计沉淀 2-4 万条 L4 段落——这是合理量级，不是百万级。

**闸三 · 脱敏**。83%/63% 的命中率意味着脱敏必须**机械化前置**，不能靠人工抽查：

| 类型 | 处理 | 保留什么 |
|---|---|---|
| 单位名 | 替换为占位符 `〔某省中烟〕`／`〔某市局〕` | 保留行政层级（省级/地市/县级），这是行文层级判断的依据 |
| 经营数据 | 替换为 `〔数据〕` 并保留量纲与对比关系 | 「同比增长〔数据〕%」比整句删掉有用 |
| 人名职务 | 删人名，保留职务 | 「〔局长〕指出」 |
| 时间 | 保留年份，删具体日期 | 用于 `valid_until` 判定 |

脱敏后的段落若因去数据而失去说服力（如整段只剩「取得显著成效」），按闸二第二条直接淘汰——**脱敏不是为了保住条目，是过滤器的一部分**。

### 8.4 工作量与顺序

L4 全量是纯管线活，可完全自动化：`扫描 → 去重去空 → 文档评分 → 切段 → 脱敏 → 四闸准入 → 打标入库`。3,055 份的瓶颈在段落级 LLM 打标（`usability`／`tobacco_fit`／主题标签），按 2-4 万条估。

但顺序不变：**L4 仍排在 ④**。理由在第七节已说过——L4 的标签体系依赖 L1/L2/L3 先立住。提前做 L4，标签口径会跟着后面的 L3 反复变，2-4 万条要重刷。

唯一可提前的是**不依赖标签的部分**：去重、去空、文档评分、脱敏。这四步产出一份干净的「待切语料池」，与 ①②③ 并行做，不浪费工期。

## 九、未决的两处

1. **讲评型 106 篇的切分自动化程度**。段落级 LLM 切分成本不低（106 篇约 35 万字）。可选：先人工标 10 篇建 few-shot 再批量；或先跳过讲评型、只做技巧型，看 L3 够不够用。倾向后者——105 篇技巧型抽完可能已有 500+ 条 method/technique，边际收益需要实测。

2. **`需适配` 条目的烟草版改写由谁产出**。全部由 LLM 生成则质量不可控（生成的烟草例子可能行业上就不成立）；全部人工则工作量不现实。倾向：LLM 出草稿 + 用自有 82 篇交付物做检索式佐证，凡找不到佐证的烟草版例子降级为 `tobacco_fit: 通用` 并不给烟草例子，宁缺毋滥。
