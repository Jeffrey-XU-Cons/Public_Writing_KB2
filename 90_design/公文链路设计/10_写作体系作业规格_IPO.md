## 〇、读法

**28 个节点**：A 层 1 个 + 五个层总（W1总–W5总）+ 22 个板块。

每个节点统一四栏：

| 栏 | 含义 |
|---|---|
| **输入** | 从哪来（上游节点产物／用户／知识库检索），缺了就不能开工 |
| **过程** | 做什么动作，用什么方法，检索哪个库 |
| **输出** | 交付什么，落盘还是留会话 |
| **闸** | 不满足就不许进下一节点 |

**层总节点**（W1总等）不做具体动作，只做三件事：**汇总本层输出、执行层闸、决定是否放行**。

标注约定：`◆` 确认点（需 Jeffrey 点头）｜`▲` 硬闸（机器判定）｜`△` 软闸（LLM 判定）

## A 层 · 公理与假设

**性质**：不是流程节点，是**贯穿全程的判据**。任何节点出现取舍争议，回到 A 层裁决。

| 栏 | 内容 |
|---|---|
| **输入** | 无（体系常量） |
| **过程** | 不主动执行。被下游节点在两种时机调用：① 方法冲突时裁决 ② 用户问"为什么要这样"时解释 |
| **输出** | 裁决依据（A1–A6 编号 + 一句话理由） |
| **闸** | 无 |

**六条公理与调用位置**：

| 公理 | 一句话 | 被哪些节点调用 |
|---|---|---|
| A1 | 公文是权力的书面运行 | W1-3、W4-3、W5-3 |
| A2 | 读者是拍板的人，时间最稀缺 | W2-1、W2-2、W4-1、W4-4 |
| A3 | 一次表达只支持一个核心结论 | W1-2、W2-1、W2-3、W5-3 |
| A4 | 说服力来自证据链而非形容词 | W3-2、W4-3 |
| A5 | 同层必须穷尽且互斥 | W2-4、W5-3 |
| A6 | 改框架成本是改终稿的 1/10 | W2-5、W5 退回规则 |

**检索**：`depth=axiom`，用户问"为什么"类问题时优先命中。

## W1 思维准备

### W1-1 研情

| 栏 | 内容 |
|---|---|
| **输入** | 用户需求原话；可选素材（往年稿/批示/数据/调研记录）；任务背景 |
| **过程** | ① 四情盘点：上情（上级政策要求）／内情（本单位实际）／下情（基层执行）／外情（同类单位做法）<br>② 四要素核查：事（沿革现状问题趋势）／人（领导意图受众关切）／体（文种体例）／景（宏观背景场景）<br>③ 建"两夹一锦"：素材夹／电子夹／词句集锦<br>④ **检索补缺**：上情查政策库，外情查 articles 库<br>⑤ **标注缺口**：内情/下情拿不到的，明确列出<br>⑥ **素材时点核查**（2026-09-28 P4 补）：列出每份素材的日期，比对最新素材截止时点与材料使用时点（开会/报送日）；两者之间若有会改变核心数据的节点（评审、修订、发布、年度结算），列为**时点缺口** |
| **输出** | 四情四要素盘点表（会话内）；**素材缺口清单**（明确写"这两块必须你提供"）；**素材时点表** |
| **闸** | △ 内情/下情为空时，**不许用通用表述糊过去**，必须显式告知用户<br>▲ **时点缺口是阻断项**：主旨句数据锚或全文核心数据落在时点缺口里，确认点 1 必须向用户取得最新数据，不得以删节、[待补] 替代后继续 |

**易错**：跳过归堆直接写。A4 决定了没有素材底座就没有证据链。

### W1-2 立意

| 栏 | 内容 |
|---|---|
| **输入** | W1-1 的四情四要素盘点 |
| **过程** | ① 立意三字经取交集：时（时代背景）∩ 事（工作事项）∩ 势（发展趋势）<br>② 产出**一句话主旨**<br>③ 好立意五感自检：文体感／结构感／对象感／场景感／价值感<br>④ **判断句改写**——话题句一律改成带判断的句子<br>⑤ 检索 `c6 + depth=principle` 取立意方法 |
| **输出** | **主旨句**（一句判断句，落 outline.md 首行） |
| **闸** | ▲ **主旨句必须是判断句**——这是全链条第一硬闸 |

```
✗ 关于加强卷烟物流管理的思考          ← 话题句，后面怎么写都行
✓ 卷烟物流三项指标达标的关键在于前置调度  ← 判断句，全文都得为它服务
```

**为什么是硬闸**（依据 A3）：主旨不是判断句，W2-4 的 MECE 无从谈起（不知道对什么做穷尽分解），W5-3 的论点流窜核销不了（没有主线可对照）。**这道闸一松，后面四层全空转。**

### W1-3 意图

| 栏 | 内容 |
|---|---|
| **输入** | W1-2 主旨句；W1-1 的"人"要素 |
| **过程** | ① **WA 目标法**：写清 W（说服对象是谁）+ A（希望对方采取什么行动）<br>② 领导意图三层逻辑排序：领导意图逻辑 > 工作内在逻辑 > 形式逻辑<br>③ 把领导反复说的词句摘出来，备入 W2-5 的小标题/帽段（一稿过诀窍）<br>④ **定汇报立场**（2026-09-28 P4 补）：本文是**送审/报成果**（请对方认可、通过、批准自己的成果）还是**报问题/求决策**（请对方就问题拍板、给支持）。送审立场下问题段要克制：问题转写为“下步完善方向”或“提请评审确认事项”，不得自曝否定成果成立的判断 |
| **输出** | WA 声明（一行）；**汇报立场**（一行）；领导高频词句表 |
| **闸** | △ W 或 A 写不具体（"给领导看""推进工作"）判为未完成<br>▲ 立场未定不得出主旨句备选；主旨备选必须与立场一致（送审立场不得以“问题/不足”为主旨） |

**依据 A1**：公文不是自我表达，是说服特定对象采取特定行动。W/A 不明确，全文方向必跑偏。

### W1-4 定种

| 栏 | 内容 |
|---|---|
| **输入** | W1-1 的"体"要素；W1-3 的 WA |
| **过程** | ① 15 文种边界判定，**须给依据**（"要钱要政策→请示不是报告"）<br>② 定行文方向：上行／下行／平行<br>③ 定场合与字数区间<br>④ 检索 `c1 骨`，取该文种要件清单 |
| **输出** | 文种判定（带依据一句话）；行文方向；字数区间 |
| **闸** | ▲ 文种要件清单必须取到——它决定 W2 骨架来源与 W5 激活哪些检查 |

### W1总

| 栏 | 内容 |
|---|---|
| **输入** | W1-1～W1-4 全部产出 |
| **过程** | 汇总成**意图卡**（≤12 行表格）：文种／场景／受众／行文方向／字数／基调／主旨句／WA／**汇报立场**／素材缺口（含**素材时点**）。信息不足最多提 3 问，**呈报做成选择题**（如两版主旨方向二选一） |
| **输出** | 意图卡 → 05 章 S1 |
| **闸** | ◆ **确认点 1**。短文种（请示类）可与确认点 2 合并。存在时点缺口（W1-1 ▲）时，确认点 1 不得放行 |

**呈报做成选择题的理由**：点头不必过脑，做选择必须过脑。

## W2 结构设计

### W2-1 结论先行

| 栏 | 内容 |
|---|---|
| **输入** | W1 意图卡（主旨句 + WA） |
| **过程** | ① 把主旨句展开成**一句话版本的核心结论**<br>② 三句话测试：开头三句单独抄出来，读者能否知道你要说什么<br>③ 不通过则回 W1-2 重提主旨 |
| **输出** | 核心结论句（全文主线） |
| **闸** | ▲ 三句话测试不过，不许进 W2-2 |

**依据 A2/A3**：读者是拍板的人，时间最稀缺，一次表达只支持一个结论。

### W2-2 入口设计

| 栏 | 内容 |
|---|---|
| **输入** | W2-1 核心结论；W1-4 文种 |
| **过程** | ① 选 SCQA 变体：<br>　标准式 S→C→Q→A：一般汇报、工作报告<br>　开门见山式 A→Q→S→C：领导很忙、结论优先<br>　突出忧虑式 C→S→Q→A：问题类、整改类<br>　突出信心式 Q→S→C→A：鼓动型讲话稿<br>② 开头四戒自检：背景过多／套话虚话／引据过多／叙述过细<br>③ 检索 `c3 开头写法` |
| **输出** | 开头结构方案（选定变体 + 四段要点） |
| **闸** | △ 四戒任一命中须改 |

### W2-3 纵向逻辑

| 栏 | 内容 |
|---|---|
| **输入** | W2-1 核心结论 |
| **过程** | ① 选纵向结构：演绎（大前提→小前提→结论）用于论证分析类；归纳（多并列论据→共同结论）用于罗列汇报类；公文常用混合（骨架演绎，其下归纳）<br>② **so what 向上**：底层信息往上概括，问"这说明了什么"<br>③ **why so 向下**：上层结论往下追问"为什么／凭什么"<br>④ 两遍都走通才算合格 |
| **输出** | 论点树（带层级） |
| **闸** | △ so what / why so 任一走不通，该分支须重建 |

### W2-4 横向逻辑

| 栏 | 内容 |
|---|---|
| **输入** | W2-3 论点树 |
| **过程** | ① **MECE 检验**：查重叠（两个小标题说的是同一件事换个角度）／查遗漏（重要情况没有位置）<br>② **互换测试**：两个同级标题互换位置，若读起来无差别，说明分类维度不成立<br>③ 定横向排序，**同层只能用一种**：时间顺序（总结/历程类）／结构顺序（系统说明类）／重要顺序（方案/汇报类）<br>④ 套三块式框架：为什么-是什么-怎么办／问题-原因-对策／成绩-问题-打算 |
| **输出** | 定稿论点树 + 各层排序方式 |
| **闸** | ▲ **MECE + 互换测试不过，不许展开正文**（W2 层闸的核心） |

**依据 A5**：同层不穷尽，读者不知道你漏了什么；不互斥，读者不知道该看哪条。

### W2-5 提纲物化

| 栏 | 内容 |
|---|---|
| **输入** | W2-4 定稿论点树；W1-3 领导高频词句表 |
| **过程** | ① 定构建方向（**决定 F1/F2 分岔**）：<br>　题目明确思路成熟 → **自上而下**（结论→设想疑问→逐层回答→递归）<br>　素材一堆结论未明 → **自下而上**（先摞→再归→再改→向上概括）<br>② 三级细化：粗纲（一级标题）→细纲（到每段段旨）→腹稿<br>③ **一稿过诀窍**：把领导反复说的词句提炼进小标题／帽段／导语<br>④ 逐节登记：标题／核心判断句／素材编号／字数<br>⑤ 建**论点地图**：每个论点登记唯一归属位置 |
| **输出** | **`outline.md`（落盘）**：主旨句 + 三级骨架 + 论点地图 + 缺口标注 |
| **闸** | ▲ 提纲不可跳过，时间再紧也要先列粗纲 |

### W2总

| 栏 | 内容 |
|---|---|
| **输入** | W2-1～W2-5 |
| **过程** | 汇总 outline.md；标注 A 级素材缺口；核对板块比例是否在文种区间 |
| **输出** | outline.md → 05 章 S3 |
| **闸** | ◆ **确认点 2 · 确认即冻结**。后续偏离须书面说明。**讲话稿（及同场另有报告、方案的稿子）加呈人工两问**（W2-6，2026-10-06 P4 第 7 轮补）：Q1 本稿与同场其他材料怎么分工，Q2 问题部分放多重；起草方只给判断、选项、推荐，由用户本人答复后才冻结，终验 `--final` 查答复 |

**依据 A6**：改大纲成本是改终稿的 1/10。**这是全流程性价比最高的一次确认。**

## W3 内容填充

### W3-1 意群

| 栏 | 内容 |
|---|---|
| **输入** | outline.md 的单节段旨 |
| **过程** | ① 以**意群**（观点+支撑素材的最小有机组合）为单位组织，不以自然段为单位<br>② 意群构建四步：提炼观点→选配素材→有机组合→检验覆盖度<br>③ 完整性检验：这段观点是什么？用了什么支撑？逻辑成立吗？ |
| **输出** | 意群草稿（逐块，防长文漂移） |
| **闸** | △ 意群缺观点句或缺支撑，判为不完整 |

**意群 ≠ 段落**：一个意群可跨多个自然段，一个自然段也可含多个意群。

### W3-2 论据三元素

| 栏 | 内容 |
|---|---|
| **输入** | W3-1 意群草稿 |
| **过程** | ① **三元公式**：观点 + **概括叙述** + 典型事例——概括叙述是观点到事例之间的桥<br>② 事实论据四要：真实／准确／典型／切题；**必须有对比基准**（同比／历史最好／超额完成目标）<br>③ 理论论据三注意：融会贯通／得体适用／适度引用<br>④ 缺数据处写 `[待补:XX]` 占位，**不许编**<br>⑤ 检索 paragraphs 同 func 范例 |
| **输出** | 补齐支撑的意群 |
| **闸** | ▲ 段落缺概括句 或 数据无对比基准，须补齐（W3 层闸） |

**典型错误**（两元断层）：「某工作成效显著，张三做了什么，李四做了什么」——观点与事例之间缺概括层。

**依据 A4**：说服力来自证据链，不是形容词。

### W3-3 素材组织

| 栏 | 内容 |
|---|---|
| **输入** | 用户提供的原始素材（F1 场景）；或检索所得（F2 场景） |
| **过程** | ① **先摞**——全部素材摞在一起，**禁止边看边写**<br>② **再归**——按"为什么／是什么／怎么办"三框分类，合并同类项<br>③ **再改**——通读后四审：审缺项／审意图体现／审结构合理性／审亮点新意<br>④ 归堆结果反过来可调 W2 框架比例（**不算返工**）<br>⑤ **弃用按内容块登记**（2026-09-28 P4 补）：弃用的单位是内容块（一节、一张表、一段论证），不是整份文件；每块写明弃用理由，登入 outline.md“弃用清单”，在确认点 2 呈报 |
| **输出** | 归堆素材包（F7 场景可单独交付）；**弃用清单** |
| **闸** | △ 未归堆直接写，判为违规<br>▲ **整份弃用判为违规**；能支撑 W1-4 文种要件的内容块不得弃用（如送审汇报的“为什么建／怎么设计／怎么用”） |

**这是 F1 与 F2 的分岔点**：F1 由此向上概括出主旨（自下而上）；F2 此步为检索补素材（自上而下）。

### W3-4 详略配比

| 栏 | 内容 |
|---|---|
| **输入** | 各意群草稿；W1-4 文种 |
| **过程** | ① 按文种查板块比例区间：汇报 成效 40–55%／问题 10–20%／下步 25–40%；调研 问题-原因-对策逐行映射；总结 总起-成效-经验-不足-打算<br>② 超区间的压缩，不足的补<br>③ 检索 `c1 + templates` |
| **输出** | 配比达标的初稿 |
| **闸** | ▲ 板块比例超出文种区间须调整 |

### W3总

| 栏 | 内容 |
|---|---|
| **输入** | W3-1～W3-4 |
| **过程** | 拼合各板块；检查每个 A 级素材**被使用或显式弃用**；`[待补]` 项汇总 |
| **输出** | 初稿（会话内）→ 05 章 S4 |
| **闸** | ▲ A 级素材既未用也未显式弃用，判为遗漏 |

## W4 语言打磨

### W4-1 标题

| 栏 | 内容 |
|---|---|
| **输入** | 初稿各级标题 |
| **过程** | ① **标题四戒**自检<br>② **结论化改写**：话题句 → 判断句<br>③ 套用公式：成效类「具体业务+成果词」／措施类「着力·全力·大力」串联或「聚焦·围绕·瞄准」状语／动员类「性+感+需要」交叉<br>④ 字数节奏：同级标题字数差控制<br>⑤ 检索 `c2 标题规范` + title-guide |
| **输出** | 改写后标题；**F4 场景一次出 3 个候选**（选择题式呈报） |
| **闸** | △ 话题句标题须改 |

### W4-2 开头结尾

| 栏 | 内容 |
|---|---|
| **输入** | 初稿首尾段 |

## 五、测试计划

### 5.0 现状与总原则

**现有测试资产**：`06_testing/`（test_cases.json 18 用例 + test_e2e_workflow.py + conftest.py）、`benchmarks/rag_benchmark.py`、`rag/eval.py`。

**必须先认清**：现有 E2E 框架是 **Dify 时代的产物**——走 HTTP 调 `DIFY_API_URL`、测"六智能体工作流"，与当前 skill + 本地检索的架构已不对应，**框架作废**。但 18 个用例的**素材可用**（6 文种 × 3 例，带背景/要求/预期），迁移进本章 5.3 的场景用例池。

**四条总原则**：

| # | 原则 | 理由 |
|---|---|---|
| 1 | **闸必须可测**，测不了的闸不算闸 | 写在文档里的闸，模型跑起来会自动跳过（§四 4.1 已列） |
| 2 | **先测闸，再测质量** | 闸是二值判定，质量是连续量。闸都守不住，谈质量没意义 |
| 3 | **每级测试有独立失败模式** | 节点测试看不见层内协作，层测试看不见跨层回退，端到端看不见单点退化——三级缺一不可 |
| 4 | **用例真实，不用玩具** | 测试输入取自真实脱敏语料，不自造"某某公司要写个通知" |

**三级测试的分工**：

```
L0 节点测试   28 个节点各自的 I/P/O 与闸        → 单点正确性
L1 环节测试   5 个 W 层的层闸、层内协作、跨层回退 → 协作正确性
L2 整体测试   8 类场景端到端 + 20 条门禁 + 回归  → 交付正确性
```

### 5.2 L1 · 环节测试（5 个 W 层）

节点全绿不等于层能跑通。层测试的独立价值在三件事：

#### 5.2.1 层内串联

测本层各板块的产物能否正确流转。典型：

| 层 | 串联测试 | 失败模式 |
|---|---|---|
| W1 | 研情→立意→意图→定种→意图卡 | 四情有缺口但意图卡没标注 |
| W2 | 结论→入口→纵向→横向→提纲 | 论点树过了 MECE，但 outline 的论点地图漏登记 |
| W3 | 意群→三元素→素材组织→详略 | 意群补齐了支撑，但详略配比把它压没了 |
| W4 | 标题→首尾→字词→句子→文气 | 字词订正后句子层没复检，改出新的主语残缺 |
| W5 | 机检→语义→站位→终验 | 机检报告有项未被终验汇总 |

#### 5.2.2 层闸测试

每层的层闸独立测：

| 层闸 | 正例 | 反例 |
|---|---|---|
| W1总 ◆确认点1 | 意图卡 ≤12 行、呈报为选择题；含汇报立场与素材时点 | 一次提超过 3 个问题 → 拦截；核心数据落在时点缺口里仍放行 → 拦截；主旨备选与立场矛盾 → 拦截 |

| W3总 | A 级素材全部使用或按内容块显式弃用 | 有 A 级素材既未用也未弃 → 拦截；整份弃用 → 拦截；弃掉的内容块支撑文种要件 → 拦截 |

#### 5.2.3 跨层回退测试（**最重要，也最容易漏**）

09 章定的退回规则是「失分能靠改句子解决吗？不能就退 W2」。这条只有跨层测试能验：

| 用例 | 注入的缺陷 | 期望行为 |
|---|---|---|
| R-01 | 终稿论点在两个板块重复出现 | W5-3 检出 → **退 W2**，不是在 W4 删句子 |
| R-02 | 板块比例严重失衡（问题段占 50%） | W5-3 检出 → **退 W2** |
| R-03 | 政治表述顺序错 | W5-3 检出 → **退 W2** |
| R-04 | 某句有主语残缺 | W5-2 检出 → **W4 就地改**，不得退 W2 |
| R-05 | 术语用错 | W5-2 检出 → **W4 就地改** |

**R-01～R-03 退错（在 W4 修补）判为失败**，哪怕最终稿看起来还行——因为那是在症状上治病，下一篇会原样复发。

**R-04～R-05 退过头（退到 W2）同样判为失败**——小题大做会让流程走不完。

#### 5.3.2 门禁总验（20 条）

每条硬门禁至少 1 正 1 反，共 40 条断言。**红线 5 条另加"零容忍"测试**：注入违规后必须拦截，不得以任何理由放行。

按 09 章 §4.2 映射表，每条门禁的测试同时验证它守护的方法与公理——**门禁测试失败时，要能指出是哪层方法没到位**，而不只是报"第 7 条不过"。

**红线 5 条反例样例（2026-09-24 补，此前只有目标声明没有具体用例）**：

| 红线 | 反例（注入的违规） | 期望 |
|---|---|---|
| R1 政治表述顺序与固定套语零差错 | 地方阶段性目标表述排在中央重大决策部署之前（上下位阶顺序颠倒） | **拦截**，指出顺序错位，退回按标准顺序重排；不给出具体"正确顺序"文本，由人工按最新规范核对——这条的判据来源是公文写作惯例，不是本设计臆造 |
| R2 政策引用层级零倒置 | 先引《XX省实施办法》，后引其上位依据《中华人民共和国XXX法》/中央文件 | **拦截**，指出层级倒置，要求先引上位法规/中央文件、再引地方实施细则 |
| R3 零编造 | 正文出现"预计带动就业2.3万人"一类具体数字，且素材夹/电子夹里找不到来源，也未标 `[待补]` | **拦截**，要求要么补素材来源、要么改 `[待补:就业带动数]` 占位；`[待补]` 本身不得进终稿（另一条判据，二者不可互相替代） |

| R5 待人工裁决项全部经 Jeffrey 明示处理 | `review_report.md` 里某条标"[待人工裁决：内部数据能否外发]"，状态仍是"待裁决"，却已进入确认点 3 终稿呈报 | **拦截**，未见 Jeffrey 明示处理（状态变更为已裁决/已否决）之前不得呈报终稿 |

R1/R2 的反例刻意只描述**违规的结构模式**（顺序颠倒、层级倒置），不给出具体的"标准正确顺序"原文——那属于最新公文规范的具体条文，本设计没有把握，需要 Jeffrey 核实后固化成机检规则，不能由测试用例编造。
