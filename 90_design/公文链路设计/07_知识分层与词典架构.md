## 一、洞一：给六大类加纵深

### 1.1 `depth`：同一大类内的抽象度分层

C1–C6 回答「这条知识属于哪个主题」，`depth` 回答「这条知识有多抽象、该怎么用」。两者正交，组合成二维坐标。

| depth | 定义 | 量级 | 典型归属 | 用户怎么用 |
|---|---|---|---|---|
| `axiom` 公理 | 跨全部文种与粒度的底层判断，不可判定但可陈述为一句独立命题 | 全库 **5–8 条** | 几乎全在 C6 魂 | 领会，解释取舍 |
| `principle` 原则 | 为什么这样做，可推出多个方法，跨文种成立 | 每大类 5–15 条 | C6、C3、C1 | 领会，判断适用 |
| `method` 方法 | 可复述的步骤或框架，有明确适用条件 | 每大类 30–80 条 | C3、C5 | 套用 |
| `technique` 技巧 | 单点招式，可直接照做 | 每大类 50–150 条 | C4、C2、C3 | 直用 |
| `rule` 条文 | 有唯一正确答案的规定 | 每大类不等 | C2 形、C1 骨 | 查证对错 |

`depth` 与第四章已有的 `answer_type`（条文型/方法型/拆解型）的关系：**`answer_type` 管答案写多长（校验分档用），`depth` 管这条知识多抽象（检索与挂钩用）**。两者不合并——一条 `axiom` 的答案可能是拆解型（要讲透），一条 `rule` 的答案必是条文型。映射建议：

```
rule            → answer_type: 条文型
technique       → 条文型 或 方法型
method          → 方法型
principle/axiom → 拆解型（七层 ≥400 字，要讲清"为什么"）
```

### 1.2 挂钩链：防止知识退化成散装 tips

新增两个字段，构成自底向上的单向链：

```
technique --implements--> method --derives_from--> principle --derives_from--> axiom
```

| 字段 | 谁必填 | 指向 |
|---|---|---|
| `implements` | `technique` 必填 | 本大类某条 `method` 的 id |
| `derives_from` | `method`、`principle` 必填 | 上一级的 id（`method`→principle，`principle`→axiom） |
| `governs` | `axiom` 必填 | 它管辖的大类列表，如 `[c1,c3,c4]` |

**孤儿拦截进 kb_audit（新增 error 项）**：任何 `technique`/`method`/`principle` 挂不上上级即拒收。这是防退化的**唯一机械手段**——靠人工评审守不住，评审会橡皮图章化（第四章 4.4 步⑦已认识到这个风险，强制差评制同理）。

`rule` 不入链（它是条文，不需要推导），但建议填 `cross_refs` 指向解释它的 principle。

### 1.3 `enforce`：可判定性的正确用法

前稿想用可判定性分层，那是错的（它不是主题维度）。它的正确位置是**单条知识的执行强度**：

| enforce | 含义 | 谁执行 | 例 |
|---|---|---|---|
| `hard` | 可程序判定，违反即拒 | `draft_lint.py` / `kb_audit` | 上行文禁用下行语气；弯引号 |
| `soft` | 需读懂语义判断，LLM 判定器执行 | gw-review 四 pass | 汇报的问题段要克制 |
| `advice` | 只作建议，不拦截 | 检索返回，人决定 | 标题字数 9–13 字 |

这一条直接解掉 41 条规则的边界争议：**争的不是它属于哪层，是它拦不拦人。** 标 `enforce` 即可，不必搬家。

### 1.4 并入第四章 schema 的新增字段

在第四章 4.1 字段表后追加（JSONL 顶层字段，编辑页同名表单项）：

| 字段 | 取值 | 必填 | 说明 |
|---|---|---|---|
| `depth` | axiom/principle/method/technique/rule | 是 | §1.1 |
| `implements` | id 数组 | technique 必填 | §1.2 |
| `derives_from` | id 数组 | method/principle 必填 | §1.2 |
| `governs` | 大类数组 | axiom 必填 | §1.2 |
| `enforce` | hard/soft/advice | 是 | §1.3 |
| `usability` | 可直用/可改写/仅供领会 | 是 | 与 depth 相关但不等价：一条 method 可能因涉密只能"仅供领会" |
| `tobacco_fit` | 通用/需适配/烟草专用 | 是 | §二 |
| `confidence` | 0.5–1.0 | 是 | 跨源验证得分，§1.5 |
| `conflict_with` | id 数组 | 否 | 与本条建议相反的条目 |

`vocab.py` 相应增加五个受控词表。`kb_validate` 增加：depth 合法性、挂钩链完整性、enforce 合法性。

### 1.5 confidence：四源不去重，累加证据

四源（技巧汇编 / 五本书 / AI 手册 / 自有交付物）各有生态位，但**同一条知识在层内确实重复**（几本书都讲"标题要实"）。合并时不丢弃，而是合成一条并记录证据数：

```
confidence = 0.5 + 0.1 × (独立来源数 − 1) + 0.2 × (有自有交付物佐证)
上限 1.0。单源孤证 0.5，四源共识且有自有佐证 1.0
```

检索排序在第四章现有链路的 rerank 之后加一道轻加权：`final = rerank_score × (0.7 + 0.3 × confidence)`。冲突条目**两条都留**，互填 `conflict_with`，各自在 answer 里写明适用边界——沿用 `rules_master` 已有的 `context_note` 做法。

## 二、洞二：词典四层重构

### 2.1 实测诊断

| 检查项 | 结果 | 判断 |
|---|---|---|
| 烟草术语条数 | 390 条（5 个 YAML） | 结构化良好，可用 |
| 术语在 378 万字语料中出现 | 226/390 = **58%** | 164 条是造出来的，语料里没人这么说 |
| 语料高频（≥60 次）而词典未收 | **1,242 个**词组 | 卷烟营销 1047 / 精益管理 989 / 管理诊断 852 / 现代终端 423 |
| `official_terms_v2.yaml` 结构 | 单个 `content` 字段装 9,179 字 Markdown | **程序无法解析**，禁用词/搭配/套话替换的校验实为空转 |
| 词典层次 | 只有「定义」一层 | 缺搭配、分寸、辨析三层 |

结论：**词典不是"缺内容"，是"形态不对 + 少三层"**。只补条数解决不了问题。

### 2.2 四层词典

词典不是新大类，它是 C4 肉 的底座 + 一个新的非 QA 单元 `terms.jsonl`（与 articles/paragraphs/templates 并列）。

| 层 | 回答什么 | 现状 | 来源 | 能否自动化 |
|---|---|---|---|---|
| **T1 定义** | 这个词什么意思 | 390 条，覆盖 58% | 已有 + 1,242 候选筛选 | 半自动 |
| **T2 搭配** | 这个词跟什么词连用 | **空** | **3,349 万字语料共现统计** | **全自动，零 LLM 成本** |
| **T3 分寸** | 什么行文方向/场合能用 | **空** | 五本书 + 讲评型篇目 | LLM 萃取 |
| **T4 辨析** | 近义词选哪个 | **空** | 语料频次对比 + 书籍 | 半自动 |

T2 是投入产出比最高的一层：**纯统计，不涉密**（只要词与词的共现，不要单位名和经营数据），因此可以绕开 §三的脱敏闸，**立即开工**。

### 2.3 `terms.jsonl` 字段

```jsonl
{"id":"T-00042","term":"卷烟营销",
 "t1_definition":"……",
 "t2_collocation":{"前接":["深化","推进","统筹"],"后接":["网络建设","策略","转型升级"],
                   "语料频次":1047,"典型例句":"深化卷烟营销网络建设"},
 "t3_register":{"direction":["上行","平行"],"occasion":["正式会议","书面报告"],
                "caution":"下行文布置工作时多用「卷烟销售」，「营销」偏战略口径"},
 "t4_contrast":[{"vs":"烟草营销","rule":"行业内部一律用「卷烟营销」；「烟草营销」多见于外部文献"}],
 "domain":"市场营销","org_level":["省级公司","地市局"],
 "corpus_freq":1047,"in_dict_before":false,"status":"active"}
```

`domain` 沿用现有 5 个业务域（技术研发/原料保障/生产制造/市场营销/物流管理），作为 §四术语召回的主键。

### 2.4 1,242 候选的入库门槛（需你拍板，见 §五）

候选里混着两类，必须分开：

```
烟草专有：卷烟营销、现代终端、管理诊断、精益管理、物流配送中心  → 收
通用公文：贯彻落实、科技创新、质量管理、生产经营、管理办法      → 不收（或只收进 T2 搭配层）
```

建议门槛：**频次 ≥100 且（含行业专有词根 或 人工标为行业专有）**。行业专有词根指：卷烟、烟叶、烟草、专卖、终端、货源、配送、精益、对标、成熟度 等。预估收 300–500 条，词典总量到 700–900 条，覆盖率目标 85%。

### 2.5 `official_terms_v2.yaml` 解构

当前 9,179 字 Markdown 按其自带的模块前缀（COU 常用语 / PW 禁用词 / MM 搭配 / CP 套话替换）逐条拆成 JSONL 行，并入 `terms.jsonl`（禁用词与套话替换另立 `kind` 字段区分）。这是 L1 校验器能真正跑起来的前提，属于 §六 的 ①' 步。

## 三、洞三：3,055 份语料的分流

### 3.1 家底实测

| 指标 | 值 |
|---|---|
| 原始语料 | **3,055 份 / 3,349 万字**（非此前口径的 6,000 份） |
| 有 to-md frontmatter（可溯源） | 97% |
| 正文 <200 字（空壳/残件） | 49 份（1.6%） |
| 乱码文件 | 0 |
| 前 3000 字完全重复 | 62 份冗余，唯一文档 2,993 |
| 正文长度 | 中位 5,320 字，P75 9,877，P95 35,803 |
| **含具体单位名** | **83%** |
| **含经营数据** | **63%** |

### 3.2 全量入库 ≠ 全量进 QA

3,349 万字是**成品交付物**，示范"写成什么样"，不解释"为什么这样写"。硬抽 QA 会得到大量"本方案分四个部分"这类零信息条目。

按第四章已有的单元类型分流：

| 语料 | 份数 | 去向 | 说明 |
|---|---|---|---|
| 六目录交付物 | 2,973 | **paragraphs.jsonl 为主** | 切段入段落库，按 `func` 词表归档（含 `模块-*` 前缀族） |
| 同上 · 高分者 | 300–500 | **articles.jsonl** | 全文范文，走现有评分机制 |
| 同上 | 全部 | **T2 搭配统计输入** | 不入库，只贡献共现统计 |
| 同上 | 全部 | QA 的 `confidence` 佐证 | 验证某手法在真实交付物中是否真被使用 |
| 个人历史交付物 | 82 | articles + paragraphs，**优先** | 差异化资产，第四章 4.3 已列为防死因 D3 |
| 空壳/残件 | 49 | 丢弃 | — |
| 重复件 | 62 | 去重保一 | — |

**QA 的来源不变**：仍是技巧汇编 305 篇、五本书、AI 手册、词句大全（第四章 4.3 的火力分配不动）。交付物语料是**段落库与范文库的料**，体量大是段落库的优势，不是 QA 的来源。

### 3.3 段落准入四闸

3,349 万字直接切段会产出百万级 chunk，检索必被稀释。四条全过才入库：

```
① 有观点句（不是纯流水账）
② 有支撑（数据／事例／政策依据）
③ 长度 120–600 字
④ 已脱敏，且脱敏后仍成立
```

按现有段落库 v2 的实测通过率（5–8%），预估沉淀 **2–4 万条段落**——合理量级，不是百万级。

### 3.4 脱敏：机械化前置，且本身是过滤器

83% / 63% 的命中率意味着脱敏不能靠人工抽查，必须建成管线的一环：

| 类型 | 处理 | 保留什么 | 为什么保留 |
|---|---|---|---|
| 单位名 | `〔某省中烟〕`／`〔某市局〕` | **行政层级** | `org_level` 判断依据 |
| 经营数据 | `〔数据〕` | **量纲与对比关系** | 「同比增长〔数据〕%」比整句删掉有用 |
| 人名职务 | 删人名留职务 | `〔局长〕指出` | 行文口吻依据 |
| 时间 | 留年份删日期 | 2021 年 | 时效判定 |

**关键设计**：脱敏后若整段只剩"取得显著成效"这类空壳，按准入闸②直接淘汰。**脱敏不是为了保住条目，它本身就是过滤器的一部分。**

脱敏后段落仍需过 kb_audit 的污染启发式（第四章 4.6 已有该项）。

## 四、烟草味的三处注入（贯穿全库）

现状的毛病是术语只在**末端校验**起作用：生成时模型按通用公文语感写，写完再挑错，代价高且改不干净。三处注入：

**入口 · 每条 QA 打 `tobacco_fit`**

| 取值 | 含义 | 处理 |
|---|---|---|
| `通用` | 手法与行业无关 | 直接用 |
| `需适配` | 手法通用但例子是党政口径 | answer 里**必须额外给一条烟草版 worked example** |
| `烟草专用` | 只在烟草语境成立 | 标 `org_level`，非烟草场景不召回 |

技巧汇编 305 篇全是党政口径，萃取时默认 `需适配`——**这意味着萃取阶段就要产出烟草版例子**，不是留到生成时临时换词。这是本设计增量最大的一处工作量，也是"写出来行业看得懂"的真正成本。

**中段 · 术语进生成上下文**

gw-draft 生成每个段落前，按段落主题从 `terms.jsonl` 按 `domain` 召回 3–8 条，以**候选词表 + T2 搭配**形式进 prompt。这是 T2 搭配层的主要消费场景——光有定义没有搭配，模型仍然会写出"进行卷烟营销的推进"这种别扭搭配。

**出口 · 校验不变**

`draft_lint.py` 继续跑禁用词/搭配/套话替换（此时已可真正解析，见 §2.5）。

**可观测指标**：出口校验的术语命中率应随入口/中段落地而**下降**。若始终居高不下，说明 `需适配` 的烟草版例子没做到位，回头补 QA，而不是加严校验。

## 五、待你拍板的三条

这三条不定，管线无法开工：

**① 1,242 候选的入库门槛**（§2.4）
建议：频次 ≥100 且含行业专有词根，预估收 300–500 条。
影响：词典规模与覆盖率目标。

**② 脱敏占位符粒度**（§3.4）
`〔某省中烟〕` 统一占位 vs `〔A 省中烟〕` 带编号。
后者能保住同一份文档内的指代一致性（"A 省"在全文指同一家），但增加标注成本。
建议：**带编号**——段落库里一个段落常跨句指代同一单位，统一占位会让段落读不通，直接影响准入闸②。

**③ 讲评型篇目的切分深度**
技巧汇编里"讲评型"篇目（点评具体句子）技巧藏在段落里，标题路由抽不到。
选项：A 先只做技巧型，看 QA 够不够用；B 上 LLM 段落级切分（约 35 万字成本）。
建议：**A**。第四章 4.4 首件铁律本就要求实测校准，技巧型跑完再看边际收益。
