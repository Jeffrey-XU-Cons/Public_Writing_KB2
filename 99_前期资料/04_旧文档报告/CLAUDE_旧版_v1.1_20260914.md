## 任务文件夹规范

每次任务在 `tasks/` 目录下建一个文件夹：
```
tasks/[日期]_[文种]_[主题]/
```

例如：
```
tasks/2026-03-28_汇报_效能攻坚推进/
tasks/2026-03-28_方案_管理成熟度评价/
```

文件夹内文件命名规范：
- 素材文件：任意命名，我会读取文件夹内所有文件作为素材
- 框架文件：`v1_框架.md`
- 全文文件：`v2_全文.md`
- 修改版本：`v3_修改版.md`（依次递增）

**每次启动后，我会先询问当前任务是哪个文件夹，然后读取其中所有素材文件。**

## 模式一：框架优先生成全文

### Step 1：准备工作
读取以下内容（按顺序）：
1. 当前任务文件夹内所有文件（素材）
2. 必读知识库文件（规则、骨架、词典、术语、金句、段落）
3. 对应文种高分范文3-5篇（从索引找评分≥8的范文，读取MD全文）

### Step 2：确认任务参数
如果素材文件里没有明确说明，询问：
- 文种（汇报/方案/讲话稿/报告）
- 主题和核心内容
- 字数要求（如无特别说明按骨架默认范围）
- 受众（向谁汇报/谁来讲）

### Step 3：输出逻辑框架

框架格式严格如下，不得跳过：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【逻辑框架】
文种：XX | 主题：XX | 预计字数：XX

一、[标题]（本部分核心论点：XXX）
  （一）[小标题]
    第1句：[作用]——[具体内容方向]
    第2句：[作用]——[具体内容方向]
    句间衔接：[过渡逻辑]
  （二）[小标题]
    ...

二、[标题]
  ...

意思分布检查：
- [论点A] → 仅在 一、（一）出现
- [论点B] → 仅在 二、（二）出现
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

框架输出后说：
「框架已完成。请确认（说"确认"继续展开全文），或直接告诉我要改什么。」

### Step 4：等待确认
- 你说「确认」→ 进入Step 3.5
- 你指出修改意见 → 调整框架，重新输出，再次等待确认
- **不得在你确认之前展开全文，这一步不可跳过**

### Step 3.5：提纲逐句打磨

对框架里每一句的内容方向，逐句细化为三个要素：
1. **主体**：这句话写的是谁（哪个部门/哪项工作/哪个指标）
2. **动作**：这句话的核心动作（做了什么/达到什么）
3. **支撑点**：这句话的落脚依据（数据/政策依据/对比基准）

输出格式：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【提纲逐句打磨】

一、（一）[小标题]
  第1句：[主体]→[动作]→[支撑点]
  第2句：[主体]→[动作]→[支撑点]
  第3句：[主体]→[动作]→[支撑点]

一、（二）[小标题]
  第1句：[主体]→[动作]→[支撑点]
  ...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

示例：
```
第2句：生产管理部→驻厂督导联合攻坚→卷烟厂生产作业天数平均下降11天
```

打磨完成后说：
「逐句打磨已完成。请确认（说"确认"展开全文），或告诉我要调整哪句。」

**如某句暂无支撑数据，标注「[待补充：需XX类数据]」，不得用模糊表述占位。**

### Step 5（调整后）：等待二次确认
- 你说「确认」→ 进入Step 6
- 你指出某句需调整 → 修改对应句，重新输出打磨结果，再次等待确认

### Step 6：展开全文

按确认后的框架逐部分展开，每展开一个部分执行质量检查：
- 意思流窜检查：本部分的论点是否在其他部分重复出现
- 术语检查：是否使用了词典里的禁用词或不规范搭配
- 逻辑检查：本部分与上一部分的递进关系是否成立

全文完成后：
1. 输出完整全文
2. 保存到 `tasks/[当前任务文件夹]/v2_全文.md`
3. 说明引用了哪几篇范文作为参考

## 模式二：修改初稿

### Step 1：理解任务
读取：
- 当前任务文件夹内的初稿文件
- 你指出的具体问题
- 必读知识库文件

### Step 2：定向修改
**只修改你指出的问题位置，不重写全文其他部分。**

修改前说明：「我将修改[具体位置]，原因是[XXX]」
修改后说明：「已修改，主要变化：[对比说明]」

同时执行意思流窜检查和术语检查，发现其他问题只提示，不自动修改。

### Step 3：输出
输出完整修改后全文，保存到 `tasks/[当前任务文件夹]/v[N+1]_修改版.md`

## 质量规则（每次生成必须遵守）

### 规则一：意思不流窜
同一个论点在全文只能在一个位置出现。发现重复时合并到最合适的一处，其余删除。

### 规则二：逻辑层次严谨
- 同级内容MECE：相互独立，完全穷尽，不重叠不遗漏
- 上下层级有明确递进或包含关系
- 同级条目之间不互相包含

### 规则三：烟草行业规范
- 使用 `tobacco_terms/` 中的术语，不用通用AI替代表达
- 遵守 `official_terms_v2.yaml` 的禁用词表（PW模块）和搭配规范（MM模块）
- 套话替换参考CP模块规则
- 语言风格参考高分范文行文习惯

### 规则四：数据规范
- 同一数据全文只出现一次
- 数据须有对比基准（同比/历史最好/超额完成目标）
- 不得使用无来源的模糊数字
