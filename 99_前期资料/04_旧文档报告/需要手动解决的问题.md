## 🔴 P0 - 阻塞性问题（必须先解决，否则后续全部卡住）

### 问题1：T-6.3 Dify系统启动 - OOM导致中断

**状态**: 🔄 60% 完成，OOM崩溃
**现象**: 服务器内存不足（OOM），docker-compose启动时容器崩溃或被kill
**影响范围**: 阻塞 T-6.4, T-7.1~7.4, T-8.1~8.7, T-9.1~9.4, T-10.x 全部后续任务

**你需要做**：

```bash
# 1. SSH登录服务器
ssh user@your-server-ip

# 2. 检查内存状况
free -h
df -h

# 3. 停止所有容器（清理残留）
cd /your/dify/directory
docker-compose down

# 4. 关闭占用内存的进程
# 查找占内存最多的进程：
ps aux --sort=-%mem | head -10

# 5. 调整 docker-compose.yml 内存限制（可选）
# 在每个service下添加：
# deploy:
#   resources:
#     limits:
#       memory: 2G

# 6. 重新启动（按依赖顺序，逐个启动）
docker-compose up -d postgres redis
sleep 10
docker-compose up -d weaviate
sleep 10
docker-compose up -d dify-api dify-worker
sleep 20
docker-compose up -d dify-web nginx

# 7. 验证健康
docker-compose ps
curl http://localhost:5001/api/health
```

**最低内存要求**: 8GB RAM（推荐16GB）
**备选方案**: 若服务器内存 < 8GB，移除 `weaviate` 容器，改用 Dify 内置向量存储（Chroma）
