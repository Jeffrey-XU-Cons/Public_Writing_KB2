### 2.2 🔴 21 个 ID 重复（最严重的质量问题）

**问题本质：跨书提炼时同名 ID 没有重命名为"书名_原ID"形式**

- FORMAT[0] 「公文校核四原则」← 公文高手自我修炼.yaml
- LOGIC[60] 「标题SPA三原则」← 李忠秋_结构化写作.yaml
- STYLE[1] 「公文语言准确第一原则」← 胡森林_公文写作底层心法.yaml

**完整重复 ID 清单（按出现次数排序）：**

| ID | 次数 | 涉及书籍数 |
|---|---|---|
| LR-001 / LR-002 / LR-003 | 各 3 次 | 3 本书各自的 LR-001/002/003 |
| LR-004 / LR-005 / LR-006 | 各 2 次 | 2 本书 |
| MT-001 / MT-002 / MT-003 / MT-005 | 各 2 次 | 2 本书 |
| MT-007_胡森林公文写 | 2 次 | 同一本书内部重复 ⚠️ |
| MT-009 / MT-010 / MT-011 / MT-012 | 各 2 次 | 2 本书 |
| PM-002 / PM-003 / PM-004 / PM-005 | 各 2 次 | 2 本书 |
| 其余共 **21 个 ID** 至少出现 2 次 | | |

**业务后果：**
- Claude Code 按"LR-001"检索时，会返回 3 条不同规则，无法判断哪条对应当前场景
- skills/skill_*.md 中引用规则编号（如 LR-001 SPA、LR-002 废话）时会产生歧义

**修复方案（推荐）：**

将所有跨书 ID 加书名前缀，统一为：
```
原: LR-001
改: LR-001_公文高手   （来自《公文高手自我修炼》）
    LR-001_李忠秋     （来自《李忠秋·结构化写作》）
    LR-001_胡底层心法  （来自《胡森林·公文写作底层心法》）
```

或更彻底：所有跨书规则统一重新编号（M-001 到 M-345）+ 保留 original_id 字段。

### 3.3 🔴 排比句库 / 比喻词库 YAML 解析错误

**问题本质：内嵌中文引号未转义**

```yaml
# 排比句库 行 869:
  - id: GS-081
    category: 斗争类排比句
    content: "敢于斗争"讲的是斗争态度，"善于斗争"讲的是斗争方法，...
    #          ↑ YAML 把这识别为 "敢于斗争" 后面跟着裸文本，解析失败
```

**修复方案三选一：**

**方案 A：用单引号包裹**（最简单）
```yaml
content: '"敢于斗争"讲的是斗争态度，"善于斗争"讲的是斗争方法，"骨头要硬"讲的是斗争精神，"见微知著"讲的是斗争本领。'
```

**方案 B：用块标量（推荐）**
```yaml
content: |
  "敢于斗争"讲的是斗争态度，"善于斗争"讲的是斗争方法，"骨头要硬"讲的是斗争精神，"见微知著"讲的是斗争本领。
```

**方案 C：把引号改为中文弯引号**（符合 Jeffrey CLAUDE.md 个人规范）
```yaml
content: '「敢于斗争」讲的是斗争态度，「善于斗争」讲的是斗争方法，「骨头要硬」讲的是斗争精神，「见微知著」讲的是斗争本领。
```

### 3.4 🔴 金句库 P4 — 52% 是 PDF 转换垃圾

**深度抽样发现（206/394 = 52% 疑似垃圾/低质量）：**

| 垃圾类型 | 示例 |
|---------|------|
| 会议保存标记 | `(会议材料妥善保存)\n坚持稳中求进工作总基调...` |
| Markdown 标题 | `# 三、《关于建设现代化烟草经济体系...》起草情况的说明` |
| 多页文档碎片 | `团队成员列表\n## （四）课题计划\n两支队伍建设一张纸工作法研究与应用甘特图\n## （五）课题总体思路` |
| PDF 表格垃圾 | `监控\n监控\n信息和沟通\n信息和沟通\n控制活动\n控制活动` |
| 章节标题 | `二、现状分析及目标设定\n## （一）现状分析\n1、问卷调查` |
| 单位封面 | `唐山烟草专卖局（公司）\n物流中心管理诊断报告\n全省物流系统管理诊断项目组\n2023` |
| 页码 | `## 第 6 页\n2022年对标情况` |

**根因：** `p4_paragraph_extraction.py` 抽取脚本基于"长度 50-180 字"窗口切分原始 MD 文件，但没有过滤 PDF 转 MD 时产生的：
1. Markdown 标题行（以 `#` 开头）
2. 多列布局碎片（`监控\n监控\n` 类型）
3. 文档头/尾元信息（封面、页脚、保存标记）
4. 表格/编号列表

**真正能用的金句估计仅 ~190 条**（48%）。

**修复方案：**

| 方案 | 工作量 | 效果 |
|------|--------|------|
| A. 重写抽取脚本，加垃圾过滤规则后重跑 | 0.5 天 | 自动 + 可重现，但仍可能漏检 |
| B. 人工逐条审核打标签（保留/丢弃） | 1-2 天 | 质量最高 |
| C. 用 Claude API 自动判断每条是否是"合格金句" | 0.3 天 | 中等质量，可批量 |
| D. 推荐：A + 人工抽检 100 条验证 | 0.7 天 | 性价比最高 |

## 八、最严重的"隐形质量风险"

> 这是审计中发现的最值得警惕的 3 个问题，它们目前都不会让脚本崩溃，但会持续污染 AI 输出。

### 8.1 金句库污染输出

`03_dictionary/金句库(P4).yaml` 是 CLAUDE.md 声明的**每次必读**文件。当 Claude Code 在润色环节"按 category=报告类 检索金句"时，会读到一堆 PDF 转换碎片（标题、表格、页码），可能会被当成示例插入到生成的公文中。

**典型风险场景：** 用户让 Claude 写一篇"管理诊断报告"，Claude 检索金句库后，找到 #62「本次管理诊断主要基于Q/SZY 1073-2023《物流管理诊断程序》、《物流管理诊断操作手册》、卓越绩效方法」——这是某份诊断报告的引言，并不是金句，但 Claude 可能直接搬过来用。

### 8.2 official_terms_v2 无法精确校对

CLAUDE.md 声明每次必读，但**实际是 9179 字符的纯文本**。Claude Code 读 yaml 后只能看到一个 markdown 文档，无法按 `禁用词 → 替换词` 形式逐条检索。当用户文档中出现"最好的"、"完全"等禁用词时，Claude 只能凭文本理解去找，可能漏检。

### 8.3 ID 重复 + 规则引用歧义

skills/skill_*.md 中已经引用了 LR-001（标题 SPA 三原则）、LR-002（废话/十个不写）等 ID，但 rules_master.yaml 中 LR-001 出现 3 次、LR-002 出现 3 次——分别来自三本书的不同规则。

**如果未来要做"按 ID 反查规则原文"的功能（如 Claude 解释为什么这么改），会直接歧义。**
